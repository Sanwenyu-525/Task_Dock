## 1. 产品定位

### 1.1 一句话

> 一个**默认与 Task Dock 其他数据隔离**的本地加密保险库，用来长期、安全地保存"几个月才用一次、
> 但丢了会很麻烦"的凭据与敏感资料。

### 1.2 它必须解决的真实问题

按用户实际叙述（不是产品想象）归纳为六类痛点：

| # | 痛点 | 触发时刻 | 现有产品为何没解决 |
|---|---|---|---|
| P1 | 几个月才登录一次的网站，忘了账号密码 | 需要登录老账号时 | 笔记里散落明文；浏览器只记最近常用的 |
| P2 | 不记得某平台注册时用了哪个邮箱 | 找回密码、判断归属时 | 邮箱与账号没有绑定存放 |
| P3 | 软件激活码/许可证需要长期保存 | 重装系统、换机 | 邮件里翻找；截图散落 |
| P4 | API Key / 访问令牌需要长期保存 | 接新工具、写脚本 | 明文存在 `.env`、聊天记录、便签 |
| P5 | 路由器 / NAS / 设备后台凭据 | 设备重置、搬家 | 说明书丢了；只记得部分 |
| P6 | 双重验证恢复码、备用邮箱、恢复说明 | 手机丢失、账号被锁 | 存在手机里，手机正是丢失的那台 |

### 1.3 设计原则（有冲突时按顺序取舍）

1. **安全边界优先于便利**：宁可多一次解锁，不让普通功能读到秘密。
2. **不增加记忆负担**：用户只需要记住**一个主密码**，恢复密钥是一次性纸质备份。
3. **诚实**：不承诺"绝对安全"，不隐藏平台限制（剪贴板历史、内存、恶意软件）。
4. **不做功能堆砌**：每个功能都必须对应 §1.2 的具体痛点，否则不进 MVP。
5. **可退出**：数据必须能加密导出，不把用户锁死在应用里。

### 1.4 明确的非目标（Non-goals）

| 非目标 | 原因 |
|---|---|
| 浏览器自动填充 / 系统级密码管理器替代品 | 需要浏览器扩展与系统集成，P3 才评估；MVP 明确不做 |
| 团队共享 / 多人协作保险箱 | 单人本地产品；共享会引入服务端可见面 |
| 云同步服务端托管密钥 | 服务端只存密文；密钥不出设备（见 multi-device-sync） |
| 硬件密钥（YubiKey）/ 智能卡 | 平台与依赖成本高，P3 评估 |
| 完整 TOTP 身份验证器 | 第一阶段只存恢复码；TOTP 生成器 P3 评估（见 decision-log D-11） |
| 明文导出 | 默认禁止；仅 P3 提供带强确认的例外流程（见 backup-and-recovery §6） |
| 密码强度"评分保证安全" | 强度只是启发式提示，不是安全结论 |

## 3. 功能卡（按域）

每张卡固定回答 12 个问题：为什么需要 / 解决什么 / 怎么用 / 页面交互 / 后端实现 / 数据保存 /
安全边界 / 涉及方法 / 依赖 / 测试 / 验收 / 扩展。

### 3.1 账号密码（SV-ACC-01 / 02 / 03）

- **为什么**：这是最高频的"几个月才用一次"场景，也是唯一必须支持"复制粘贴"的场景。
- **解决什么**：网站名 + 登录地址 + 用户名 + 邮箱 + 密码 + 平台 + 分类 + 标签 + 备注的长期保存；
  同一站点多个账号（工作号/私人号/子账号）不打架。
- **用户怎么用**：新建 → 填站点与账号 → 保存（密码默认隐藏）→ 下次搜索站点名 → 打开详情 →
  点"复制密码"→ 粘贴到浏览器 → 30 秒后自动清除。
- **页面交互**：列表行只显示站点名、账号掩码（`a***@gmail.com`）、分类、更新时间；
  **列表不显示密码**；详情页密码字段默认打码，点眼睛图标才显示，显示 30 秒后自动回到打码态
  （可设"保持显示直到离开页面"）。复制有 toast 与"已复制，30 秒后清除"提示。
- **后端实现**：记录写入 `records` 表；元数据（站点名/用户名/邮箱/分类/标签）进 `meta_blob`；
  密码进 `secret_blob` 的 `kind=password` 字段；复制走 `vault_copy_secret`（Rust 侧写入 + 定时清除）。
- **数据保存**：`records.meta_blob` / `records.secret_blob`（AES-256-GCM，见 data-model §5）。
- **安全边界**：密码永不出现在列表响应、日志、搜索索引、备份明文；锁定后内存索引与所有明文被丢弃。
- **方法**：`vault_record_create / update / get(reveal) / list / delete / restore`、
  `vault_copy_secret`（api §4、§7）。
- **依赖**：SV-LOCK-01、SV-ORG-01。
- **测试**：T-ACC-01..06（字段往返、多账号、掩码规则、复制与清除、锁定后不可读、超长/特殊字符）。
- **验收**：库文件二进制中搜不到任一测试密码明文；锁定后 `vault_record_get` 返回 `VAULT_LOCKED`。
- **扩展**：P3 可加"登录成功次数/最近使用"（已在 `last_used_at` 预留），自动填充另立 SV-AUTO-01。

### 3.2 API Key 与密钥（SV-API-01 / 02）

- **为什么**：API Key/Token 一旦泄漏比密码更难察觉，且经常需要原样粘贴到配置文件。
- **解决什么**：API Key、Secret Key、Access Token、Refresh Token、SSH 私钥、软件授权密钥、
  许可证、激活码的长久保存，并记录到期日与使用说明。
- **用户怎么用**：新建时选类型（API 密钥 / 许可证 / SSH 私钥）→ 填服务名、密钥内容、到期日、
  使用说明 → 详情页可"整段复制"。
- **页面交互**：密钥内容用等宽字体、默认折叠为"已隐藏（N 字节）"，展开后按行显示；
  许可证显示到期倒计时徽标（仅本地计算）。
- **后端实现**：`fields[]` 中 `kind=secret`（单行）或 `kind=blob`（多行/原始字节，存
  `value_b64` + `encoding`）。**不做任何 trim / 换行归一 / 大小写处理**；SSH 私钥的 CRLF 与尾部
  换行按原字节保存与复制。
- **数据保存**：`secret_blob.fields[i].value_b64`（base64 文本，仍在 AEAD 内）。
- **安全边界**：到期日属于元数据（进 `meta_blob`），可被搜索"到期"；密钥本体永不出现在列表。
- **方法**：`vault_record_create`（`fields` 支持 blob）、`vault_copy_secret`（按字节写入剪贴板）。
- **依赖**：SV-ACC-01 的字段模型。
- **测试**：T-API-01..05（PEM 私钥含 `\r\n` 往返逐字节一致、8KB 密钥、含 NUL 字节的二进制 blob、
  复制后文本与原字节一致、导出/导入往返一致）。
- **验收**：`sha256(原始字节) == sha256(复制出的剪贴板字节)`（人工 + 自动化各一次）。
- **扩展**：P3 生命周期管理（轮换提醒、到期通知 SV-EXP-01）。

### 3.3 账户恢复资料（SV-REC-01）

- **为什么**：账号被锁时，恢复码/备用邮箱往往比密码更关键，而它们最容易被"存在手机里"。
- **解决什么**：双重验证恢复码（多条）、备用邮箱、恢复电话、恢复说明、备用登录方式、安全提示。
- **用户怎么用**：为某账号建一条"恢复资料"记录，粘入一组恢复码（每行一个），填写备用邮箱与说明。
- **页面交互**：恢复码以"码块列表"展示，支持逐条复制与"复制全部"；默认隐藏；打印/抄写提示
  （P3 可导出 PDF，本轮不做）。
- **后端实现**：`fields[]` 中 `kind=secret_multiline`（每行一条），或 `kind=secret` 多条字段；
  与账号记录通过 `linked_record_id`（元数据内软引用）关联。
- **数据保存**：`secret_blob`；关联关系在 `meta_blob`。
- **安全边界**：恢复码与密码同级加密；搜索不索引恢复码内容（只索引标题/服务名）。
- **方法**：`vault_record_create / get / copy_secret`。
- **依赖**：SV-ACC-01。
- **测试**：T-REC-01..03（10 条恢复码往返、逐条复制、关联记录被删除后的悬空引用显示"已删除"）。
- **验收**：详情页可逐条复制且锁定后不可读。
- **扩展**：P3 评估 TOTP（存种子并本地生成 6 位码），本轮只存恢复码。

### 3.4 私密备忘（SV-MEMO-01）

- **为什么**：现实里存在"不是标准密码、但绝不能进普通笔记"的信息（私人编号、设备管理后台说明、
  私密联系方式）。
- **解决什么**：任意自定义字段（文本/多行/日期/密码型），字段名与顺序可自定义。
- **用户怎么用**：新建"私密备忘"→ 添加字段（如"NAS 管理后台"）→ 选择类型 → 填写 → 拖动排序。
- **页面交互**：字段编辑器为行式列表（标签 + 类型下拉 + 值 + 上/下移 + 删除），不用复杂表单；
  密码型字段在编辑态也默认打码。
- **后端实现**：`fields[]` 数组即数据模型，字段 `id` 稳定（UUID），排序由数组顺序表达；
  字段名与值都在 `secret_blob` 内。**注意：字段名也可能敏感**（如"某医院账号"），故字段名也加密。
- **数据保存**：仅 `secret_blob`；`meta_blob` 只留标题与类型。
- **安全边界**：字段名、字段值、顺序全部加密；列表只显示标题。
- **方法**：`vault_record_create / update / get`。
- **依赖**：SV-ACC-01。
- **测试**：T-MEMO-01..04（字段增删改排序、类型切换不丢值、字段名加密（库内搜不到）、20 字段上限）。
- **验收**：库文件搜不到任一字段名与值。
- **扩展**：P3 模板（"路由器"、"NAS"模板一键建记录）。

### 3.5 分类、标签、收藏与搜索（SV-ORG-01 / SRCH-01）

- **为什么**：记录一多，"我到底存过没有"比"存哪了"更痛。
- **解决什么**：内置分类（账号密码/API 密钥/软件许可证/恢复资料/私密备忘）+ 自定义分类 + 标签 +
  收藏 + 最近使用 + 搜索。
- **用户怎么用**：左侧分类栏 + 顶部搜索框；输入站点名、用户名、标签即时过滤；
  收藏置顶；"最近使用"按 `last_used_at` 排序。
- **页面交互**：搜索框常驻（Ctrl+F 聚焦）；输入即搜（150ms 防抖，**后端搜索**）；
  空结果给"没有匹配记录"+ 清空筛选；搜索期间**不显示**任何密钥字段。
- **后端实现**：解锁时把全部 `meta_blob` 解密成内存索引 `Vec<RecordMeta>`；搜索为内存子串/分词
  匹配（大小写不敏感、支持中文按字符）；**不建 FTS 表、不写磁盘缓存**。
- **数据保存**：分类名在 `categories.name_blob`（加密）；标签在 `meta_blob.tags`。
- **安全边界**：搜索只在解锁态可用；锁定即清空索引；搜索响应只含元数据，不含任何 `secret` 字段；
  搜索词不写日志（诊断只记录 `query_len_bucket`）。
- **方法**：`vault_search`、`vault_records_list`、`vault_categories_*`、`vault_record_toggle_favorite`。
- **依赖**：SV-LOCK-01。
- **测试**：T-SRCH-01..05（1000 条记录搜索 < 50ms、中文/英文/符号、锁定后搜索返回 `VAULT_LOCKED`、
  搜索词不入日志、标签与分类过滤组合）。
- **验收**：解锁后搜索可用；锁定后接口拒绝；诊断日志中无搜索词。
- **扩展**：P2 移动端复用同一搜索语义（纯函数移植）。

### 3.6 密码生成器与强度（SV-GEN-01 / 02）

- **为什么**：用户改密码时最需要"够随机又好输入"的候选。
- **解决什么**：长度、字符集、排除易混淆字符、强度提示、安全随机源。
- **用户怎么用**：新建/编辑密码字段旁"生成"按钮 → 弹层调参 → 生成 → "用这个"或"再生成一个"。
- **页面交互**：长度滑杆 8–64（默认 16）；四类字符开关（默认全开）；"排除易混淆 `0O1lI`"默认开；
  生成结果等宽显示 + 复制按钮 + 强度条；**不把强度条当作安全结论**，文案写"强度为启发式估计"。
- **后端实现**：`OsRng`（`getrandom`）取随机字节；对每个字符集用**拒绝采样**消除取模偏差；
  先保证每类至少 1 个（当长度 ≥ 类别数），再用 Fisher–Yates（同样基于 OsRng）洗牌；
  强度：长度熵 + 字符集熵 − 常见模式惩罚（键盘序、重复、日期、"password"类词根），输出 0–100 与等级。
- **数据保存**：不保存生成历史（避免"生成过的密码"成为泄漏面）。
- **安全边界**：只用 CSPRNG；禁止 `rand::thread_rng` 之外的任何非密码学随机；生成结果只在当前
  表单内存中存在。
- **方法**：`generate_password(opts)`（api §6）、`evaluate_password_strength(value)`。
- **依赖**：无。
- **测试**：T-GEN-01..06（字符集约束、每类至少一个、排除字符不出现、10 万次无重复偏差粗检、
  长度边界、强度单调性样例）。
- **验收**：`grep` 代码确认无 `thread_rng` / `Math.random` 用于生成；单测覆盖拒绝采样分支。
- **扩展**：P3 口令短语（词表）模式。

### 3.7 备份与恢复（SV-BKP-01 / 02）

- **为什么**：加密数据的最大现实风险不是被破解，而是**丢**（换机、磁盘坏、误删库）。
- **解决什么**：加密备份导出、加密导入、完整性校验、版本兼容、损坏与中断处理、覆盖确认。
- **用户怎么用**：设置页"导出加密备份"→ 选路径 → 输入导出密码（默认预填主密码，可改）→ 生成
  `.tdvault` 文件；换机时"从备份恢复"→ 选文件 → 输密码 → 预览（记录数/时间/版本）→ 确认恢复。
- **页面交互**：导出前显示"将包含 N 条记录（含全部密钥字段），文件本身已加密"；导入先"检查文件"
  （只解密头部与清单，不写库），再给覆盖警告（现有 N 条将被替换/合并二选一）。
- **后端实现**：独立容器（JSON 头 + AEAD 载荷，见 backup-and-recovery §2）；导出用独立随机
  `file_key` 加密载荷，DEK 用导出口令派生的 KEK 封装后放头部；导入先全量解密到内存并校验计数与
  摘要，再写入 `secure-vault.db.restore-tmp`，验证通过后原子替换，旧库保留为 `.pre-restore`。
- **数据保存**：`.tdvault` 单文件；不写主库、不进主备份、不自动上传。
- **安全边界**：默认**没有明文导出**；导出文件即使被拿走，没有口令也无法读出记录；
  导入失败不破坏现有库。
- **方法**：`vault_backup_export / inspect / restore`（api §8）。
- **依赖**：SV-LOCK-01、SV-KEY-01。
- **测试**：T-BKP-01..08（往返一致、错口令失败且不写库、截断/篡改头部失败、旧版本拒绝/兼容、
  中断恢复、覆盖确认、10k 条记录、导出文件内无明文）。
- **验收**：`strings`/`grep` 备份文件搜不到测试密码；恢复中断后原库仍可解锁。
- **扩展**：P2 同步复用同一容器语义（仅传输单元不同）。

### 3.8 自动锁定与剪贴板（SV-LOCK-02 / CLP-01）

- **为什么**：用户忘了锁，或复制后忘了清，是最高频的真实泄漏路径。
- **解决什么**：闲置锁定、进入后台锁定、系统锁屏锁定、休眠锁定、窗口隐藏/退出锁定；
  复制后自动清除且不误删。
- **用户怎么用**：默认无需配置；设置页可调"闲置锁定 5 分钟 / 后台 60 秒"；
  复制密码后提示"30 秒后自动清除"，可改 10–300 秒。
- **页面交互**：锁定态显示独立锁屏视觉（不显示任何记录标题）；解锁后顶部有"锁定"按钮与倒计时
  提示（"3 分钟后自动锁定"）；复制 toast 带倒计时。
- **后端实现**：`VaultSession` 持 `last_activity: Instant`；后台 tokio 每 5s tick，超时即 `lock`；
  Win32 `WTSRegisterSessionNotification` 监听 `WTS_SESSION_LOCK`；窗口 proc 监听
  `WM_POWERBROADCAST`（`PBT_APMSUSPEND`）；`WindowEvent::CloseRequested`（隐藏到托盘）与
  进程退出钩子锁定；恢复后若单调时钟间隔 ≥10s 也锁定。
- **数据保存**：锁定原因与时间写 `vault_audit`（无正文）。
- **安全边界**：锁定 = 丢弃 DEK/明文索引/搜索结果 + 通知前端清空 UI；不依赖前端定时器；
  剪贴板清除前比对内容，用户新复制的内容绝不删除。
- **方法**：`schedule_auto_lock`（内部）、`handle_app_background`、`handle_system_lock`、
  `clear_sensitive_memory`、`copy_secret`、`clear_clipboard_if_unchanged`（api §7、§9）。
- **依赖**：SV-LOCK-01。
- **测试**：T-LOCK-01..07、T-CLP-01..06（见 test-and-acceptance）。
- **验收**：锁屏/休眠/隐藏三类事件在真机上各触发一次锁定并留下审计；剪贴板在 30s 后被清空且
  期间用户新复制的内容未被删除。
- **扩展**：P2 移动端后台切换锁定；P3 空闲检测（系统级输入空闲）替代应用内活动。

### 3.9 审计（SV-AUD-01）

- **为什么**：出了事要能回答"什么时候解锁过、什么时候导出过"。
- **解决什么**：解锁成功/失败、锁定（含原因）、导出、导入、恢复、主密码修改、恢复密钥重生成。
- **用户怎么用**：设置页"安全审计"列表（最近 200 条），可清空（二次确认）。
- **页面交互**：时间倒序、事件名 + 结果徽标 + 原因码；不含任何记录标题或字段值。
- **后端实现**：`vault_audit(id, at, event, outcome, reason_code, count)`；只存枚举与计数；
  同时发一条诊断事件（`vault/*`，metadata 只含枚举与计数）。
- **数据保存**：`secure-vault.db` 内明文枚举（不含秘密）；清空只删本表。
- **安全边界**：审计本身不泄漏内容；但会泄漏"使用频率"，文档明确写出（threat-model R-09）。
- **方法**：`vault_audit_list / clear`。
- **依赖**：SV-LOCK-01。
- **测试**：T-AUD-01..03（事件齐全、导出不含正文、清空需确认）。
- **验收**：每次锁定均有审计；`grep` 审计表无记录标题。
- **扩展**：P3 导出审计报告（脱敏）。

## 4. MVP（P1）范围与暂缓清单

### 4.1 MVP 必须交付（19 项）

初始化、主密码、恢复密钥、解锁/锁定、自动锁定、账号密码、API 密钥、恢复资料、私密备忘、
分类标签收藏、内存搜索、密码生成器与强度、加密备份/恢复、剪贴板自动清除、安全设置、安全审计。

### 4.2 明确暂缓（不得偷偷进 MVP）

| 暂缓项 | 原因 | 何时 |
|---|---|---|
| 移动端保险箱 | 需原生模块与 Keystore 验证 | P2 |
| 多设备同步 / 设备授权 | 需独立密钥传递协议与中继设计 | P2 |
| 生物识别解锁（桌面 Windows Hello / 手机指纹） | 需系统 API 与"不可作为唯一解锁方式"的降级设计 | P2 |
| Agent 凭据调用 | 需租约、审计、最小权限全套 | P3 |
| 自动填充 / 浏览器扩展 | 跨进程与浏览器集成成本高 | P3 |
| TOTP 生成器 | 需正确处理时钟漂移与种子保护 | P3 |
| 明文导出 | 默认禁止，需强确认流程 | P3（默认仍不做） |
| 附件（证件照/扫描件） | 体积、缩略图、备份膨胀 | P3 |

### 4.3 与现有功能的边界（执行细则）

1. 保险箱记录**不得**出现在 `notes`、`tasks.description`、`clipboard_items`、`shelf_items.note`、
   `knowledge_documents.content` 中；代码评审按此条检查。
2. 保险箱复制**不得**调用会入库的剪贴板命令；只能走 `vault_copy_secret`。
3. 保险箱设置**不得**写 `application_settings`（该表进主备份）。
4. 保险箱数据**不得**进入 `BACKUP_TABLES`、`EXTENDED_TABLES`、`EXPORT_VERSION` 相关导出结构。
5. 保险箱**不得**注册任何 MCP 能力位（`mcp::permissions::CAPABILITIES` 保持不含 vault）。
6. 保险箱**不得**被 `global_search` 的任何 `search_*` 函数查询。

## 5. 产品级验收标准

| # | 标准 | 判定方式 |
|---|---|---|
| A1 | 用户能在 90 秒内完成初始化（含恢复密钥抄写确认） | 人工计时（3 人各 1 次） |
| A2 | 解锁后 2 次点击内可复制到某个账号的密码 | 人工走查 |
| A3 | 锁定态不显示任何记录标题/数量（页面仅锁屏视觉） | 截图评审 + 代码检查 |
| A4 | 关闭应用再打开，记录完整、无需重新初始化 | 重启走查 |
| A5 | 备份文件可在"删库重装"后完整恢复 | 破坏性演练（隔离数据目录） |
| A6 | 功能矩阵中 P1 的 19 项全部有入口、有测试、有验收记录 | 对照矩阵逐项勾选 |
| A7 | 全部 P1 记录在库文件、备份文件、日志中均无明文（哨兵串检索为空） | 自动化脚本 |
| A8 | 任何 Agent/MCP/CLI 路径都无法读到保险箱（返回不存在/无权限） | 专项测试 |
