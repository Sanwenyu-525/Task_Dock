# 产品价值审计（效率中枢 V2）

> 日期：2026-11-13。目的：回答「为什么在 Task Dock 里做，而不是直接用 Windows、IDE、
> Agent 或专业软件？」。**不提供虚构的效率百分比**，只比较可观察的操作步骤与信息留存方式。
> 结论用于决定「保留 / 加强 / 合并 / 降级」，不是功能宣传。

## 判断口径

- **保留**：Task Dock 有明确跨工具价值，继续维护。
- **加强**：方向成立，但当前只是底座，需要下一轮补齐真实闭环。
- **合并**：与原生/专业工具高度重叠，应减少入口、复用系统能力，不再扩张。
- **降级**：价值依赖未实现能力或使用频率低，降低优先级，不投入 UI。

## 逐项审计

### 1. 应用管理 / 快捷启动

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| Windows 原生 | 开始菜单搜索 → 回车；或任务栏固定图标单击 | 成熟、零维护、覆盖所有安装应用 |
| IDE / 专业工具 | 内置终端或运行配置启动项目 | 只覆盖本项目 |
| Task Dock 现状 | 胶囊/完整面板应用页 → 点击目标；场景可一次启动多应用；现场恢复可回到窗口布局 | 价值在「一组目标 + 场景 + 现场」，不是单个应用启动 |

**判断：合并（启动）+ 保留（场景/现场）。** 单个应用启动与开始菜单重叠，不再增加
新的启动入口或图标；保留「场景 = 多应用/URL/目录组合」与「现场恢复」这两个跨工具能力。

### 2. 文件收集（收集箱投递）

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| Windows 原生 | 拖到桌面/资源管理器目标文件夹 | 适合长期归档与大文件管理 |
| Task Dock 现状 | 拖文件到收集箱 → 作为待处理素材，可关联任务 | 价值在「临时收集 + 任务关联」，不是文件管理 |

**判断：保留（轻量收集）。** 不做文件管理器替代品；超过「临时收集/转存」的需求应引导
用户用资源管理器。

### 3. 暂存架

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| Windows 原生 | Win+V 剪贴板历史 → 选择粘贴 | 系统级、但内容易丢、无任务语义 |
| Task Dock 现状 | 复制/拖入暂存架 → 持久保留类型（文本/图片/文件/HTML）→ 需要时取用/拖到目标 | 持久化 + 类型保留 + 可被任务/项目引用 |

**判断：保留。** 与剪贴板历史相比的差异是「持久 + 可关联」，这是明确价值；不要把它
扩展成通用文件库。

### 4. 任务管理

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| Windows 待办/第三方 | 打开应用 → 新建任务 → 设提醒 | 功能完整，但与开发/项目上下文分离 |
| IDE | TODO 注释/问题面板 | 只在代码内 |
| Task Dock 现状 | 快速捕获/完整面板 → 任务 → 提醒、关联目标、Agent 关联、工作空间关联 | 价值在「和项目/Agent/现场同处一个上下文」 |

**判断：保留，不扩张为完整项目管理。** 里程碑/甘特/多人协作交给规划中心或专业工具；
Task Dock 只保证「捕获—关联—提醒—复盘」链路。

### 5. Agent 任务交接包

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| Agent 内置 | 在会话里手工粘贴背景、约束、文件清单 | 每次换 Agent/工具都要重复输入；历史难留存 |
| IDE | 复制文件路径 + 说明 | 无模板、无敏感扫描 |
| Task Dock 现状 | 选项目/任务 → 生成十二节模板 → 选择资料（笔记/暂存架）→ 敏感扫描 → 保存版本/复制 | 跨工具复用同一份交接内容 |

**判断：加强。** 这是最有跨工具价值的能力之一。下一轮补「关联 Agent 会话 + 执行结果
回到待验收」，但仍以复制/导出为主，不自动向外部 Agent 发送。

### 6. Git / Worktree 协调

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| IDE | 源代码管理面板：分支、暂存、提交、worktree 扩展 | 单仓库体验最好 |
| Task Dock 现状 | 开发项目登记 → 只读探测分支/dirty/是否 worktree | 仅摘要 |

**判断：加强（只读协调），不重做 Git 客户端。** 价值在「多个 Agent/多个 worktree 同时
改动时，看出谁改了哪些文件、是否重叠」；不提供 merge/rebase/reset/stash/删除分支。
当前只有底座，未实现协调中心，能力状态不得标 available。

### 7. 开发环境监控

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| IDE | 终端/任务运行器启动测试、看退出码 | 与项目强绑定、成熟 |
| Task Dock 现状 | 未实现 | 无真实执行器 |

**判断：降级（先做只读登记）。** 若只做「服务/命令登记 + 最近结果展示」，价值有限且与
IDE 终端重叠；只有接入真实执行（明确授权、超时、取消、输出上限）并回传验收证据时才值得
投入。未实现前不得显示「自动测试」入口。

### 8. 问题复现包

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| 通用 | 截图 + 手写步骤 + 日志文件，分多处保存 | 信息散落、跨工具传递靠手工 |
| Task Dock 现状 | 诊断中心可查记录；尚无「问题包」 | 诊断底座已存在 |

**判断：加强（下一轮）。** 跨领域价值明确：诊断事件 → 问题包（复现步骤/附件/脱敏）→
修复提示词 → 关联任务 → 复验。复用现有诊断，不建第二套日志系统。

### 9. 工作现场恢复

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| Windows 原生 | 重启后应用自行恢复；或手动逐个打开 | 不可选择、不可预览 |
| Task Dock 现状 | 保存现场 → 恢复（逐项回执）→ 场景/应用恢复 | 可选择、可解释失败项 |

**判断：保留 + 加强关联。** 关联 Project Workspace / 开发仓库 / 当前任务，恢复前预览与
部分恢复；**项目切换不自动启动应用**，三种操作（项目切换 / 场景进入 / 现场恢复）保持分离。

### 10. 专业工作空间（Project Workspace）

| 通道 | 真实操作步骤 | 观察 |
|---|---|---|
| IDE workspace | 打开仓库 → 看到代码/终端/Git | 只覆盖开发，单一领域 |
| 专业软件 | 游戏引擎/视频编辑器各自管理项目 | 互不联通，跨工具上下文靠人 |
| Task Dock 现状 | 独立窗口 + 四类型 Profile + 事项/任务关联 + 开发项目弱引用 + Git/Agent 摘要 | **基础 Profile 已实现**：导航/首页/能力声明按类型不同；游戏与 AI 漫剧没有真实业务闭环 |

**判断：保留 + 克制。** 定位是「跨工具项目上下文容器」，不是第二套 IDE/引擎。下一步只做
已有真实接口的最小闭环（开发：交接/验收/Git 协调；游戏/AI 漫剧：没有构建或生成接口前
保持 planned/unavailable，不放假按钮）。

## 汇总

| 能力 | 判断 | 理由（一句话） |
|---|---|---|
| 应用管理 | 合并 + 保留场景/现场 | 单应用启动与系统重叠，组合启动才有价值 |
| 文件收集 | 保留（轻量） | 价值在临时收集与任务关联，不在文件管理 |
| 暂存架 | 保留 | 持久 + 类型 + 可关联，区别于系统剪贴板历史 |
| 任务管理 | 保留（不扩张） | 上下文整合是差异点，项目管理深度交给专业工具 |
| Agent 交接包 | 加强 | 跨工具复用同一份上下文，减少重复输入 |
| Git 协调 | 加强（只读） | 多 Agent/多 worktree 的重叠提示是真空缺 |
| 环境监控 | 降级 | 无真实执行器前与 IDE 终端重叠 |
| 问题复现包 | 加强（下一轮） | 诊断→问题包→修复→复验的闭环跨领域通用 |
| 现场恢复 | 保留 + 关联 | 可选择/可解释恢复优于系统自动恢复 |
| 专业工作空间 | 保留 + 克制 | 基础 Profile 成立，专业闭环不得假装完成 |

**结论：** Task Dock 的产品价值集中在「跨工具的项目上下文、任务关联、Agent 协调与
复现/验收闭环」，而不是替代任何专业软件。后续投入应按此集中，不再增加与系统/IDE
重叠的单点功能入口。
