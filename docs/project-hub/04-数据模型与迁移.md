# 项目中枢：数据模型与迁移方案

> 版本：2026-11-18 设计基线
> 约束：迁移只追加在 `db::MIGRATIONS` 末尾；不改已发布迁移；不重建已发布表；
> 新表全部登记 `EXTENDED_TABLES` / `BACKUP_TABLES` 并给出 `restore_order`。
> 本文给的是**待实施 DDL 草案**，不是已执行迁移；实施时以 `schema.rs` 与迁移回放测试为准。

## 1. 设计原则

1. **一个项目根**：`workspace_projects` 是唯一项目实体，已有 20+ 表以它为外键，不新建第二套。
2. **计划不独立成项目**：`planning_projects` 收敛为「计划容器」，通过 `workspace_project_id` 挂到项目。
3. **阶段复用里程碑表**：不新建 `project_phases`。`planning_milestones` 增加 `kind`，
   `kind=phase` 即阶段；功能通过既有 `planning_features.milestone_id` 挂阶段。
4. **弱引用优先**：跨域指针（计划→项目、需求→阶段、交付物→路径）用弱引用 + 完整性校验，
   避免 SQLite 重建表、备份顺序与级联误删；同一域内仍用真实外键。
5. **不复制内容**：任务、笔记、知识库、Skill、MCP、Agent 只存关联/引用，不存副本。
6. **不新增「项目状态」轴**：项目 `active/archived` 是生命周期；计划 `planning/in_progress/paused/completed`
   是执行状态；两者并存，UI 分开显示。

#### project_capabilities（能力库，全局）

```sql
CREATE TABLE project_capabilities (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  category TEXT NOT NULL DEFAULT 'human',      -- human | tool | ai | agent | external
  description TEXT NOT NULL DEFAULT '',
  mastery TEXT NOT NULL DEFAULT 'unknown',     -- expert|proficient|basic|learning|none|unknown
  mastery_note TEXT NOT NULL DEFAULT '',       -- 证据/说明，不存个人敏感信息
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
```

> 为什么能力库是全局：同一能力服务多个项目；项目删除不得删除能力。
> 掌握度默认 `unknown`，**不得**默认 0 或 80%。

#### project_capability_requirements（项目能力需求）

```sql
CREATE TABLE project_capability_requirements (
  id TEXT PRIMARY KEY NOT NULL,
  project_id TEXT NOT NULL REFERENCES workspace_projects(id) ON DELETE CASCADE,
  capability_id TEXT NOT NULL REFERENCES project_capabilities(id) ON DELETE CASCADE,
  phase_id TEXT,                                -- 弱引用 planning_milestones.id（kind=phase）
  necessity TEXT NOT NULL DEFAULT 'required',   -- required | recommended | optional
  target_level TEXT NOT NULL DEFAULT 'basic',   -- 期望达到
  assessment_level TEXT,                        -- 本项目实测；NULL=未评估
  status TEXT NOT NULL DEFAULT 'open',          -- open | resolved | waived
  impact TEXT NOT NULL DEFAULT '',              -- 缺失影响
  alternative TEXT NOT NULL DEFAULT '',         -- 替代说明（自由文本）
  source TEXT NOT NULL DEFAULT 'user',          -- user | template | inferred
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (project_id, capability_id)
);
CREATE INDEX idx_pcreq_project ON project_capability_requirements(project_id, phase_id, necessity);
CREATE INDEX idx_pcreq_capability ON project_capability_requirements(capability_id);
```

> 一个项目内同一能力只有一条需求（避免重复行）；首次需要的阶段记在 `phase_id`。
> `assessment_level` 优先于能力库 `mastery`；两者皆空 → `unknown`（展示「待评估」）。

## 3. 关系与 ID 规则

| 关系 | 基数 | 实现 | 删除策略 |
|---|---|---|---|
| 项目 → 计划 | 1:N（1 个 active） | `planning_projects.workspace_project_id` + `is_active` 唯一索引 | 项目删除级联计划 |
| 计划 → 阶段 | 1:N | `planning_milestones.project_id`（既有 FK） | 计划删除级联阶段 |
| 阶段 → 里程碑 | 1:N | `planning_milestones.phase_id`（弱引用） | 删除阶段先解除/级联由服务决定 |
| 阶段 → 功能 | 1:N | `planning_features.milestone_id`（既有 FK 到里程碑表） | 阶段删除：功能置空（SET NULL 语义） |
| 项目 → 能力需求 | 1:N | `project_capability_requirements.project_id` | 项目删除级联需求 |
| 能力 → 需求 | 1:N | `capability_id` FK | 能力删除级联需求（先校验引用） |
| 能力 → 资源 | 1:N | `capability_resource_links` | 能力删除级联关联；资源本体不动 |
| 项目 → 交付物 | 1:N | `project_deliverables.project_id` | 项目删除级联；磁盘文件永不删除 |
| 项目 → 版本 | 1:N | `plan_versions.project_id` | 项目删除级联 |
| 任务 ↔ 阶段/能力 | N:N | `task_plan_links` / `task_capability_links` | 任一端删除只删关联 |

**ID**

- 沿用 `uuid::Uuid::new_v4()`；计划 ID 与项目 ID **互不复制**（除迁移同 ID 回填外）。
- 迁移时若计划 ID 与既有项目 ID 冲突（UUID 碰撞，理论上极低）：项目行使用确定性
  `plan-<plan_id>`，计划 ID 保持不变；MCP 授权仍按计划 ID 命中，不受影响。
- 弱引用一律保存原 ID，不因目标删除而清空；读侧返回 `exists=false`。

## 4. 删除与共享资源策略

### 4.1 删除项目

```
deleteProject(projectId):
  1. validateProjectIntegrity(projectId) → 有阻塞项则拒绝并列出
  2. 单事务：
     - planning_activity / features / steps / milestones / plan_versions / goals /
       requirements / deliverables / project_events / task_*_links / plan_dependencies 级联删除
     - workspace_items / instances / novel_* / 五线专业表 级联删除（既有外键）
     - 任务：只删关联（workspace_task_links / task_plan_links / task_capability_links），
       tasks 行保留
     - 共享资源：knowledge_bases / capability_skills / capability_contexts /
       capability_recipes 的 project_id/workspace_id → SET NULL（既有行为）
     - 能力库 project_capabilities 不删除
  3. 记录 project_events(kind=project_deleted)？项目行已删，无处挂载 → 写入全局审计
     （diagnostics 或 navigation_log 口径），不在已删项目下留孤儿事件
```

> 注意：`project_events` 外键级联，项目删除后事件也消失。若需留档，复制摘要到全局审计表
> （P1，实施时决定），不得伪造「可恢复」。

### 4.2 删除共享能力/资源

- `project_capabilities`：先查 `project_capability_requirements` 与 `task_capability_links`
  引用数；>0 时拒绝，提示「仍被 N 个项目/任务使用」；管理员可显式 `force`（需二次确认，v1 不提供）。
- 知识库/Skill/MCP：继续由原模块管理；项目侧只解除关联。

### 4.3 项目恢复

- v1 **不提供软删除**；恢复 = 从备份恢复（完整/快速）。
- 归档项目可恢复为 active（既有 `workspace_project_set_status`）。
- 文档与 UI 不得承诺「回收站恢复项目」。

## 5. 事务与并发

| 场景 | 规则 |
|---|---|
| 应用修订 | 单事务：校验 → 写计划/阶段/功能 → 写 `plan_versions` 快照 → 写 `project_events`；任一步失败整体回滚 |
| 创建项目（自然语言/模板/手动） | 单事务：项目 + 计划 + 阶段/功能 + 能力需求 + 初始任务关联；失败不留半成品 |
| 任务状态变更 | 任务服务写 `tasks`；项目侧只重算缓存并写事件，不开跨域大事务 |
| 并发修改 | `planning_projects.revision` / `planning_features.revision` 继续作为乐观并发；新表用 `updated_at` + 服务级校验 |
| 重复调用 | 同一 `request_id`/同一唯一键返回既有结果，不新增行（能力需求、资源关联、版本号） |
| 批量生成任务 | 先算 diff，再按 `UNIQUE(task_id, phase_id)` 去重；重复生成不产生重复任务 |

## 7. 迁移 v78 实施步骤（草案）

```
v78 = DDL + backfill，全部在 apply_migrations 的单事务内执行：
1. ALTER workspace_projects 加 4 列
2. ALTER planning_projects 加 3 列 + 建索引
3. ALTER planning_milestones 加 3 列
4. CREATE 11 张新表 + 索引
5. 回填：
   a. 对每个 planning_projects：
      - 若同 ID 的 workspace_projects 不存在 →
        INSERT workspace_projects(id=plan.id, name=plan.name, kind='general',
          status=plan.archived?archived:active, description=plan.description,
          goal='', target_date=plan.target_date, active_plan_id=plan.id, ...)
      - 若冲突 → INSERT 项目 id='plan-<plan.id>'，active_plan_id=plan.id
      - UPDATE planning_projects SET workspace_project_id=<项目 id>, is_active=1
   b. UPDATE planning_milestones SET kind='milestone'（默认值即可，显式回填便于审计）
6. 自检：
   - 每个 planning_projects 都有 workspace_project_id 且目标项目存在（同库查询）
   - 每个项目最多 1 个 is_active=1 的计划（唯一索引保证）
   - 计数比对：迁移前后 planning_* 行数一致；workspace_projects 行数 = 旧数 + 新建数
   - PRAGMA foreign_key_check 0 违例
```

**回滚**：迁移在事务内，任一步失败整体回滚到 v75；不提供降级脚本，回退用升级前备份
（与既有迁移策略一致）。

## 8. 数据一致性规则（服务层强制）

1. 项目必须有且仅有一个 active 计划（创建项目时同事务创建）。
2. 计划必须属于一个项目；不允许新建「无项目计划」。旧命令 `planning_create_project`
   内部改为「建项目 + 建计划」，返回计划实体（保持签名）。
3. 阶段 `kind=phase`；`planning_features.milestone_id` 指向阶段时，功能即属于该阶段。
4. 能力需求的项目/能力必须存在；阶段弱引用失效时保留但标记 `phaseMissing`。
5. 交付物路径必须通过 `validate_abs_path`；空路径允许（仅登记链接/说明）。
6. 任务关联的项目必须存在；阶段/里程碑失效时保留关联并标记失效。
7. 项目删除前必须 `validateProjectIntegrity`；有阻塞项时拒绝。
8. 任何跨项目写入必须校验归属：`project_id` 与目标实体归属不一致 → `Forbidden/Invalid`。

## 9. 完整性校验清单（`validateProjectIntegrity`）

| 检查 | 级别 | 处理建议 |
|---|---|---|
| 项目无 active 计划 | 阻塞 | 创建默认计划 |
| 计划 `workspace_project_id` 指向不存在项目 | 阻塞 | 重新绑定或归档 |
| 阶段 `phase_id` 指向不存在阶段 | 警告 | 清空或修复 |
| 能力需求引用不存在能力 | 阻塞 | 解绑或补建 |
| 任务关联指向不存在任务/项目 | 警告 | 清理关联（需确认） |
