## 8. 实施完成判定（整体）

只有同时满足以下条件，才可称「本次架构升级完成」：

1. 项目中枢成为唯一项目入口；规划中心/能力中心不再各自维护项目。
2. 工作空间可关联并反馈；任务数据全局唯一。
3. 自然语言创建 + 局部修订 + 版本管理可用；手动创建仍保留。
4. 能力需求/缺口/资源关联可用，准备度可解释。
5. 五种模式分别通过验收。
6. 无 AI 服务时基础功能完整。
7. 旧数据无损、旧备份可恢复、旧命令不回退。
8. 构建成功（集成快照 + 正式安装包），验收证据齐全。
9. 未解决问题清单与后续建议已交付。

## 11. 2026-11-21 第二阶段：S5 缺陷收敛 + S6 规划接管 + S7 能力资源整合

目标：修掉 S5 遗留的生命周期/幂等/草案丢失三个缺陷；让项目中枢成为项目管理主入口；

### 11.1 S5 缺陷收敛

| 缺陷 | 修复 | 落点 |
|---|---|---|
| 归档 active 计划把项目变成「无 active 计划」 | `archive_plan_tx` 内核：归档当前计划必须存在**未归档继任者**，同事务切换 `is_active` 与项目 `active_plan_id`；无继任者返回 `Conflict` | `project_hub/service.rs`、`commands/planning.rs` |
| 可以直接激活已归档计划 | `activate_plan_tx` 拒绝 archived 计划；恢复需显式 `archive_plan(..., false)` | `project_hub/service.rs` |
| 删除当前计划时可能选中已归档继任者 | `delete_plan_tx` 只从未归档计划中选继任者；无继任者返回 `Conflict` | `project_hub/service.rs` |
| 完整性校验漏掉 archived 状态 | `integrity_in_conn` 新增：active 计划处于 archived / 全部计划归档 / `active_plan_id` 指向归档计划，均为**阻塞项** | `project_hub/service.rs` |
| 计划补链可能复活归档计划 | `ensure_project_plan_tx` 只在未归档计划中挑选；全部归档时新建计划 | `project_hub/service.rs` |
| 创建重试产生重复项目 | 后端保存**规范化请求摘要**（SHA-256）到 `project_events.payload_json.requestDigest`；同 ID 同摘要返回原项目，同 ID 不同摘要返回 `Conflict` | `project_hub/service.rs` |
| 草案里的「预计产出」没有落库 | `CreateProjectInput.features`（title/acceptance/priority/phaseIndex）→ 同事务写 `planning_features`，`milestone_id` 指向阶段 | `project_hub/service.rs`、`lib/contracts/models.ts` |

> 摘要存储沿用既有 `project_events.payload_json`，**没有新增表**；`clientRequestId` 仍是幂等键，
> 摘要只是把「同一请求」升级为「同一请求 + 同一参数」。

### 11.2 S6 项目中枢接管规划

- 项目中枢视图从 4 个扩到 6 个：总览 / 目标与规划 / 功能与看板 / 能力 / 项目资源 / 执行。
- 进度口径统一走既有领域函数（`calculateProjectProgress`）：阶段按**功能 + 必需交付物**计算，
  整体按阶段等权，里程碑无可判定依据时为 `null`（不再出现「全部完成后仍显示第一个阶段」）。
- 「无资源」与「资源未评估」分离：`resourceCount=0` → `unavailable`；`>0` 但从未校验 → `unknown`。
- 规划编辑**不复制**：项目中枢「目标与规划」视图提供「在规划编辑器中打开」深链，
  由 `PlanningCenterPanel` 切换到既有 `PlanningWorkspace`（新增可选 `initialProjectId`，
  不改变既有行为与签名）。
- 读模型新增 `features`（`planning_features`）、阶段/里程碑功能计数、能力已校验资源数。

### 11.3 S7 能力资源整合
