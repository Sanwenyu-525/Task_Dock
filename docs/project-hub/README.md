## 1. 一句话

TaskDock 的项目中枢是**目标驱动的项目执行体系**：用户说出想完成什么，系统生成可修改的规划，
分析能力缺口，组织任务与工作空间，承接产出与反馈，直到交付。

它把现有四个子系统收束到**一个项目根**：

| 现有模块 | 在项目中枢中的角色 |
|---|---|
| 规划中心（`roadmap`） | 成为项目中枢本体：总览 / 规划 / 能力 / 项目资源 / 执行 |
| 能力中心（`capability`） | 提供知识库 / Skill / MCP / 上下文 / 配方，作为「能力」的资源来源 |
| 工作空间（`workspace`） | 实际执行环境；关联项目并反馈交付物 |
| 任务中心（`tasks`） | 跨项目统一调度；与项目任务共用同一行数据 |

## 3. 关键决定（速查）

1. **唯一项目根 = `workspace_projects`（A 方案，2026-11-18 用户确认）**；`planning_projects`
   收敛为计划容器（加 `workspace_project_id`，不重建表）。v77 协作中心需按 `04` §12.3 改挂
   workspace 根，具体改造由 v77 负责人执行或明确移交。
2. **阶段复用里程碑表**：`planning_milestones.kind = phase | milestone`，不新建 `project_phases`。
3. **能力 ≠ 资源**：`project_capabilities` 是能力库；知识库/Skill/MCP/Agent/工具/模板/工作流
   是资源；两者用 `capability_resource_links` 关联。
4. **四项进度分列**：任务 / 阶段 / 里程碑 / 整体（阶段等权），空分母返回 `null`，禁止不透明加权。
5. **能力准备度双指标**：掌握度与资源可用度分开；未评估显示「待评估」，不编造百分比。
6. **默认自然语言创建**，手动创建保留为高级操作；草案必须可修改、可跳过、可撤销。
7. **无 AI 可用**：本地规则解析与模板生成是默认实现；AI 只是可选端口，失败不丢输入。
8. **不改任务两态**：`pending/completed` 不变；延期由 `due_at` 派生，取消 = 删除 + 解除关联。
9. **导航兼容**：保留 `roadmap` 路由与 Ctrl+9，只改显示名「项目中枢」。
10. **删除保护**：共享能力/知识库/Skill/MCP 只解绑不删除；任务永不随项目删除。
