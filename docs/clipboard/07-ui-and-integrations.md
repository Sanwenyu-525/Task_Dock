## 二、抽屉结构

```
剪贴板抽屉
├─ 头部：状态徽标（监听中/已暂停/已停用/监听未启动）
│        暂停/恢复、设置、关闭
├─ 任务关联横幅（从任务编辑器进入时显示）
├─ 工具栏：搜索（260ms 防抖）、只看收藏
├─ 类型筛选：全部/文字/链接/富文本/图片/文件
├─ 标签页：历史（total_items） / 分组（groups.length）
├─ 列表
│   ├─ 条目卡片：类型、标题（自动/手动，主行）、预览（次行弱化）、缩略图/占位、
│   │            来源/时间/大小、收藏/置顶、复制、详情、删除、多选、关联任务
│   └─ 分组卡片：名称、状态、条目/图片数·模式（合并一行弱化）、预览、
│                复制富文本/文件、粘贴、详情、收藏/置顶、删除、多选、关联
├─ 多选操作栏：复制所选（富文本）/ 复制为文件 / 逐项粘贴 / 创建分组 /
│               删除所选 / 取消选择；分组多选另有合并
└─ 底部：状态、条目/分组统计、图片缓存大小、清空历史、设置入口
```

### 单条「复制并切换 / 粘贴到目标窗口」（2026-11-06，2026-11-07 增补粘贴）

与「复制」「逐项粘贴」并列的独立操作。目标选择器内现在有两个动作，**语义严格区分**：

- **复制并切换**：只复制并激活目标窗口，不发送任何按键（2026-11-06 交付）；
- **粘贴到目标窗口**（2026-11-07 新增）：复用后端单条粘贴队列
  （`clipboard_paste_items` 传单条 id），由 Rust 完成受控写入 → 聚焦 → 发送一次
  `Ctrl+V` → 观察目标消费 → 尝试恢复原剪贴板。前端不自行聚焦、不合成按键、
  不新增第二套粘贴实现；「按键已发送」不表述为「目标已接收」。

- **入口**：完整面板条目卡片保留原复制按钮（行为不变），右侧 ↗（`ArrowUpRight`）直接打开
  目标选择器，**不再套一层只有一个选项的菜单**；胶囊列表行同样保留复制图标，旁边的小箭头
  进入胶囊内目标选择二级视图。两个入口都是独立按钮：点复制不会打开选择器，点箭头不会提前复制。
  入口文案随动作扩展为「复制或粘贴到目标窗口」，选择器标题为「复制或粘贴到…」。
- **目标行交互（2026-11-06 修正，2026-11-07 增补）**：目标不是「单选后确认」，点下即执行。
  完整面板行主体仍是复制并切换按钮（↗ 图示在按钮内部右侧，点信息区或箭头命中同一按钮）；
  行尾新增独立粘贴按钮（`.icon-btn.sm` + `ClipboardPaste`，真实按钮、`data-tip` +
  `aria-label`）。胶囊行为「主区域按钮 + `.cap-mini` 箭头（复制并切换）+ `.cap-mini`
  粘贴按钮」，三个入口绑定各自动作、命中区独立。任一动作在途时整行禁用，进行中的按钮
  显示 spinner，另一个动作不会并发触发。
  图标一律使用 `ArrowUpRight` / `ClipboardPaste`；禁止用 `ChevronDown` 表示跳转、
  禁止只有外观没有事件的图标。
- **复制并切换顺序**：选择目标窗口 → `clipboard_paste_precheck`（无副作用校验：存在性、HWND+PID、
  非本应用、权限）→ `clipboard_copy_item`（既有受控写入 + 自写登记）→
  `clipboard_focus_target`（激活前后各校验一次身份与前台）。不自动选择第一个窗口，
  不以窗口标题作为身份，不使用历史记录的来源窗口作为目标。
- **粘贴顺序**：`clipboard_paste_items(targetHwnd, expectedPid, [itemId])` →
  后端任务执行 precheck/聚焦/受控写入/按键/观察/恢复 → 前端等待 `clipboard-paste`
  终态事件（建立等待后主动读一次 `clipboard_paste_job` 快照补竞态，15s 超时兜底）→
  按任务状态显示「已向…发送粘贴 / 粘贴已取消 / 粘贴未完成 / 未确认结束」。
  开始失败（目标失效、已有其它粘贴任务、条目已删除）同样如实报错，不显示成功。
  粘贴不计入 `copy_count`（粘贴不是复制），与既有逐项粘贴口径一致。
- **共享实现**：`src/lib/clipboardCopySwitch.ts`（复制事务 + 粘贴结果归一化与统一文案）+
  `src/hooks/useClipboardCopySwitch.ts`（状态机/竞态/统计/粘贴任务等待）+
  `src/components/clipboard/CopySwitchTargetRow.tsx`（两端共用目标行，
  `full` / `compact` 只差展示，两个动作契约一致）；
  完整面板 `CopySwitchPanel` 与胶囊 `ClipboardTargetView` 只做展示布局，不各自实现窗口逻辑。
- **失败语义**：precheck/复制失败不切换窗口；复制成功但切换失败不回滚、不重复复制，
  提供「仅重试切换」；部分成功（`stats_recorded === false` 或存在 warnings）沿用
  `CopyReport`，提示保留「部分成功」且不本地累加使用次数。粘贴失败/取消提供「重试」
  （重新发起一次单条粘贴任务），不把取消或未确认显示为成功。
- **目标列表**：只在选择器打开时枚举 + 手动刷新，无轮询；图标复用 `TargetIcon` 缓存。
- **历史一致性**：复制后不重新加载/重排列表、不改变搜索筛选与分页、不跳回顶部；
  写入走既有受控链路，自写不回流历史。粘贴任务的受控写入同样不回流。

### 整组复制预检

分组详情在复制前调用 `copyPreflight`（`src/lib/clipboardUi.ts`，纯前端，无额外 IPC）：

- 内嵌图片预算 6 MB：超出时提示将使用 `[图片：预览]` 占位符，并建议改用“复制为文件”；
- 含图片的富文本提示“部分富文本编辑器不接受内嵌图片”；
- 文件模式提示只传递文件路径（不复制文件内容），文本/HTML 项会被跳过；
- 单项 HTML 超过 512 KB 时提示将降级为纯文本；
- 汇总总项数/图片数/文件数，警告措辞与后端固定警告保持一致。

预检只解释限制，不改变复制结果；最终是否占位、跳过仍以后端返回的 `warnings` 为准。

### 图片大图预览层（2026-11-03 新增）

详情原图与列表缩略图点击进入独立灯箱（`src/components/clipboard/ImageLightbox.tsx`，
portal 到 body，注册弹层栈 modal 层：Escape 只关灯箱，z 序在抽屉之上、确认框/菜单之下）：

- 默认按窗口可用空间等比适应（不上采样小图），双击在适应窗口 ↔ 实际尺寸间切换
  （以指针为不动点）；滚轮以指针位置为中心缩放（原生 `wheel` 监听非 passive，
  不与抽屉滚动冲突；`exp(-deltaY*0.0015)` 平滑系数对触控板/高 DPI 稳定）；
  缩放边界 5%–1600%；工具栏另有放大/缩小/适应窗口/实际尺寸；
- 拖拽平移用 Pointer Events + capture；平移钳制保证图片任一维度超出可用空间时
  边缘不越过舞台边缘（图片永远不会被完全拖出可视区域）；
- 舞台尺寸变化（窗口缩放）时适应态重算、缩放态重新钳制（ResizeObserver）；
- 工具栏：复制原图（`clipboard_copy_item` 受控链路，自写登记不回流，透明通道保留）、
  - 另存为：系统保存对话框选路径（只负责选路径，不保证弹 Windows 原生「替换」提示）→
    `clipboard_path_status` 判定目标状态：`missing` 以无覆盖授权落盘；`ok` 先弹应用内
    「覆盖已存在的文件？」确认框，用户确认才以覆盖授权落盘、取消/拒绝则完全不写盘；
    `inaccessible`/未知值/空结果/IPC 异常一律拒绝并提示（fail-closed，不以覆盖兜底）→
    `clipboard_save_image(itemId, path, overwrite)` 由 Rust 原子写入（仅 .png；可关闭；
    失败时原文件保持不变，错误如实展示；成功反馈区分新建/覆盖）。写盘与读图在后台
    阻塞线程池执行，保存期间灯箱与主窗口保持可交互；对话框创建失败只提示错误，
    不查状态、不写盘，并恢复按钮可用
- 信息栏：像素尺寸（解码后 natural size）、`PNG（存储格式）`（采集统一规范化为 PNG，
  不冒充用户复制的原始格式）、字节大小、来源；
- 性能：原图 data URL 由 `Media.tsx` 共享缓存提供——加载 promise 全局去重
  （详情大图与灯箱并发只发一次 IPC）、成功结果 LRU 上限 2 条（重复打开不重复
  IPC，超出释放最旧）；关闭灯箱只卸载组件状态，不改变剪贴板整体缓存策略；
  加载中/文件缺失/读取失败（图片过大、IO）三态均如实展示。

## 三、状态与数据流

- `useClipboardStore`：筛选（kind/search/favorite）、分页 80、静默刷新、
  多选；刷新后自动剔除已删除的选中 id。
- 复制成功后只调用 `bumpItemCopy(id)` 就地累加使用次数，不重新请求列表：
  后端 `bump_copy` 也不再更新 `last_seen_at`，列表顺序与已加载分页保持稳定。
- 标题编辑成功后同样就地更新（`renameItem(id, title, titleSource)`，模式同
  `bumpItemCopy`），不重新请求列表、不重置分页。
- 静默刷新（后端采集/整理事件）至少按当前已加载条目数分块拉取（每块 ≤200），
  不会把多页列表缩回第一页；筛选或请求代数变化时立即放弃在途页。
- 页面与抽屉共用底部「清空历史」入口：无条目/分组时禁用，执行期间禁用重复点击，
  确认框明确说明删除范围（含收藏/置顶与内部图片缓存）以及不影响系统剪贴板、
  外部原始文件；成功后清空多选、详情并重新加载视图。
- `useUiStore`：`clipboardOpen`、`clipboardLinkTask`（携带任务进入关联模式）、
  `clipboardLinkVersion`（关联变更后任务编辑器重读）。
- 打开抽屉或筛选变化时拉取；260 ms 搜索防抖；监听 `clipboard-changed` 事件，
  300 ms 合并后静默刷新，避免高频采集导致重复请求。
- 来源为空或 `unknown` 时显示“未知应用”，不做猜测；应用名走静态映射表（`chrome.exe` → Google Chrome），未知应用只去扩展名、保留原名；浏览器标题只去掉末尾重复的浏览器名，原始 exe 与原始标题进提示与详情页。
- 识别方式文案（2026-11-03 更正）：`owner` →「剪贴板所有者窗口（系统记录）」、
  `foreground` →「前台窗口（推断来源）」、`unknown` →「未能识别来源」、
  `''` →「旧记录未记录识别方式」。`GetClipboardOwner()` 只代表系统登记的所有者，
  不保证是用户实际执行复制的程序，文案不使用“可确认写入方/真实写入方”等绝对表述。
  详情页「采集环境」保留一句“这里记录的是采集时识别到的应用与窗口环境，
  不一定是实际执行复制操作的程序。”
- 头部状态区分“监听中 / 已暂停 / 已停用 / 监听未启动”，来自 `clipboard_status`；
  监听线程未启动时历史仍可查看，但空态不会暗示“正在记录”。
- 列表 DTO 已压实（正文→预览），完整内容只在详情接口读取。
- 预览截断只发生在展示层（2026-11-02 回归修复）：条目卡片标题单行、正文两行。
  约束必须写在 `.clip-preview-body` 的子元素上（`.clip-preview-body > span` /
  `.clip-preview-body > .clip-text`），且 `.clip-text` 要自带 `overflow: hidden`——
  `-webkit-line-clamp` 只压布局盒高度，缺了 overflow 时剩余行照样绘制到卡片外，
  表现为“卡片没变高、文字却盖住下一张卡”。长英文、URL、连续字符串靠
  `overflow-wrap: anywhere` 断行，不靠固定高度。原文与复制结果不受影响。
- 缩略图按需请求并缓存（LRU，最多 240 条，含并发去重）；大图只在详情打开时加载。
- 所有复制/粘贴结果使用后端返回的消息，不自行推断“成功”。

### 删除与离场反馈（2026-11-02）

删除分成三个可观察阶段，任何一步失败都不演“已成功”：

1. **执行中**：确认后到后端返回之前，目标卡片进入 `pending`（`aria-busy`、`tabIndex=-1`），
   常驻操作不可再触发；此时条目不离开列表、不出离场动画、不弹成功提示。
2. **离场**：后端确认删除后，store 用 `beginExit` 记住该行的快照与原始索引，
   组件在 `useLayoutEffect` 里把实测高度写进 `--clip-exit-h` 并加 `.removing`，
   由 `clip-remove` 关键帧收拢高度与透明度（0.19 s）；离场期间 `pointer-events: none`、
   `aria-hidden="true"`、移出 Tab 序列。列表刷新（含后台采集事件）不会提前卸载离场行。
3. **补位**：离场结束后 `endExit` 从视图剔除并触发一次静默刷新；删除开始时焦点若在卡片上，
   离场结束后交给相邻行，取不到时退回搜索框。

- 后端返回删除数量为 0（并发下已被别处删掉）时提示“这些内容已经不存在，列表已刷新”，
  不播离场动画；IPC 报错时原样展示错误，条目保持原位。
- 批量删除沿用同一条链路：一次请求、一次共享离场；后端返回数量少于请求（部分成功）时
  不整批演离场，提示“选中 N 条，实际删除 M 条，其余仍在列表中”并立即静默刷新，
  失败项保持原位，不伪装成已删除。
- 只看收藏下取消收藏是“退出筛选”而不是删除：不做删除式离场，toast 明确
  “退出「只看收藏」列表，内容仍保留在历史中”；取消置顶等排序变化只做轻量重排。
- 组内操作不套用删除语言：从分组移除只改归属（toast 说明内容仍在历史中），
  上移/下移用 200 ms 轻量位移；合并让原分组按分组离场退场，新分组随刷新出现。
- 收藏/置顶/添加分组/移出分组/合并等操作都是就地更新（`patchItem`/`patchGroup`）
  加一条带对象标题的 toast，不整表刷新；只有会改变排序的置顶会补一次静默刷新。
- `prefers-reduced-motion: reduce` 下离场延时为 0，动画由全局规则压到 0.01 ms，
  删除结果仍会落地；不为每种操作单独设计动画。

### 离场生命周期与重排规范（2026-11-03 第二轮）

第一轮落地后的生命周期修补，以下为长期有效的契约：

- **离场收尾定时器归 store 所有**：`beginExit` 为每个 id 建一个一一对应的收尾定时器
  （store 内 `exitTimers` 映射），到点自动 `endExit` 并从本地视图剔除。组件卸载
  （动画中途关闭抽屉/切页）不影响收尾——重开抽屉时以服务端数据为准，已删除的行
  不会以快照形式复活。`endExit` 幂等：组件收尾与 store 收尾先后各调一次是合法的；
  清理一个条目的定时器不影响其他离场条目。`resetClipboardRequestState` 会一并回收。
- **组内移除/拆分按展示顺序取位置**：分组详情的离场索引必须来自实际展示的行序
  （含仍在离场的行），不得用 `group.items.findIndex`——连续移除时后端列表已少了
  先前移除的条目，按它算会让后移除的行钉到已离场行的前面。
- **离场行整棵子树不可交互**：`aria-hidden` 的行/卡上必须加 `inert`，内部控件
  （含勾选框、行主按钮）同步禁用；不能只靠 `pointer-events: none`（键盘 Tab 仍可达）。
  组内移除的焦点在离场结束后交给相邻行，分组空了退回「返回分组列表」按钮。
- **FLIP 与离场互斥**（2026-11-04 第三轮修正，见下文）：主列表（置顶/取消置顶等排序变化）与组内（上移/下移）都用
  一次位置读取 + Web Animations API 位移补偿（≤60 行、`ease` 200 ms），
  不引库、不常驻 rAF。离场开始或结束的那次渲染不播重排——收拢动画已经在表达
  「下方行上移」，再叠 FLIP 会让行先跳回去再滑一遍。
- **拆分与删除的真实数量**：`clipboard_delete_group` 返回新增 `groups_deleted` 字段
  （实际删除的分组数，`delete_items` 恒为 0）；分组不存在时前端按“已经不存在，
  列表已刷新”处理，绝不演一场成功。拆分成功的条目按组内移除的同一套收拢语言离场，
  失败不播任何成功动画。
- **筛选退出 ≠ 删除**（2026-11-04 第三轮修正：改为先提交、成功后才离场，见下文）：
  完成任务（默认未完成筛选）与行动中心标记已处理（默认不含
  已处理）使用 `list-collapse-out`（淡出收拢、无删除侧移语言），动画结束后才提交
  刷新；失败立即弹回原位。「历史」分类确认后行仍留在列表，不播退出动画。
  空列表出现用 0.18 s 轻量淡入（`soft-fade-in`）。

### 离场与重排第三轮修正（2026-11-04）

- **先提交、成功后才离场**：任务完成与行动中心确认点击后立即进入执行中并调用后端；
  只有真成功且该行确实要退出当前筛选时才播 `list-collapse-out`，动画结束才同步列表。
  后端失败不进入离场、不刷新列表、原卡片与按钮状态保持不变。`useTasksStore.toggle(id,
  { refresh: false })` 只推迟「列表同步」这一件事，写入本身不推迟、也不允许用重复提交补偿。
- **行动中心的最小离场快照**：`ack()` 成功后内部会立刻静默刷新并移除该行；组件在点击时
  记下「原条目 + 展示索引 + 实测高度」，离场期间把快照按原位置渲染回列表。后台整表刷新、
  游标翻页、`countsOnly` 刷新都不会提前卸载或重复插入它；筛选/分类变化、卸载时清掉快照
  与定时器。`ack()` 返回 0（已处理过）只提示「已经是已处理状态」，不演首次成功、不播离场。
  「历史」分类与「显示已处理」下条目仍留在列表，只更新状态、不做退出动画。
- **分组删除判定统一**：`groups_deleted > 0` 才算真删；卡片与分组详情共用
  [groupDeleteFeedback](file:///d:/Develop/task_dock/src/lib/clipboardUi.ts) 的判定与文案。
  `groups_deleted = 0` 时只提示「这些内容已经不存在，列表已刷新」（warning），
  不播成功离场、不从本地移除，交给静默刷新定性；连带删除仍只在 `retained_shared === 0`
  时本地摘条目，收藏/置顶/任务引用/其他分组引用的条目不会被误删。
- **网格与 FLIP**：离场进行中永远跳过重排补偿（离场优先于重排，数据正确性优先于动画）。
  顺序列表的收拢高度已经表达「下方行上移」，结束帧不再叠加 FLIP（否则会闪回原位）；
  纯图片双列网格改用 `clip-shot-remove`（原地淡出 + 轻缩、不收缩高度），在移除那一帧
  做一次 x/y 位移补偿，避免半格空白与补位跳动。列表 ↔ 双列/整理模式切换的那次渲染
  不做补偿，防止坐标系切换被当作排序变化。
- **减少动态**：`prefers-reduced-motion` 下不播离场、不等时长，业务立即提交并刷新，
  删除结果、筛选与焦点转移保持准确。

### 复制反馈、滚动位置与清空一致性（2026-11-04）

**复制反馈三态**：写入成功才算成功；`CopyReport.warnings` 非空或
`stats_recorded=false` 时统一显示「已复制（部分成功）」（`info`），只有命令真正
失败才显示「复制失败」。列表卡片、条目详情、胶囊轻量视图共用同一判定；
`stats_recorded=false` 不本地累加使用次数。

**滚动容器与锚点**：

- 真实滚动容器是 `.clip-body`；`.clip-list` 只是行容器，不承载滚动状态。
- 滚动时按阈值采样「第一个与可视区相交的行」→ `{id, 相对可视区顶部偏移}`，
  只在列表结构变化的一次 layout 中补偿 `scrollTop`。没有 `setTimeout` 强恢复、
  持续 rAF、虚拟列表或动画库。
- 顶部附近（`scrollTop ≤ 8`）不补偿，保证外部新增历史时正常显示最新内容；
  中/底部保持当前可见内容，不抢焦点、不打断多选。
- 同一筛选内才做补偿；筛选变化允许回顶并清空旧锚点，旧筛选的滚动状态绝不
  落到新筛选，旧请求响应也不能把新筛选的位置改回去。
- 滚动补偿已经表达位移时跳过该次 FLIP，避免「滚动 + FLIP」双重移动。
- 打开详情时同步记录滚动位置，返回列表后在同一筛选内恢复；期间滚动
  不挂在已卸载的列表节点上。
- 复制只就地更新 `copy_count`，不重排、不整表刷新，因此不改变滚动位置与分页。

**全量清空（前端）**：`clipboard_clear_history` 成功后才调用
`resetAfterClear()`：丢弃 `exiting` 快照并回收 `exitTimers`、清空多选、清空胶囊
轻量视图、推进筛选/请求代际（旧响应作废），立即呈现空态再由 `load()` 以服务端
结果为准。失败路径不调用，保留仍有效的数据；单项/批量删除的离场动画不受影响。

### 导出面板请求生命周期与探测缓存（2026-11-04）

- **默认不探测**：面板收起时只显示「导出给 Agent…」；展开后先给核心导出按钮，
  「Agent 兼容信息」默认收起，只有用户展开才调用 `clipboard_agent_targets`。
- **探测异步 + 缓存**：命令在 `spawn_blocking` 中执行，结果进程内缓存 5 分钟；
  `refresh=true`（界面「重新探测」）强制重扫；普通并发请求持锁串行，只有第一个真正扫描，
  其余复用同一次结果；**并发强制刷新按请求开始时的扫描序号合并**——排队期间已有更新的
  扫描完成则直接复用，不会排成多次 17–28s 的全量扫描。未安装 Agent 跳过窗口/CLI 探测；
  探测失败不缓存错误，再次展开或点击「重试」会重新探测。缓存不持有句柄，退出无需额外回收。
- **探测时间语义**：命令返回 `{ targets, probed_at_ms, cached }`。`probed_at_ms` 是快照的
  真实扫描完成时间（Unix 毫秒），不是前端收到响应的时间；`cached=true` 表示本次请求直接
  复用了 5 分钟内的旧快照。界面据此显示“上次探测 HH:MM”或
  “缓存结果 · 约 N 分钟前探测”，不把缓存中的「窗口可用」表述为实时验证结果；
  刷新失败时保留上次有效列表与时间，并标注“本次刷新失败，以下为上次有效结果”。
- **空结果不等于失败**：`scan_all()` 没有失败通道，空列表只代表当前没有可列出的 Agent，
  不会被当作探测失败，也不会用空结果覆盖已有有效快照；只有后台任务异常结束才是探测错误。
- **请求身份**：导出与路径复制回调在发起时记录 `targetType + targetId + taskId` 的上下文代际，
  完成时仅当代际未变才写回界面。切换条目/分组或关闭面板后，旧请求的结果、
  错误与 loading 状态都不会落到新上下文；同一上下文连点只发起一次导出。
- **忽略结果 ≠ 取消任务**：前端只丢弃过期结果，后端导出任务继续完成并保留已生成文件，
  不会因关闭面板而中断或删除；写盘中途失败时只删除本次独占创建、且未被 `commit` 的
  半成品目录。
- **关闭再展开**：导出结果、技术说明与 Agent 兼容详情均回到默认收起状态。

## 十一、列表离场第四轮修正（2026-11-04）

- **行动中心 ack 代际身份**：`ack()` 在发请求前记录当时 `filter`，返回后只有筛选引用未变才静默
  刷新；`ActionCenterPanel` 另用 `actionViewKey(category + kind + priority + source_id + task_id +
  include_acked)` 校验是否仍处发起视图。切分类/优先级/来源/任务后，旧请求结果只在后端生效，
  不用来刷新列表，也不建离场快照；切换本身已触发加载，不会多加一次轮询或定时器。
- **任务离场键盘隔离**：离场行加 `inert` + `aria-hidden`，完成按钮同时禁用，Tab/Enter/Space
  与鼠标都不能再触发它；离场结束把焦点交给相邻的仍在场任务，相邻任务也离场时取列表里第一个
  仍在场任务，全部离场则回到快速添加入口。失败从不进入离场态，`prefers-reduced-motion` 下
  不播动画但仍按上述规则交接焦点。
- **后台刷新不打断离场**：离场开始时把任务、原展示索引、后续任务 id 与高度登记到
  `useTasksStore.exitHolds`，仅用于**渲染层**按原位置补渲染；`tasks` 始终是后端返回的唯一真实
  数据，快照不参与排序、分页与刷新。动画结束、请求失败、筛选/视图切换与组件卸载都会释放；
  切筛选立即清空。后台 `refresh()` 或别的任务完成触发的刷新不会让离场行提前消失或重复出现。
- **撤销与刷新失败**：离场期间撤销把任务恢复为未完成时，行在动画收尾后撤掉离场态，保持可见
  可操作；刷新失败导致列表仍为未完成时同样撤掉，避免任务被藏成不可见。
- **性能边界**：每行只有一次 190 ms 离场定时器，结束后自然释放；未引入动画库、常驻 rAF、
  全局订阅或轮询，长列表只做一次浅层快照合并。

## 十三、分组卡片预览与智能连续收集呈现（2026-11-05）

### 13.1 数据来源

- 列表 IPC 分组对象新增 `kind_counts`（`image / text / html / url / files`）与
  `cover_items`（最多 3 条图片轻量元数据），由 `store::enrich_groups` 两次批量查询生成，
  不落库、不改表结构、不读正文/原图字节。封面查询外层显式
  `ORDER BY group_id, position`，不依赖 SQLite 的窗口/扫描计划恰好有序，
  保证多组混合时封面顺序与灯箱 `position` 顺序一致。
- 卡片只用列表已返回的元数据渲染摘要与类型数量；**不按卡片额外发 IPC**。
- 旧数据/旧 mock 缺少新字段时，`clipboardUi.groupKindCounts` 用 `item_count + image_count`
  回退为「图片 + 文本」；缺 `cover_items` 时显示统一类型占位，不猜测文件/链接数量。

### 13.2 卡片结构

左侧：选择框 + 44px 预览；中间：分组名、内容摘要、组合数量与时间；右侧/底部：核心快捷操作。
卡片高度按内容自然变化，不强制等高；文本组保持紧凑，图片组仅因封面略高。

| 分组 | 预览 | 摘要 | 补充信息 |
|---|---|---|---|
| 图片 | 1–3 张代表截图叠放（窄容器只渲染 1 张）；数量徽标移到封面右侧，仅在 `image_count` 超过可见封面数时显示真实总数 | 无文字摘要时留空 | 组合数量；**只有单图组**才显示尺寸（如 `1 张截图 · 1920×1080`），多图组不拿首图尺寸冒充整组 |
| 文本 | 类型图标 | 120 字符内的辨识性摘录，2 行截断、长串 `overflow-wrap:anywhere` | `N 段文本`（`html` 合并计入文本） |
| 链接 | Link 图标 | 优先域名 + 路径摘要，`www.` 前缀仅展示层去掉；**不联网抓标题** | `N 个链接` |
| 文件 | Files 图标 | 代表文件名 + 总数（如「季度报告.docx 等 3 个文件」），不读磁盘 | `N 个文件` |
| 混合 | 代表缩略图；无图时类型占位 | 纯文本摘录，避免堆标签 | 各类型数量（如 `2 张截图 · 1 段文本 · 1 个链接`） |

交互约定：

- 点缩略图 = 打开大图预览（分组封面会进一步打开整组多图灯箱），`stopPropagation`
  且不触发卡片详情与选择；
- 点卡片空白区域 = 打开分组详情；卡片根节点**不是** `role="button"`，键盘用户使用卡片内
  「查看分组详情」按钮，内部复制/删除等真实按钮按 Enter 不会串到根节点；
- 常显只保留高频入口：复制整组（富文本）、逐项粘贴、详情、更多；复制文件、置顶、收藏
  收进「更多」菜单（`DropdownMenu`，焦点管理由该组件负责），删除与普通操作之间留固定间距；
- 快捷操作全部带 `aria-label` 与 `data-tip`，危险操作使用独立配色；离场/在途时卡片 `inert`、
  `aria-busy="true"`，操作禁用，避免对即将消失的分组二次操作；
- hover / focus-visible / selected / disabled 沿用历史条目卡片的统一状态样式，不新增视觉语言。

### 13.3 性能与异步

- 缩略图沿用 `useThumbnail` 的缓存与在途去重，只在卡片预览进入视口（`240px` 前后）后请求，

- 未新增轮询、常驻订阅、后台服务或全历史扫描；分组刷新仍复用现有 `clipboard-changed` 事件

## 十四、分组多图灯箱与分页取图（2026-11-05）

### 14.1 预览上下文

`ClipboardWorkspace` 用单一 `PreviewState` 表达灯箱上下文，不重复存大对象：

| 字段 | 含义 |
|---|---|
| `mode` | `single`（单条卡片）或 `group`（分组封面） |
| `itemId` | 打开时点击的图片 id；分组序列晚到时先用它定位 |
| `groupId` | 所属分组（单图为 `null`） |
| `items` | 分组模式下**已加载**的图片序列（仅图片、按 `position` 升序，可随分页增长） |
| `total` | 组内图片真实总数（`image_count`），可能大于 `items.length` |
| `ready` | 首屏真实序列是否已返回；false 时 `items` 只是点击封面的占位，索引不作正式位置 |
| `revision` / `loading` / `error` | 内容版本、分页在途、读取错误（用于竞态与反馈） |

- 单条卡片 → `mode=single`，`items` 不传给灯箱，因此没有箭头/序号。
- 分组封面 → `mode=group`，**封面 `cover_items`（最多 3 张）只用来渲染卡片，绝不当作整组序列**。
  灯箱打开后才调用 `clipboard_group_page(groupId, { limit: 50, offset, imagesOnly: true })`
  取轻量图片元数据：`imagesOnly` 保证文本/文件不计入序号，`ORDER BY position` 与分组顺序一致，
  `offset` 在图片行内计算；不调用 `clipboard_group` 拉全量正文，不预加载任何原图。
- 超过 50 张时按需翻页：灯箱接近已加载末尾时触发 `onNeedMore`，工作区串行追加下一页
  （最多一次在途、按 id 去重），序号与箭头始终按 `total` 显示，不会在第 50 张截止。

### 14.2 交互与异步安全

- 多图灯箱：左右箭头、`当前 / 总数`、`←`/`→` 键盘切换、首张禁用上一张、末张禁用下一张、
  默认不循环；切换只重置上一张的缩放/平移并按比例适应窗口；`Escape` 只关最顶层（弹层栈）；
  关闭只卸载灯箱状态，列表滚动位置不动。
- 从第 3 张封面打开时先按 id 在返回序列中定位，序号从 `3 / 7` 开始；封面只参与占位。
- 请求代号（`previewGenRef`）在打开/关闭/换组时递增：快速切换、跨分组切换、请求未回即关闭、
  组件卸载后返回的旧响应一律丢弃，不覆盖新分组/新图片状态；没有轮询。
- 分页期间 `revision` 变化说明分组内容被移动：丢弃已拼接序列并从第一页重取，避免序号错位；
  当前图片已删时灯箱按 id 找不到，安全回退到序列首张；分组已删/首屏失败时保留点击的图片并
  在工具栏显示「分组图片读取失败：…」，不伪装成可翻页多图；后续页失败保留已加载图片并提示。
- 首屏序列未返回（`ready=false`）时，灯箱不把占位数组的索引 0 当正式位置：方向键只累积
  相对位移（`pendingStepsRef`），不用临时索引计算绝对目标；真实序列到达后在 layout effect 中
  按打开图片的稳定 id 求基准位置，再叠加位移并夹到 `[0, total-1]`，因此第 3 张封面打开后
  立即按 `→` 会落到第 4 张，按 `←` 会落到第 2 张。加载期连按 N 次按 N 步累加，
  不会都映射到同一张；序号显示为「… / N」而不是错误的第一张。
- 目标位置尚未加载（例如首屏还在路上就按 `→`）时，灯箱记住目标序号，页数据追加后自动切过去，
  避免「按了没反应」；目标超出真实总数（条目被删/分组收缩）时丢弃该目标，不跳到错误图片。
  已加载前缀之外的目标也不丢步：分页边界连按时每次从 pending 目标继续累加，
  同一在途请求返回后一次落到最终位置，不会重复请求。
- 打开的封面在真实序列中已不存在（被删除/移出分组）时，丢弃加载期位移并按最近位置回退，
  不显示空序号；首屏在途时关闭再打开不同分组，旧请求代号已失效，迟到响应不会写入新分组。

### 14.3 分组命名去重（2026-11-05）

- 根因在自动命名来源：`candidate_topic` 优先取条目标题，而图片条目标题由引擎自动生成

### 14.7 截图组动态变更后的图片身份恢复（2026-11-06 Round 4）

- 预览期间优先维护**当前图片身份**而不是旧序号：revision 变化后第一页直接命中则保持
  同一图片（位置可变）；未命中走新增的轻量接口 `clipboard_group_item_position`
  （组内图片序位 + `image_count`/`total_count`/`revision`，两条有界 SQL，不加载整组）
  按图片 ID 找回新序位，再按需补页到该序位所在页（最多 10 页缩略图元数据）。
- 明确的降级路径，任何情况都不静默换图：图片已删除/移出本组 → 按旧序号 clamp 到
  新总数内选相邻图片并提示；组已删除（NotFound）→ 提示并退出组内预览；图片新序位
  超出预载范围 → 提示新序位（如「已移动到第 101 张」）并回到组首。
- 定位返回的 revision 与第一页不一致时整体重试一次，仍不一致按「未找到」降级；
  每次 await 后做代际检查，旧请求一律不写 state，翻页与刷新并发由同一代际守卫互斥，
  不产生请求风暴。分页仍只拼同一 revision 的页；重复条目按 id 去重。
- 下层组视图经 `onReplace(items, total, revision)` 同步新前缀，返回组视图后缩略图与
  当前 revision 一致；组从列表快照消失时先用不走缓存的定位接口确认删除再退出
  （分页缓存此时可能仍命中旧摘要）。
- 回归：`ClipboardLite.test.tsx` A5 新增前插保持身份、前删保持身份、跨页按 ID 找回、
  组删除退出、移出本组相邻回退、连续两次 revision、超出预载范围回到组首等 7 例；
  真机（通道 C，隔离实例）验证了前插保持同一图片 src、删除当前图片相邻回退提示。
