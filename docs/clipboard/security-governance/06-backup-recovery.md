# 06 · 备份与恢复方案

| 项目 | 内容 |
|---|---|
| 状态 | 方案设计（待审核授权后实施） |
| 日期 | 2026-11-23 |
| 范围 | 加密备份 bundle、备份密钥保护、跨设备恢复、旧明文备份兼容、恢复前校验与资产还原 |
| 边界 | 备份不自动上传；恢复材料只交用户保管；不云端托管 |

## 1. 现状回顾

- 备份：`commands/backup.rs` 流式 JSONL bundle，header + rows 分块 + 归档/资产 base64 分块 + SHA-256 完整性行；剪贴板表与图片资产纳入 `EXTENDED_TABLES` / `StagedAsset`。
- 恢复：`commands/restore.rs` 校验完整性/结构/引用 → 自动备份当前数据 → 单事务替换库 → staging 资产落回各目录；`restore/journal.json` 支持中断恢复。
- 现状 bundle 内正文与图片均为明文；`clipboard_enabled` / `clipboard_paused` 属本机隐私偏好，恢复不写回。

## 2. 备份加密结构

### 2.1 密钥分离

| 密钥 | 用途 | 保护方式 | 生命周期 |
|---|---|---|---|
| 本机 CEK | 加密本机库字段与资产 | DPAPI 当前用户作用域封装（ADR-0012） | 本机轮换时更新信封 |
| 备份 BEK | 加密备份包内记录与资产密文 | 双 slot：① DPAPI slot（本机快速备份可解）；② 恢复 slot（恢复口令 Argon2id 派生 或 离线恢复密钥包，见 §4 未决项） | 每次备份可复用同一 BEK，也可按备份周期轮换；轮换需重新封装 |

> BEK 不复用 CEK：备份包要脱离本机/本用户存活，不能依赖本机 DPAPI 上下文；CEK 也不随备份导出。

### 2.2 Bundle 格式演进（向后兼容）

新增加密标记与头部字段（具体编码实施定稿）：

- `format`: 保留 `taskdock-bundle` 主标识，`manifest_version` 递增；新增 `encryption: { scheme, version, kdf?, wrap?, nonce_b64?, salt_b64? }`。
- 明文旧包：`encryption = null`，按现有读取路径处理。
- 加密包：
  - 记录行：字段密文（GCM 输出 + nonce + AAD 含 bundle_id/条目 UUID）。
  - 资产块：图片密文块（base64），非原始 PNG。
  - 完整性校验：对密文载荷做 SHA-256；校验通过后才在内存解密，不先落明文临时文件。
  - 头部不携带 BEK 明文；DPAPI slot 仅在本机可解，恢复 slot 材料由用户提供。

### 2.3 备份范围与裁剪

- 延续现有：完整备份全量；快速备份按收藏/置顶 + 最近 N 条裁剪（`QUICK_CLIPBOARD_ITEM_LIMIT` 等）。
- 裁剪规则不变；加密后裁剪在密文行/资产引用层面进行，不解密正文。
- 本机瞬时状态（同步游标、配对设备、手机文件记录等）继续不进备份；剪贴板采集/加密开关与导出清理策略按 `LOCAL_PRIVACY_SETTINGS` 规则处理，恢复不写回。

## 3. 恢复流程（加密包）

### 3.1 恢复前校验（沿用并加强）

1. 读取 bundle 头部：格式版本、加密标记、载荷 SHA-256、行数/资产计数。
2. 完整性校验：缺行/截断/篡改拒绝；结构与外键引用预检。
3. 环境检查：目标数据目录可写、磁盘空间充足、无其他实例占用。
4. **自动备份当前数据**：恢复前先把现有库与资产做一次可读备份（现有行为保留），失败则中止恢复。

### 3.2 密钥解锁

- 本机 DPAPI slot 可解（同机同用户）：直接解出 BEK。
- 跨设备/换用户：要求用户提供恢复口令或恢复密钥包；Argon2id 参数（m_cost/t_cost/p_cost/salt）记录在头部；派生 KEK 解封装 BEK。
- 解锁失败（口令错误/材料缺失/篡改）：fail-closed，不部分导入、不降级明文；错误提示不回显密钥材料。

### 3.3 导入与资产还原

1. staging：密文行写入临时 JSONL；资产密文块落 staging（不明文落地）。
2. 内存解密后写入影子库/影子资产目录；条目 UUID 保留，关联关系按现有外键顺序恢复。
3. 资产按 `safe_asset_rel` 校验后落回 `clipboard/images`、`clipboard/thumbs`；预览缓存由读取时重生成，不从旧包恢复缓存文件。
4. 单事务替换数据库；资产计划先校验后落盘；journal 记录阶段，支持中断续跑。
5. 恢复后采集状态保持本机当前选择，不被旧备份的 `enabled/paused` 覆盖。

### 3.4 旧明文备份导入（已实现，批次 10）

- `bundle_meta` 对 `clipboard_sealed=false` 且头部计数存在剪贴板行的旧包返回
  `clipboard_migration_required=true`；恢复确认框提示原备份只读、恢复时先读出再按本机 CEK 重加密。
- 走与 §3.2–3.3 相同的影子库路径：明文/旧机 CEK 读出 → 用本机 CEK 加密写入；不把明文行直接写进加密库。
  本机 `clipboard_encrypt_history` 关闭时保持原样，并在恢复结果中明确告警「仍为明文」。
- 旧包内资产明文读出后加密落盘；staging 不明文长期留存。跨机旧包缺少原机 CEK 时 fail-closed，
  提示重新生成可移植备份。
- 旧包文件本身不改写，继续只读兼容；迁移条数/资产数只作为恢复告警返回，不记录正文。

## 4. 跨设备恢复材料（二选一或组合，实施定稿）

| 方式 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| 恢复口令 | Argon2id 派生 KEK 封装 BEK；用户记忆 | 无需保管文件；跨设备通用 | 弱口令风险；遗忘不可恢复；每次恢复输口令 |
| 离线恢复密钥包 | 随机恢复密钥直接封装 BEK；导出为加密/受保护文件交用户保存 | 强随机，不依赖口令强度 | 用户需保管文件；丢失即不可恢复 |

建议基线：**首次启用加密时生成恢复密钥包并提示离线保存；同时可选设置恢复口令作为第二 slot**。恢复材料展示一次/受控导出，应用不记录其明文。

## 5. 备份加密与静态加密的边界

| 场景 | 依赖 |
|---|---|
| 离线拷贝本机库/目录 | 本机 CEK + DPAPI（跨用户不可解） |
| 拷贝备份 bundle 到别处 | BEK + 恢复口令/恢复密钥（DPAPI slot 在新机器不可解） |
| 本机备份被同用户进程读取 | 同用户边界内不设防（威胁模型外） |
| 备份包丢失/网盘泄露 | 无恢复材料不可解；算法与参数在头部公开，安全依赖密钥 |

## 6. 审计与可见性

- 备份/恢复事件记录：类型（quick/full/restore）、格式版本、是否加密、条目数/资产数、时间、结果；**不记录正文、图片、路径正文、密钥材料**。
- 设置页展示：最近备份时间、备份格式（加密/旧明文）、恢复材料是否已生成；不展示密钥信封内部字段。
- 恢复失败给出可操作原因（完整性损坏、密钥材料错误、空间不足、外键引用缺失），技术细节入诊断日志。

## 7. 未决项

1. 恢复 slot 采用口令、密钥包还是双 slot；Argon2id 参数取值（参考保险箱现有参数但独立命名空间）。
2. BEK 是否每次备份轮换；轮换对恢复材料与旧包可读的影响。
3. 备份包是否允许用户选择「不加密（仅本机）」——建议不提供新的明文导出选项，旧包只读兼容。
4. 跨设备恢复时图片资产是否纳入默认备份范围，还是仅文本/元数据（与容量策略联动）。
