# 05 · 明文 → 密文迁移方案

| 项目 | 内容 |
|---|---|
| 状态 | 已实施（clipboard_items 与资产；粘贴作业文本列仍待复核） |
| 日期 | 2026-11-23 |
| 约束 | 兼容已有明文历史；原子性、可恢复、不覆盖原始数据直到验证完成；中断可继续或回滚；哨兵确认无明文残留；明确 WAL checkpoint 与旧文件策略；未备份验证不删旧数据 |
| 红线 | 遵循 ADR-0004：只在 `MIGRATIONS` 末尾追加迁移，不改已发布迁移；不动主键/外键/关联语义 |

## 1. 迁移范围

### 1.1 数据库

- 表：`clipboard_items` 的 `text`、`html`、`preview`、`title`、`source_app`、`source_title`、
  `file_paths`（批次 6 起全部纳入；空字符串保持为空，非空且无 `tdcl1:` 前缀即视为待迁移）。
- `clipboard_paste_jobs` / `clipboard_paste_items` 中可能含文本的列先逐列复核，纳入或显式排除并记录理由。
- 不迁移：分组、组内顺序、任务链接、快照链接、计数、收藏置顶、时间戳、哈希、尺寸、`source_kind`/`title_source` 枚举。

### 1.2 文件资产

- `clipboard/images/<id>.png`（原图）
- `clipboard/thumbs/<id>.png`（缩略图）
- `clipboard/thumbs/<id>-preview-640.png`（预览缓存）
- 排除：`clipboard-exports/` 历史导出包（属用户另存产物，不自动回填加密；按导出清理策略处理）；外部文件路径不复制本体。

### 1.3 信封与元数据

- 新增剪贴板密钥信封（表或小文件）：格式版本、算法、DPAPI 封装 CEK、entropy 标识、创建时间、CEK 版本。
- 每条密文记录携带：格式版本、nonce、密文（base64）；AAD 含记录 UUID 与类型。
- 每个加密资产文件头：版本、nonce、密文长度；原 `.png` 文件名布局可保留，内容改为密文容器。

## 2. 前置条件（迁移前必须满足）

1. **自动备份**：先对当前库与剪贴板目录做一次完整可读备份 bundle（明文格式），校验 SHA-256 与完整性标记；备份落盘成功且通过读取校验后，才允许进入迁移。
2. **状态快照**：记录迁移前 `user_version`、条目数、资产行数、分组数、组内关系数、任务链接数、快照链接数、粘贴作业/项数、各资产文件字节合计。
3. **环境检查**：数据目录可写；磁盘剩余空间 ≥ 迁移中间副本所需（库 + 资产临时副本，按现有占用预估余量）；无其他实例占用库（dev 实例纪律，独立数据目录）。
4. **密钥材料就绪**：OsRng 生成 CEK；DPAPI 封装成功并可在同进程内解出一次往返验证；信封落盘。
5. **回滚材料就位**：原始库文件与资产目录在观察期内保留，路径与清单写入迁移日志。

## 3. 迁移阶段（状态机）

```
PENDING → BACKED_UP → ENCRYPTING → VERIFYING → SWITCHED → OBSERVING → CLEANED
                ↘ ROLLING_BACK ↘──────────────┘（任一失败）
```

### 3.1 PENDING

- 检测库版本与剪贴板数据格式版本：明文旧库 → 进入迁移；已是密文格式 → 跳过。
- 写迁移状态记录（幂等键），记录开始时间、前置快照计数。

### 3.2 BACKED_UP

- 生成明文完整备份 bundle 到备份目录；`read_bundle` 回读校验完整性与行数；失败中止，不碰原数据。
- 备份未通过验证：禁止后续阶段；界面/日志如实报告 `ENVIRONMENT BLOCKED` 或备份错误。

### 3.3 ENCRYPTING（可中断续跑）

采用「影子副本 + 逐批加密 + 清单对账」，不在原库上边读边改写正文：

1. 在数据目录内建迁移工作区（如 `clipboard-migrate/<session>/`），复制库与待加密资产；工作区隔离，不覆盖原文件。
2. 逐条批次（建议每批 500 条，与备份分块口径协调）：
   - 读取明文行 → 字段加密 → 写入影子库密文行；保留原 UUID、哈希、元数据、关联键。
   - 资产文件逐文件加密写入影子资产目录；记录 `(item_id, role, rel, sha256, size)` 清单。
   - 批次提交带进度断点（已处理 item_id 水位 + 批次号）；崩溃后重启从水位续跑，不重复加密已完成批次（幂等：同 CEK 重加密 nonce 不同，以影子库目标行是否存在为准）。
3. 文本与图片解耦：图片采集关闭期间留下的纯文本条目，只加密字段；缺失资产按现状缺图处理，不报错。

### 3.4 VERIFYING（切换前强制校验）

- **计数对账**：影子库条目数、资产行数、分组/关系/链接计数与前置快照一致。
- **往返抽样**：随机抽样（含最大条目、最早/最晚条目、图片条目、文件条目、HTML 条目）解密往返，比对正文/图片字节与明文快照一致。
- **关联完整性**：外键检查 `foreign_key_check` 为 0；任务链接、分组、快照链接指向存在。
- **哨兵扫描**（见 §5）：影子库、影子 WAL、影子资产目录不得出现已知明文哨兵与敏感模式；扫描不过不切换。
- **信封校验**：DPAPI 解封装成功；AAD 绑定正确；篡改一位密文必须 GCM 校验失败。

### 3.5 SWITCHED（原子切换）

- 数据库：影子库替换主库（沿用既有备份/替换的原子策略：临时文件 → 轮换旧文件 → 替换；失败回滚旧文件）。WAL/SHM 随切换重建，不复制旧 WAL 到新库。
- 资产目录：影子资产原子替换 `clipboard/images`、`clipboard/thumbs`；替换前旧目录改名进入观察期目录，不先删。
- 迁移状态记录置 `SWITCHED`；应用以密文格式打开；新采集直接写密文。

### 3.6 OBSERVING

- 观察期（建议随版本发布窗口，具体时长实施评审定）内保留原始明文备份与旧资产目录副本；期间出现解密/关联问题可整体回滚。
- 观察期内不自动清理旧副本；清理动作单独受 §6 策略控制。

### 3.7 CLEANED

- 确认无回滚需求后，按策略清理观察期旧副本与迁移工作区；清理清单写入日志（路径、字节、时间）。
- 未到清理条件或用户未确认：旧副本保留，不计为清理成功。

## 4. 中断与回滚

| 中断点 | 恢复行为 |
|---|---|
| BACKED_UP 前/中 | 原库未改动；重新进入迁移即可 |
| ENCRYPTING 中崩溃 | 影子工作区保留；重启按水位续跑；原库仍是明文可正常使用 |
| VERIFYING 失败 | 不切换；保留影子与现场；报告失败批次/校验项；修正后重跑该阶段 |
| SWITCHING 替换失败 | 沿用 `commit_file` 式轮换回滚：旧库/旧目录恢复原位；错误如实上报 |
| SWITCHED 后发现问题 | 用迁移前备份 bundle + 旧资产目录回滚；回滚后库格式回到明文；回滚操作记录审计 |
| DPAPI 解封装在目标环境失败 | fail-closed：不降级写明文；界面提示密钥/环境问题，保留备份走恢复流程 |

回滚禁止事项：不 `git clean`/`reset --hard` 式清理用户数据；不删除迁移前备份直到观察期结束；回滚需可追溯（时间、版本、计数、错误码）。

## 5. 明文哨兵扫描策略

### 5.1 哨兵准备

- 迁移前在样本条目（测试夹具/隔离库）中写入固定哨兵字符串（如 `TDCLIP-SENTINEL-<随机段>`），随真实数据一起进入迁移流程。
- 扫描器覆盖：主库文件、`-wal`、`-shm`、影子库、资产目录、预览缓存、staging 目录、导出目录（只读检查并报告）。

### 5.2 扫描规则

1. **哨兵直查**：明文哨兵字符串不得出现在密文库与密文资产中（base64/压缩后亦不可见原文片段）。
2. **敏感模式抽样**：对高置信模式（PEM 头、`AKIA`、`ghp_`、`xox`、`Authorization: Bearer` 等）在迁移前快照中命中的样本，迁移后在密文形态中不得以原文出现。
3. **文件熵/头校验**：资产文件不再是合法 PNG 头（加密容器头）；密文列不再是可读 UTF-8 正文（抽样断言）。
4. **WAL 专项**：切换后对主库执行 checkpoint 策略（见 §7），再扫描 `-wal`；旧 WAL 不随新库保留。

### 5.3 扫描结论口径

- 扫描通过：哨兵 + 样本模式 + 文件头校验全部满足。
- 扫描失败：列出命中类型与位置（不含正文回显），阻断切换/清理。
- 已知不覆盖：SSD 物理残留、内存转储、已另存的导出副本。

## 6. 旧数据与旧文件处理策略

| 对象 | 观察期前 | 观察期后 |
|---|---|---|
| 迁移前明文备份 bundle | 保留，作为回滚与换机恢复源 | 按既有备份保留天数策略处置；加密备份上线后新备份为密文格式 |
| 旧库文件（轮换副本） | 保留在观察期目录 | 确认无回滚后安全删除；删除前复核清单 |
| 旧资产目录副本 | 保留 | 同上；删除计数与释放字节入账 |
| 迁移工作区/影子库 | 保留用于续跑与排查 | 清理；中途崩溃残留由下次启动扫描识别 |
| 旧格式导出包 `clipboard-exports/` | 不自动加密、不自动删除 | 按导出清理策略提示用户；孤立包可手动清理 |
| WAL/SHM | 切换时不复制旧 WAL；新库重建 | 按常规 checkpoint 维护 |

**未完成备份验证前，禁止删除任何旧数据。**

## 7. WAL / SHM 处置

- 迁移期间：影子库独立连接，WAL 留在迁移工作区；不向生产库写半套密文。
- 切换时：生产库关闭旧连接 → 原子替换主库文件 → 新连接在新库上重建 WAL/SHM；旧 `-wal`/`-shm` 随旧库副本进入观察期目录，不并入新库。
- 加密上线后日常策略（实施阶段定稿）：
  - 保留默认 `wal_autocheckpoint`；在清空历史、批量淘汰、迁移切换等大批量删除后执行一次 `TRUNCATE`（或 `PASSIVE` + 复测）checkpoint，降低旧明文页滞留。
  - SHM 不作为机密存储对象，但删除/迁移时随库一并处置，不单独拷贝。
- 不关闭 WAL 模式（读写并发与既有诊断依赖）。

## 8. 兼容与契约

- 旧明文库在未完成迁移前：读取路径兼容明文格式版本；迁移完成后读取路径按密文格式解包。格式版本号在信封/记录头显式记录，避免新旧格式误判。
- 备份 bundle 格式版本位升级：读取旧明文 bundle 走导入迁移路径；新 bundle 为加密格式（见 06）。
- 关联表与 UUID 不变；工作篮/任务引用不因加密断裂。
- 非 Windows 编译桩：加密路径同样降级，不伪装可用。

## 9. 迁移失败的典型场景与处置（测试对齐）

| 场景 | 预期 |
|---|---|
| 备份校验失败 | 中止，原库明文不动 |
| 批次中途断电/杀进程 | 续跑成功；计数对账一致 |
| 某资产文件损坏/缺图 | 按现状缺图记录，不阻塞其余条目 |
| 信封 DPAPI 封装失败 | fail-closed，不写半套密文 |
| 抽样往返不一致 | 阻断切换，保留现场 |
| 哨兵在 WAL 命中 | 阻断切换/清理，触发 checkpoint 后重扫 |
| 回滚到明文 | 备份可读、关联恢复、历史不丢 |
