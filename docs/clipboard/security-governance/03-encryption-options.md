# 03 · 加密方案对比与选型

| 项目 | 内容 |
|---|---|
| 状态 | 第一阶段方案对比（待主 Agent 审核授权后实施） |
| 日期 | 2026-11-23 |
| 范围 | 剪贴板静态数据加密、密钥保护、备份加密、迁移与恢复 |
| 硬约束 | 不得复用保险箱 DEK；区分静态加密 / 密钥保护 / 备份加密 / 迁移 / 恢复；兼容已有明文历史 |

## 1. 分层定义（先厘清，避免把三件事混为一谈）

| 层 | 职责 | 本方案对应物 |
|---|---|---|
| 静态数据加密（DEK 层） | 加密库内敏感字段与图片资产文件；每条记录/每个文件独立 nonce，AAD 绑定记录身份 | 剪贴板专用 **CEK**（内容加密密钥，32B）+ AES-256-GCM（复用 `secure_vault/crypto/aead.rs` 同原语） |
| 密钥保护（KEK 层） | 保护 CEK 不落明文；绑定本机/本用户 | 候选 A：DPAPI 当前用户作用域封装；候选 B：Windows Credential Manager；候选 C：独立主口令 KDF |
| 备份加密 | 保护导出 bundle（正文 + 图片 base64）；与本机 KEK 解耦，支持换机/恢复 | 备份专用 **BEK**；由恢复口令 Argon2 派生或由独立恢复密钥封装；与 CEK 信封分离 |
| 数据迁移 | 明文旧库 → 密文新库，原子、可回滚、可续跑 | 见 `05-migration-plan.md` |
| 数据恢复 | 换机/重装后解包；区分本机恢复与跨设备恢复 | 见 `06-backup-recovery.md` |

> 与保险箱的隔离：保险箱有自己的主口令/恢复口令/DEK 信封体系（`secure_vault/`）。剪贴板 CEK、KEK 封装、AAD info 字符串、entropy 全部独立命名空间；**不读取、不导出、不复用保险箱 DEK/KEK**。两套体系可以共用 AEAD/KDF 原语代码，但密钥材料与信封严格分离。

## 2. 候选方案

### 方案 A：Windows DPAPI 保护随机数据加密密钥（推荐基线）

结构：

1. 生成随机 32B CEK（OsRng），不落明文。
2. `CryptProtectData`（当前用户作用域，**不传** `CRYPTPROTECT_LOCAL_MACHINE`，`CRYPTPROTECT_UI_FORBIDDEN`，应用固定 entropy）把 CEK 封装为密文，落库/落小信封文件。
3. 运行时 `CryptUnprotectData` 解出 CEK 到 `Zeroizing<[u8;32]>`，用于字段/文件加解密；进程退出即清零。
4. 跨设备恢复另走备份加密层（BEK + 恢复口令/恢复包），不依赖 DPAPI 密文迁移。

参考实现：`personal_hub/crypto/dpapi.rs`（当前用户作用域、entropy 隔离、失败 fail-closed、输出 `LocalFree`）；新剪贴板模块复制其模式但使用独立 entropy 与错误类型，不共用常量。

优点：

- 无用户口令负担：解锁本机即解密，与剪贴板「后台静默历史」产品形态匹配。
- 绑定当前 Windows 用户：同机其他用户 DPAPI 不可解（密码学边界，不只是目录 ACL）。
- 系统级密钥管理，应用不自行保管主秘密；`UI_FORBIDDEN` 后台不弹对话框。
- 现有代码已有同模式封装与测试，原语（aes-gcm/zeroize/sha2/base64/argon2）依赖齐备。

缺点 / 风险：

- DPAPI 密文不可跨用户、跨机器直接迁移；换机必须靠备份加密层。
- 用户密码重置（非「更改密码」而是还原/重置凭据）、用户配置文件损坏时 DPAPI 主密钥可能不可解 → CEK 丢失。
- 同用户下被攻陷的进程可调用 DPAPI 解出 CEK（不防运行时同用户恶意进程，与威胁模型一致）。
- 强绑定 Windows；非 Windows 仅编译桩（现状剪贴板本就降级）。

### 方案 B：Windows Credential Manager 保存密钥

结构：CEK 作为凭据条目写入「Windows 凭据管理器」（`CredWrite`/`CredRead`，target name 带应用命名空间），库内只存条目定位信息。

优点：

- 凭据与数据文件分离；用户可在系统面板看到/删除条目。
- 同样绑定当前用户；不暴露明文密钥文件。

缺点 / 风险：

- Credential Manager 条目可被同用户进程枚举/读取（同用户边界内无额外壁垒），相对 DPAPI 没有安全增益。
- 条目迁移、漫游、备份策略不可控；系统升级/清理工具可能删除条目，导致 CEK 丢失且无信封可复核。
- `windows-sys`/`windows` 凭据 API 封装与错误处理成本高于 DPAPI；现有代码无先例。
- 调试/取证时条目与库文件分离，排障链路更长。

### 方案 C：独立主口令加密（口令派生 KEK）

结构：用户设置剪贴板主口令；Argon2id 派生 KEK，封装 CEK；口令不存本机。

优点：

- 不依赖 Windows 用户态；跨设备/换机可凭口令恢复（配合备份层）。
- 静态边界最强：离线拷库在无口令时不可解；可与保险箱口令体系独立。

缺点 / 风险：

- 改变产品形态：每次启动/解锁需输入口令，与现有「静默采集历史」冲突；需额外锁屏/超时锁定会话设计。
- 口令遗忘 = 数据不可恢复（除非另发恢复密钥）；口令爆破/弱口令风险需 KDF 参数与失败计数兜底。
- 入口、改口令、口令提示、失败锁定、内存清零等一整套 UI/会话状态，工作量显著高于 A。
- 与保险箱主口令是两套秘密，用户负担叠加。

## 3. 对比矩阵

| 维度 | A. DPAPI 封装随机 CEK | B. Credential Manager | C. 独立主口令 |
|---|---|---|---|
| 静态离线加密 | 是 | 是 | 是 |
| 同机跨用户不可解 | 是（DPAPI 用户作用域） | 是（用户作用域） | 是（口令未知） |
| 同用户恶意进程防护 | 否（模型外） | 否 | 部分（运行时仍需解到内存） |
| 跨机器迁移 | 否，需备份层 | 否，需备份层 | 可凭口令 + 备份层 |
| 用户额外负担 | 无 | 无 | 每次解锁输口令 |
| 密钥丢失风险 | DPAPI 主密钥损坏/密码重置 | 凭据条目被清理/漫游丢失 | 口令遗忘 |
| 实现成本（基于现有代码） | 低（有 dpapi.rs 先例） | 中高（新 API 封装） | 高（会话/UI/口令管理） |
| 与现有产品形态契合 | 高 | 中 | 低 |
| 可演进性 | 可后续叠加口令二次加密 | 一般 | — |

## 4. 推荐选型

**基线采用方案 A：DPAPI（当前用户作用域）封装随机剪贴板 CEK；备份层独立 BEK，提供可选的跨设备恢复口令/恢复包。**

理由：

1. 剪贴板历史是后台静默采集的便利性功能，方案 C 的口令门槛会显著改变产品形态，且与保险箱口令体系叠加负担；本期目标是补齐静态加密兜底，不是再造一个口令保险箱。
2. DPAPI 提供「跨用户不可解」的密码学边界，弥补现状只靠目录 ACL 的缺口；现有 `dpapi.rs` 模式与测试可复用经验。
3. 备份/换机场景由独立备份加密层解决，不把跨设备需求压给本机 KEK。
4. 保留演进路径：未来若需要「二次口令锁定剪贴板」，可在 CEK 外再套一层口令 KEK 封装（A 的信封结构可扩展为多 slot：dpapi slot + optional passphrase slot），不推翻本期结构。

### 4.1 推荐结构（概念，实施时落 ADR 细化）

```
[本机]
  CEK (32B, 随机, 仅受保护内存)
    ├─ DPAPI slot: CryptProtectData(CEK, entropy="TaskDock.Clipboard.CEK.v1", user scope)
    │     → 落库 envelope 表 / 信封文件（密文 + nonce 元数据 + 版本）
    └─ 可选 passphrase slot（本期不实现，预留版本位）

  记录加密: AES-256-GCM(CEK, nonce=12B 随机, AAD="tdclip|item|<id>|v1")
    敏感字段: text / html / preview / title(若含正文派生) / file_paths(按策略)
  资产加密: AES-256-GCM(CEK, nonce, AAD="tdclip|asset|<item_id>|<role>|v1")
    原图 / 缩略图 / 预览缓存；密文落文件，头记录 nonce/长度/版本

[备份]
  BEK (32B, 随机)
    ├─ 本机封装 slot: DPAPI(BEK)（仅本机快速备份可解）
    └─ 恢复 slot: Argon2id(恢复口令) 封装 BEK，或离线恢复密钥包
  bundle 内: 记录密文 + 资产密文块；头部标注 format/version/加密算法/KDF 参数
```

### 4.2 字段加密策略（建议，实施前复核）

| 数据 | 建议 | 备注 |
|---|---|---|
| `text` / `html` / `preview` | 加密 | 核心敏感正文 |
| `title` | 加密（自动生成标题）；手动编辑标题按同策略 | 避免标题泄露正文片段 |
| `file_paths` | 加密 | 路径含隐私；保留可检索性需求需另行评估（本期不做密文检索） |
| `source_app` / `source_title` | 加密（隐私元数据）；`source_kind` 明文枚举 | 窗口标题常含隐私 |
| `content_hash` | 明文保留（去重/索引依赖） | 接受哈希可离线比对的残余风险 |
| 尺寸/时间/计数/收藏置顶/分组/关联 | 明文 | 非内容；关联 UUID 不动 |
| 图片原图/缩略图/预览缓存 | 文件级加密 | 派生图同样保护 |

### 4.3 明确不做（本期边界）

- 不做密文全文检索：搜索在解密后的内存/结果集上进行，或本期保留有限明文索引（需在实施评审中定）。
- 不复用保险箱 DEK/KEK/会话；不把剪贴板密钥写进保险箱记录。
- 不引入云端密钥管理、远程擦除、多端实时同步加密。
- 不在本期实现图像内容识别/敏感截图分类。
