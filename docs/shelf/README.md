# 文件暂存架（File Shelf）

> v0.8 新增模块。用户**主动**收纳临时资料的空间：文件、图片、截图、文档、文件夹、
> 网页链接与文本片段；支持查看、整理、多选、删除、过期清理与任务关联。
> 模块代码：`src-tauri/src/shelf/`（逻辑）+ `src-tauri/src/commands/shelf.rs`（命令）
> + `src/components/shelf/`（UI）+ `src/store/useShelfStore.ts`。

## 1. 与智能剪贴板的职责边界（强制）

| | 智能剪贴板 | 文件暂存架 |
|---|---|---|
| 数据来源 | 被动记录用户复制历史 | 用户主动添加/整理/清理 |
| 生命周期 | 受采集开关、保留期、条数与容量配额约束 | 独立；只受用户操作与（可选的）过期清理约束 |
| 资产存储 | `data_dir/clipboard/{images,thumbs}` | `data_dir/shelf/{files,images,thumbs}` |
| 删除语义 | 删条目会清理其拥有的资产文件 | 引用模式绝不触碰原文件；托管模式只删 Task Dock 拥有的副本 |

**资源所有权**：暂存架**不共享** `clipboard_assets`。该表的删除按路径反查引用、
没有跨模块引用计数，直接共享必须改动剪贴板清理策略（跨模块风险不可接受）。
因此「从剪贴板添加」把字节**复制**为暂存架独立副本：

- 剪贴板历史被清空 → 暂存架中的截图仍可访问；
- 删除暂存条目 → 只删暂存架自己的副本，剪贴板条目与其资产不受影响；
- 剪贴板的清理/清空/孤儿扫描逻辑（`clipboard/store.rs`）**零改动**。

## 2. 两种存储模式

### 引用模式（reference，默认）

- 只保存规范化后的原文件路径（词法消解 `.`/`..`，拒绝穿越），不复制文件；
- 适合：本地文档、大型文件、项目目录、文件夹（文件夹**仅支持**引用模式）；
- 原文件被移动/删除后条目失效：进入页面时批量核对存在性，失效条目带
  「失效」徽标并在详情页明确提示；打开/定位前再次校验；
- 删除暂存记录不删除原文件，也不统计释放字节。

### 托管副本模式（managed）

- 流式复制到 `data_dir/shelf/{files|images}/<uuid>.<ext>`，缩略图在
  `thumbs/<uuid>.png`（PNG 源生成；非 PNG 暂不出缩略图，避免引入图像解码依赖）；
- 适合：截图、剪贴板图片、需要短期保留、用户显式勾选「保存副本」的文件；
- 复制采用 `.part` 临时文件 + 校验长度 + 原子改名：中断只留 `.part`（启动与
  清理时回收），绝不把半份文件当完整资源；并发复制上限 4（RAII 闸）；
- 配额：`shelf_max_storage_mb`（默认 2048，范围 64..102400）；复制前还要求
  磁盘剩余 ≥ 文件大小 + 128MB；单文件上限 2GB（超过请用引用模式）；
- Task Dock 拥有副本：删除条目时删除副本与缩略图（canonical 路径复核在
  shelf 根目录内），原文件永不触碰。

默认策略：拖入/文件选择器/**引用**模式（不偷偷复制占用磁盘）；UI 提供明确
的「保存副本」开关；从剪贴板添加的图片一律托管复制（必须落副本才有独立生命周期）。

## 3. 数据模型（v22 迁移）

- `shelf_groups`：分组；三个内置分组（默认暂存/工作资料/图片截图）随迁移种子化；
  删除分组时条目归位默认分组，不删条目；
- `shelf_items`：`kind(file|folder|image|link|text)`、`storage_mode(reference|
  managed|link)`、`original_path`、`managed_path`（相对 shelf 根，仅
  `files|images|thumbs` 前缀）、`content`（link=URL ≤2048；text=正文 ≤512KB）、
  `byte_size`、`file_ext`、`favorite/pinned`、`exists_state(ok|missing|unknown)`、
  `group_id`、`scene_id`（场景工作区软关联预留，接口稳定前恒 NULL）、`expire_at`；
- `shelf_task_links`：`(task_id, item_id)` 复合主键（天然防重复关联），双向
  `ON DELETE CASCADE` —— 删除任务只级联删关联行，暂存资源保留；解除关联随时可用；
- 备份登记：三表均在 `BACKUP_TABLES`（class=shelf，快速/完整都全量）与
  `EXTENDED_TABLES`（依赖序：groups → items → task_links）。

## 4. 过期清理

- **自动清理默认关闭**（`shelf_auto_cleanup_enabled`）；启用后每 1 小时检查一次，
  每次运行前重读设置（设置不可读则跳过本轮，fail-closed）；
- 过期判定：显式 `expire_at` 优先；未设置时按 `created_at + shelf_retention_days`
  （默认 30 天，范围 1..3650）；
- **收藏/置顶永不被自动清理**，也不计入候选；用户显式勾选包含保护项时才可清；
- 清理分三类动作：删暂存记录 / 删托管副本与缩略图 / **绝不删用户原文件**（第三类
  由架构禁止）；
- 文件删除失败只计数（`failed_files`）不谎报成功；数据库行已删的残留由孤儿扫描
  （`purge_orphan_files`，清理时执行）兜底回收；报告含 deleted/skipped/freed/orphans；
- 手动清理前可「预览可清理」（dry_run 返回候选数、受保护跳过数、预计释放字节）；
- 批量执行、1 小时粒度，无高频后台扫描。

## 5. 备份与恢复

- 三张 shelf 表中的 `shelf_items`、`shelf_groups`、`shelf_recent_dirs` 走通用扩展
  模块通道（`EXTENDED_TABLES` + `BACKUP_TABLES`）；
- **`shelf_file_ops` 不进入跨设备备份**：它只保存本机未完成文件操作的绝对路径，
  属于设备本地瞬时恢复日志。备份写入空 section（保持 schema 完整），恢复时忽略
  旧备份中的该表行并清空本机旧日志，避免恢复后凭他机路径执行移动/删除或改写引用。
- **托管副本全部打包**（快速与完整备份都含，条目元数据不截断）：避免恢复出
  「有记录无文件」的失效托管条目；占用受配额约束不会无限膨胀。缩略图是可再生
  装饰：存在才打包，缺失不阻断备份；
- bundle 内托管文件使用独立命名空间 `shelf/<files|images|thumbs>/<name>`，
  `safe_asset_rel` 同时校验剪贴板（`images|thumbs/*.png`）与 shelf 两个命名空间；
- 恢复：`build_plan` 按 `shelf/` 前缀路由到 shelf 根目录，沿用「留底 vault →
  逐文件原子提交 → 失败整体回滚」状态机；读取端校验每个 shelf 资产都被
  `shelf_items` 引用（managed_path 或确定性缩略图），大小与 `byte_size` 一致；
- 引用模式条目**不打包用户原文件**（只存路径）；恢复后原路径失效时 UI 如实
  显示 missing 状态；
- 快速备份的 partial_reasons 明确声明「暂存架条目与托管副本全量包含」。

## 6. 文件拖放：实现与限制

### 拖入（已实现，待真机验收）

- 监听 Tauri Webview 级 `onDragDropEvent`（`ShelfWorkspace.tsx`）：真实 OS 文件
  拖入，非 HTML5 dragstart 模拟；仅在暂存架页签激活时订阅，随卸载释放
  （subscription scope 引用计数）；
- enter/over 显示高亮遮罩（文案随「保存副本」开关切换）；drop 批量调用
  `shelf_add_paths`（≤500/批），逐条失败原因以 Toast 展示（中文/空格/Unicode
  路径由后端规范化处理，不经过前端拼接）；
- **验收状态**：无头会话无法产生真实 OS 拖拽 → ENVIRONMENT BLOCKED，待真机
  复验（证据见 `tmp/acceptance/file-shelf/report.md`）。

### 拖出（第一版未实现，如实标记）

- 结论：Tauri 2.12.5 / WebView2 没有可靠的「从 webview 内容向资源管理器发起
  OS 文件拖出」通道；原生实现需要 OLE `IDataObject` + `DoDragDrop` 独立线程
  （COM 初始化、鼠标捕获与 WebView2 拖放处理器的冲突、线程与资源生命周期），
  属后续专项；
- 提供替代（全部走受控链路）：
  - **复制路径**（文本，换行分隔）；
  - **复制文件**（CF_HDROP —— 资源管理器 Ctrl+V 即得文件本体）；
  - **打开 / 所在文件夹**（explorer /select）；
- 前端不存在任何会被误认为拖出的 dragstart 实现。

## 7. 安全边界

- **路径**：托管文件名由后端生成（uuid），前端字符串不进入路径成分；
  `safe_managed_rel` 白名单校验；删除前 canonical 复核在 shelf 根内
  （防符号链接/重解析点逃逸）；引用路径词法规范化 + 穿越拒绝；
- **打开/定位**：复用 `navigation::validate_local_path` / `validate_url`（仅
  http/https、拒绝控制字符），链接 URL 取库内正文，不信任前端回传；
- **预览**：文本 ≤512KB 截断；HTML 文件经前端白名单净化只读渲染（复用
  HtmlReader，不发资源请求）；未知格式只展示元数据，不自动执行；
- **剪贴板写入**：复制路径/复制文件走 `write_payload_notifying`（自写登记，
  不回流为剪贴板记录，不与逐项粘贴互相覆盖）；
- **磁盘**：配额 + 128MB 余量预检 + 流式分块复制（不整读进内存）+ `.part`
  原子提交；设置键全部进入 `ALLOWED_KEYS` 白名单并逐键校验。

## 8. 用户操作说明

- 入口：完整模式左侧导航「暂存架」（收集箱之后、历史之前，Ctrl+6）；
- 添加：「添加」按钮（文件选择器，可多选）▾ → 添加文件夹 / 网页链接 / 文本
  片段 / 从剪贴板添加；或直接把文件拖进窗口；「保存副本」开关决定拖入与
  剪贴板添加是否复制；
- 查看：点击卡片名进详情（图片灯箱、文本/HTML 只读预览、链接、元数据、任务
  关联、备注）；缩略图懒加载；
- 整理：搜索（名称/内容/备注）、类型/分组/收藏筛选、收藏 ★、置顶、多选
  （移动分组/收藏/删除/复制文件）、自定义分组（内置分组不可删）；
- 文件操作（v34）：卡片/详情右键「移动文件到…」「复制到…」「导出副本到…」，
  多选后可批量移动/复制；文件操作面板内选最近目录、固定目录或浏览其他目录，
  并选择同名冲突策略（跳过 / 自动重命名）；
- 清理：工具栏 ⚙ → 空间占用、自动清理开关与过期天数、预览可清理、立即清理；
  回收站式清空按钮保留收藏/置顶；
- 失效处理：失效徽标 → 详情页提示；引用条目点「重新定位…」选择新路径即可
  更新引用（保留分组、收藏、置顶、备注与任务关联）；托管条目丢失不得指向外部
  文件，需通过备份恢复或删除记录后重新添加。

## 9. 已知限制

- 非 PNG 图片暂无缩略图（不为此引入图像解码依赖），显示类型图标，原图可灯箱打开；
- 文件夹仅引用模式（不递归复制目录内容）；
- 系统级拖出未实现（见 §6）；
- 与场景工作区的 `scene_id` 联动为预留字段，等场景接口稳定后接入；
- 存在性探测对失效网络路径可能阻塞数秒（在异步命令线程执行，不阻塞 UI）；
- 文件移动/复制的第一版同名策略只有「跳过」与「自动重命名」，不支持覆盖；
  跨卷移动依赖复制 + 逐字节校验，超大文件夹耗时随体积增长且不可断点续传；
  跨盘、网络目录、文件占用、权限不足、磁盘写满等真实环境场景见 §11 的验收说明。

## 10. 统一入口「收集与暂存」（v0.8 后期整合）

「收集箱」与「暂存架」在侧边栏合并为单一视觉入口**收集与暂存**，页面内双子页签
**快速收集 | 文件暂存**（容器 `src/components/collection/CollectionPanel.tsx`）。

- **职责区别不变**：快速收集 = 快速捕获的落地箱（想法/文字/待办/任务/链接，处理导向）；
  文件暂存 = 用户主动收纳的临时资料（文件/图片/文件夹/链接/文本，资料管理导向）。
  两套 Store（useCaptureStore / useShelfStore）与后端存储完全独立，未合并任何表。
- **交互规则**：点击合并入口打开「上一次的子页」（`useUiStore.collectionSub`，默认
  快速收集）；`setTab("inbox" | "shelf")` 幂等同步子页状态，因此 Ctrl+5=快速收集、
  Ctrl+6=文件暂存、旧调用方语义全部不变。同一时刻只挂载一个子页，切换即卸载，
  Store 状态保留，不重复拉取全量。
- **快捷键兼容**：TAB_ORDER 保持逻辑 Tab 序列不变（新增 Tab 由其所属模块追加），
  合并只发生在 FullView 的视觉渲染层（RAIL_ENTRIES 折叠），其余快捷键不偏移。
- **跨模块转存**：
  - 收集箱 → 暂存架：text/idea 条目 → 暂存文本，link 条目 → 暂存链接（走
    useShelfStore 既有 addText/addLink）；任务/待办保留「转为任务」，不默认入库暂存架。
    成功 Toast 附「查看」直达文件暂存子页；**原收集条目默认保留**，失败不改变状态；
    逐条 busy 在途守卫防连点重复创建。
  - 暂存架 → 收集箱：text/link 条目菜单「添加到收集箱」，复用快速捕获既有
    `quick_capture_submit`（client_id 幂等去重）。注意：列表载荷不含 content
    （大文本不进前端内存），转存前先经 `shelf_get_item` 取全量权威行。
- **原始数据保留**：转存是复制不是移动——两个方向的原始条目都保留，不删除、不改状态。
- **资源所有权不变**：不触碰剪贴板资产所有权、文件托管语义与清理策略；
  徽标口径：合并入口徽标只显示「待处理收集内容」数（收集箱），暂存条目不计入。

## 11. 文件移动、复制与失效重定位（v34）

命令：`shelf_move_items` / `shelf_copy_to` / `shelf_relocate_item` / `shelf_recent_dirs*`；
后端实现 `src-tauri/src/shelf/fsops.rs`；前端面板 `src/components/shelf/ShelfFileOpPanel.tsx`。

### 11.1 语义与模式边界

| 操作 | reference（文件/图片/文件夹） | managed（托管副本） | link / text |
|---|---|---|---|
| 移动原文件到… | 允许：移动真实文件/文件夹并更新 `original_path` | **不允许** | 不显示 |
| 导出副本到… | — | 允许：复制托管副本到用户目录，保留 `managed_path` | — |
| 复制到… | 允许：保留原文件与暂存记录 | 允许（同「导出副本」） | 不显示 |
| 重新定位… | 失效时允许 | **拒绝**：只能通过备份恢复或删除记录 | 不显示 |

- 移动/复制一律由后端按条目 ID 从数据库读取权威路径，前端传入的源路径不参与
  文件操作；link/text 没有文件语义，后端直接拒绝。
- 移动成功后只更新路径与存在状态，**条目 ID、收藏、置顶、分组、备注、任务关联
  全部保留**；不会用「删旧建新」模拟移动。
- 同一原文件被多条记录引用、或父目录/子目录条目同时引用被移动路径时，按
  大小写不敏感的路径前缀同步改写所有匹配的 `original_path`。
- 托管副本不参与移动；「导出副本到…」成功后托管副本与配额统计不变，不产生
  新的暂存记录；复制同样不会把目标文件重新加入暂存架。

### 11.2 同名冲突与文件系统安全

- 默认「跳过」：目标已存在同名项时该条目标记为 skipped，不覆盖任何文件；
  「自动重命名」生成 `名称 (1).ext`（文件夹为 `名称 (1)`），最多尝试 999 次。
- 源与目标同一目录：移动标记 skipped（不重复移动）；文件夹移入自身或子目录
  直接拒绝（canonical 路径比较，防递归）。
- **同卷移动不再使用会覆盖的 `rename`（2026-11-05）**：改为不带 REPLACE 标志的
  `MoveFileExW`（非 Windows 走存在性检查 + rename）。即使目标在检查后被并发创建，
  也返回冲突并保持源/目标原样，绝不静默覆盖。
- **移动源与暂存架根重叠时拒绝（2026-11-05）**：`src == root`、源是 root 的祖先或
  位于 root 内部都会在磁盘操作前失败，避免把 `data_dir` / 托管资产目录搬走后导致
  `managed_path` 全部失效。
- 同卷优先原子改名；跨卷降级为「流式复制到唯一临时副本
  `.原名.<uuid>.shelf-part` → 完整性校验 → 原子建立目标 → 删除源」。完整性校验
  同时覆盖目录结构（含空目录）、文件集合、文件大小和逐文件流式内容比对；复制或
  校验期间源文件集合/大小/时间戳变化即判失败，**绝不删除源文件**。
- **源清理失败绝不删除目标**：源可能已被部分删除，目标可能是唯一完整副本。此时
  保留目标、把暂存引用切到目标并返回 `partial`（附 `residual_source` 与
  `recovery` 建议），不递归清理不确定状态的残留源；不再用 `src.exists()` 推断
  源完整性。
- 复制或校验失败、日志关键阶段写失败时都不删除源；日志阶段失败会保留源与已校验
  目标（`partial`），交由启动恢复收敛。
- 复制到自身或自身子目录（canonical 祖先比较）直接拒绝；目标检查与最终建立之间
  重新确认不存在，文件优先用同目录硬链接提交，避免 `rename` 静默覆盖同名文件。
- 符号链接、联接点及其他重解析点直接拒绝（Windows 按 `FILE_ATTRIBUTE_REPARSE_POINT`
  判定，不只看 `is_symlink`）；目录递归复制有深度上限并用 canonical 已访问集合
  防循环；临时副本名含 uuid，绝不预先删除目标目录中的同名用户文件。
- 每次磁盘操作前写入 `shelf_file_ops` 日志（intent/copied/moved），磁盘移动与
  SQLite 引用更新非原子；启动时 `recover_pending_file_ops`（幂等、可重复执行）
  按「日志阶段 + 文件系统现状」收敛，而不是只凭目标存在判成功：
  - copy / 未完成的跨卷临时副本：源仍存在时只清理带本次 uuid 的 `.shelf-part`；
  - 目标存在、源不存在：补写引用后清日志；
  - 源与目标都存在：保留两者，仅把引用切到已校验目标，并记录源残留；
  - 源与目标都不存在：保留日志作为异常诊断，不判成功、不清理文件；
  - 日志条目对应记录已删除或路径已指向无关位置时直接丢弃日志，不操作文件；
  - 恢复失败只记录并按启动节奏重试，不做高频循环；清日志只在安全终态之后。

### 11.3 最近目录

- 表 `shelf_recent_dirs`（路径主键、`pinned`、`last_used_at`），最多 8 项；
  按固定优先、最近成功使用倒序排列；重复路径自动去重。
- 仅在打开文件操作面板或执行时读取并探测 `available`，**启动阶段不扫描目录**，
  不新增后台服务；不可用目录在面板中明确标注。
- 支持固定/取消固定/移除/清空；全部 8 项被固定时新增目录会提示先取消固定。
- 只有操作至少成功一条后才更新最近使用时间；失败不影响排序。

### 11.4 批量与完成后处理

- 复用现有卡片多选；批量移动/复制共用一套面板与冲突策略，结果逐条返回
  `ok/skipped/failed/partial` 及原因，失败与部分完成条目保留在暂存架。
- 批量内父目录与子项同时被选中时，按物理路径（大小写不敏感）先处理父目录，子项
  标记 skipped 并保留记录；父目录移动会同步改写子记录引用。同一物理路径对应多条
  记录时只处理第一条，其余 skipped；并发批次占用同一路径会被拒绝。
- `partial` 表示文件已完整复制并校验到目标、但源清理或暂存路径更新未完成；附
  `residual_source`（残留源路径）与 `recovery`（建议动作），不参与「从暂存架移除」。
- 完成后可选「保留在暂存架」（默认）或「从暂存架移除」；只移除完全成功的记录：
  - reference 移动：删除暂存记录不影响已移动的目标文件；
  - managed 导出：移除记录会连同托管副本删除，面板明确提示，需用户显式勾选；
  - 失败/跳过/部分完成条目永不因「移除」选项被删除。
- 批量报告区分三类结果：`failed`（文件操作失败）、`record_cleanup_failed`
  （文件成功但移除记录失败，记录保留可重试）、`remove_failed_files`（记录已移除
  但托管文件清理失败，由下次清理兜底）；记录清理失败不会把已成功的文件操作报成
  全部失败。
- 2026-11-05 起文件操作面板完整消费 `partial` / `record_cleanup_failed`：汇总显示
  部分完成数量，逐项展示残留源与恢复建议；只要存在部分完成或记录清理失败，就保持
  面板打开并给出 warning，不再把「成功 0 项」当成完全成功关闭。
- 「移动文件到…」作用于磁盘上的原文件；「移动到分组」只改暂存架分组，二者在
  菜单中分组呈现，文案与图标明确区分。

### 11.5 验收状态与已知限制

- 已用隔离目录 `tmp/` 覆盖：单文件/文件夹移动、跨卷（测试模式强制降级）内容校验
  失败、源复制期间变化、源部分删除、关键日志阶段失败、数据库更新失败、异常退出
  恢复（源+目标/仅目标/两者均无）、空目录与嵌套/Unicode 名称、批量部分失败、
  同名跳过/重命名、复制到自身与子目录、目标竞争不覆盖、父子目录同批、同路径多
  记录、托管导出、删除记录不影响外部原文件、备份与操作日志隔离、最近目录
  去重/固定/上限、失效重定位类型校验。
- **UNVERIFIED**：真实跨物理磁盘（单测用测试钩子强制跨卷分支）、网络共享目录、
  文件被其他进程占用、权限不足、磁盘写满、应用在移动/清理过程中被强杀（恢复
  用例为构造日志现场）、符号链接/联接点的真实创建（部分 Windows 环境需特权）
  等场景，需真机复验；现有单测只证明逻辑分支与临时目录行为，不代表上述环境已通过。
- 第一版不支持断点续传、覆盖同名文件、跨设备原子移动；文件夹复制会完整遍历
  目录并逐文件比对内容（有深度与循环保护，不装载全部内容进内存，但耗时随体积
  与文件数增长）。

### 11.6 结果模型契约（IPC，v34 定稿）

`shelf_move_items` / `shelf_copy_to` 返回同一个 `ShelfOpReport`。字段只增不减，
新增字段均为可选或默认值，旧前端忽略即可；命令参数与语义未变。

`ShelfOpReport`：

| 字段 | 类型 | 可选性 | 语义 |
|---|---|---|---|
| `success` | `number` | 必有 | 文件操作完全成功（`ok`）的条数 |
| `skipped` | `number` | 必有 | 主动跳过（同名冲突、源目标同目录、父目录已处理、重复物理路径）的条数 |
| `failed` | `number` | 必有 | 文件操作失败条数（未产生完整目标） |
| `partial` | `number` | 必有，默认 0 | 目标已完整校验但源清理/记录更新未完成的条数 |
| `removed` | `number` | 必有 | 按「从暂存架移除」实际移除的记录数 |
| `remove_failed_files` | `number` | 必有，默认 0 | 记录已移除但托管文件清理失败条数（下次清理兜底），仅计数、无逐项明细 |
| `record_cleanup_failed` | `number` | 必有，默认 0 | 文件操作成功但移除暂存记录失败条数（记录保留可重试） |
| `record_cleanup_error` | `string \| null` | **可选**，`undefined` 表示无清理失败 | 记录清理失败原因摘要（多条时取首条） |
| `entries` | `ShelfOpEntry[]` | 必有（保留字段名） | 逐项结果，顺序与请求 `ids` 一致；不存在的 ID 也占一项 `failed` |

`ShelfOpEntry`：

| 字段 | 类型 | 可选性 | 语义 |
|---|---|---|---|
| `id` | `string` | 必有 | 暂存条目 ID |
| `display_name` | `string` | 必有 | 展示名（可能为空字符串） |
| `source` | `string \| null` | 必有 | 实际操作的源路径；解析失败时为 `null` |
| `target` | `string \| null` | 必有 | 目标路径；未建立目标时为 `null` |
| `status` | `"ok" \| "skipped" \| "failed" \| "partial"` | 必有 | 仅这 4 个稳定取值，不新增枚举 |
| `reason` | `string \| null` | 必有 | 用户可读原因；`status != "ok"` 时保证非空且稳定；`ok` 时通常为 `null`，仅在「源清理报错但源已消失」时附说明文本 |
| `recovery` | `string` | **可选**，`undefined` | 部分完成时的建议动作 |
| `residual_source` | `string` | **可选**，`undefined` | 部分完成时仍残留的源路径 |

- `entries` 与 `remove_failed_files` 保持原名，前端改为可选读取是兼容的，但后端始终
  返回这两个字段。
- 失败分类只看 `status`：前端展示 `reason` 即可；跨条目汇总用 `failed` /
  `partial` / `record_cleanup_failed` / `remove_failed_files` 四个计数区分，不新增总体
  `overallStatus` 字段。需要「是否部分完成」时以 `partial > 0` 判断。
- `status == "partial"` 的条目目标副本一定已完整校验，且不会被「移除记录」选项删除。

## 12. 收集箱文件投递（v35，v36 整合最近暂存与视图分离）

工具面板（胶囊）的「收集箱」拆成两个子页：**快速收集 | 文件**。文件子页让用户把
资源管理器里的文件/文件夹直接拖到一张目标卡片上，**落到真实磁盘目录**；下方同时提供
最近暂存条目，不必跳完整面板就能打开/复制。它与完整面板共享同一份目标配置与暂存架数据，
不新建文件管理系统，也不因投递往暂存架写记录。

### 12.1 与相邻概念的边界（不要合并）

| | 文件投递目标 | `shelf_recent_dirs` | `shelf_groups` |
|---|---|---|---|
| 来源 | 用户显式配置 | 文件操作成功后自动记录 | 用户手动创建 |
| 主键 | `id`（uuid） | `path` | `id` |
| 别名 | 有（显示名称） | 无（显示目录名） | 有 |
| 排序 | 有（`sort_order`，上下移动） | 固定优先 + 最近使用 | 有 |
| 工具面板 | 可勾选是否显示 | 不显示 | 不显示 |
| 上限 | 24 | 8 | 无硬上限 |

三者共享同一套**路径校验**（`normalize_target_dir`：绝对路径、必须存在的目录、
不得指向暂存架内部），但存储与语义独立，互不覆盖。

### 12.2 数据模型（迁移 v35）

`db::MIGRATIONS` 追加 v35：`shelf_drop_targets`

| 列 | 说明 |
|---|---|
| `id` | uuid 主键 |
| `name` | 显示名称（≤40 字符，留空回退为目录名） |
| `path` | 真实目录，`COLLATE NOCASE` 唯一（Windows 路径大小写不敏感） |
| `sort_order` | 显示顺序，新增取 `max+1`，上下移动交换相邻两项 |
| `show_in_capsule` | 是否出现在工具面板 |
| `op_mode` | `copy`（默认）/ `move` |
| `conflict` | `rename`（默认）/ `skip` |
| `created_at` / `updated_at` | 审计时间 |

- 表在 `BACKUP_TABLES`（class=shelf，快速/完整均全量）与 `EXTENDED_TABLES` 登记；
  旧备份缺该段时按「缺表即跳过」恢复，不影响可用性，只是没有目标配置。
- 迁移只**新增空表**，不导入任何示例路径；首个目标必须由用户自己选择目录。

### 12.3 语义

- **默认复制**：保留源文件与目录结构（含空目录），成功后**不**创建暂存记录
  （避免同一份文件在暂存架里再出现一次）。需要移动必须由用户在目标上显式选择。
- **移动模式**：完全复用 `fsops` 的移动实现——同卷 `rename` 原子改名；跨卷
  「流式复制 → 逐文件内容校验 → 原子建立目标 → 删除源」；目标未完整校验前绝不删除源；
  源清理失败返回 `partial` 并保留目标（可能是唯一完整副本）。
- **同名冲突**：默认 `rename`（`名称 (1).ext`，最多 999 次），可选 `skip`；
  **不存在覆盖策略**，绝不静默覆盖用户已有文件。复制/移动的**最终提交**不依赖
  「先检查再改名」：文件优先用硬链接建立目标（已存在必然失败），硬链接不可用或目录
  走 `MoveFileExW`（不带 `REPLACE_EXISTING`）；提交阶段出现同名一律报冲突并回收临时副本。
- **并发占用（源 + 目标）**：占用同时覆盖**源路径**、**目标目录**与**最终目标路径**，
  并按读写语义分层，避免「源路径不同但目标互相踩踏」：
  - `Exclusive`：会改变该路径及其子树的操作（移动源、最终写入目标）；
  - `Shared`：只要求路径保持原位、可并行的操作（复制时读取源、向同一目录写入）。
  - 冲突规则：Exclusive×Exclusive 相等或互为祖先/后代即冲突；Exclusive 是 Shared
    的祖先或同路径即冲突（搬走父目录会毁掉正在写入的子目录）；Shared×Shared 从不冲突。
  - 效果：两个批次向同一目录复制**不同**文件可并行；同一最终目标互斥（后到者拿到可重试
    冲突）；目标目录被移动/删除期间，写入方整批拒绝；移动父目录与写入其子目录互斥。
  - 占用按规范化分量比较（大小写不敏感、解析重解析点/8.3 短名）；成功、失败、提前返回
    都由 `Drop` 释放；每次占用带 owner，释放只删自己的登记。
- **提交前再验证**：复制在最终提交前重新确认目标父目录仍是目录（外部删除/重挂载时给出
  可读原因）；移动在改名/复制前同样检查。真正的无覆盖仍由系统级原子提交保证。
- **文件夹**：保持层级、保留空目录、拒绝重解析点（符号链接/联接点）、拒绝把目录放进
  自身或子目录；单文件失败不阻断同批其他条目。
- **目标解析**：前端只提交 `target_id` 与路径列表，后端按 id 从库里取权威目录；
  目录在投递时再做一次 `is_dir` 确认，不可用直接拒绝（fail-closed），不写入任何文件。
- **批次**：单批 ≤200 项；同批次重复路径先去重；父目录与子项同时拖入时只处理父目录，
  子项标记 `skipped`。源类型在磁盘操作**之前**记录：移动后源路径已不存在也不会把子项
  误判为失败。父目录只完成一部分时，子项标记 `partial` 并附残留源与人工处理建议，
  不冒充成功、也不重复执行文件操作。
- **崩溃恢复**：磁盘操作前写 `shelf_file_ops`，`item_id` 用 `drop:<batch>` 前缀与条目
  操作区分；启动恢复对投递批次只清理**本次创建的** `.shelf-part` 临时副本，不改写任何
  引用、不删除源或用户目标文件。
- **最近目录联动**：批次至少成功一条后，目标目录也会出现在文件操作面板的「最近目录」里。

### 12.4 命令（IPC）

| 命令 | 说明 |
|---|---|
| `shelf_drop_targets_list` | 列表；读取时逐个探测 `available`（`is_dir`），无后台扫描 |
| `shelf_drop_target_create` | 添加（名称/路径/模式/冲突策略/是否显示） |
| `shelf_drop_target_update` | 局部更新；改路径会重新校验存在性与去重 |

| `shelf_drop_target_move` | `up`/`down` 相邻移动；重复/不连续 `sort_order` 按位置规范化为 `0..n-1`（单事务，只写真正变化的行） |
| `shelf_drop_target_open` | 在资源管理器中打开（不存在时明确报错） |

`DropReport`：`batch_id / target_id / target_path / op / total / success / skipped /
failed / partial / entries[]`；`entries[]` 每项含 `source / display_name / target? /
status / reason? / recovery? / residual_source?`。状态取值与 `ShelfOpEntry` 一致。

### 12.5 拖放通道与所有权

`src/lib/fileDrop.ts` 是**唯一**的 `onDragDropEvent` 订阅者：

- 按需订阅：第一个消费者注册时建立，最后一个注销时立即 `unlisten`（不常驻）；
- 一次拖入在 `enter` 时只选一个消费者（自己 `claim()` 为真且优先级最高），
  会话期间不换人；`leave` / `drop` 结束会话；
- 无人认领时丢弃事件——不执行任何文件操作；命中不到卡片同样不投递（fail-closed）；
- `leave` 之后的 `drop` 不投递：松手时不再临时仲裁（「找不到会话就不猜消费者」）；
- 坐标链路（按 `Cargo.lock` 实际解析的 tauri 2.12.5 / wry 0.57.1 源码核实）：Windows OLE 传入屏幕坐标 →
  wry `ScreenToClient` → **Windows 客户端区物理像素**（相对 webview 左上角）→
  Tauri 包装为 `PhysicalPosition<f64>`。前端除以 `devicePixelRatio` 得到 CSS 像素，
  再 `document.elementFromPoint(...).closest('[data-drop-target]')` 命中卡片，
  因此 DPI 缩放与多显示器共用同一套逻辑；高亮层必须 `pointer-events: none`；
- 落点以**松手瞬间的坐标重新命中**：不复用可能过期的 `over` 高亮缓存；
  坐标缺失时传 `null`，卡片不可见/已删除/视图已切换时同样不投递（绝不回到默认目录）。

消费者优先级：胶囊投递卡片 `20` > 暂存架 `10`。暂存架在胶囊停靠期主动退出
（`dock-app` 处于 inert，不能抢拖入事件），避免文件被悄悄塞进暂存架。

### 12.6 UI 入口

- **工具面板**：收集箱 →「文件」子页。目标网格按容器宽度自适应：单个目标占满整行，
  两个目标分两列，3/5… 个时最后一张占满整行（不留孤立的半幅卡片）；卡片固定为
  「文件夹图标 + 名称 → 路径摘要 → 复制/移动状态」三层，失效目标用红色「目录不可用」
  文字徽标表达（不只靠透明度）。卡片右上「更多」菜单收纳编辑/上移/下移/移除入口，
  移除需二次确认；点击卡片主体打开真实目录，拖放文件到卡片执行投递。拖入时只高亮命中
  的那张，菜单在拖入开始时重置，避免弹层挡住落点。
  结果条内联展示「成功 · 跳过 · 部分完成 · 失败」四类计数，展开后逐条给出状态标签、
  原因、可能残留的源路径与人工处理建议；目标被移除后结果仍保留（显示目标路径，
  不再提供打开入口）。上次使用的子页记在 `localStorage`
  （`taskdock.capsule.inbox.sub.v1`，纯 UI 偏好）。
- **最近暂存（工具面板）**：文件子页下方显示最近 4 条暂存条目（名称/类型/存储方式/
  原文件是否可用），支持点击打开、更多菜单（在暂存架中查看/复制文件/复制路径）与
  「+」直接添加文件（默认引用，不复制）。数据来自 `useShelfStore.loadRecent` 的同一条
  `shelf_list` 轻量查询，不建第二套缓存、不扫描目录；跳转完整暂存架复用全局搜索的
  `pendingLocate` 一次性定位通道。
- **完整面板**：文件暂存架与「投递目标管理」是互斥的内容视图（`targetsOpen`），
  不新增左侧导航 Tab，Ctrl+5 / Ctrl+6 语义不变。进入目标管理后暂存架工具栏、搜索、
  类型/分组筛选、空态与批量操作全部不渲染，暂存架拖放消费者同时释放（该视图只负责
  目录配置，拖入不归它管）；返回时恢复原搜索/筛选条件并尽量恢复列表滚动位置。
  目标管理视图的结构为「返回暂存架 → 标题与目标数量 → 添加目标文件夹 → 重新检查目录 →
  目标列表 → 说明」；每行展示文件夹图标、名称、路径摘要、模式/同名策略、可用状态与
  管理操作。添加表单在列表上方展开，编辑表单**就地替换该行**，只提交名称/目录/模式/策略，
  id、排序与可见性保持原值；有未保存表单时返回暂存架先弹确认，不静默丢弃输入。
  完整面板与工具面板共用同一份表单组件（`components/shelf/DropTargetForm.tsx`），
  胶囊表单控件统一为 30px 高（`--input-height-sm`），同名策略折叠在「高级选项」里
  但摘要常显；胶囊底栏按状态切换：列表态「添加目标/管理」，表单态只有「保存/取消」，
  不再出现表单内与底栏两套主操作。胶囊里的「管理」会切到该视图。
- **暂存架空状态**：区分「暂存架真空」（显示添加文件/文件夹与拖入提示，隐藏没有对象的
  类型/分组/收藏筛选）、「当前筛选无结果」（保留筛选，提示没有匹配并给「清除筛选」）、
  「首次/刷新加载中」与「读取失败」（错误空态 + 重试），不把加载或失败画成空暂存架。
- 定位：拖入与操作中都不自动收起——展开态胶囊本来就是「用户主动关闭」，
  不因短暂失去 hover 收起，也不为此修改全局收起策略。

### 12.7 性能与资源

- 目录可用性只在打开面板/强制刷新时探测，不轮询、不在启动阶段扫描；结果缓存
  `AVAILABILITY_TTL_MS = 30s`，过期后由面板打开时后台重探一次（不阻塞首屏）；
- 「看起来不可用」时投递前强制重探一次（外接盘重连后无需重启应用）；手动刷新无视 TTL；
- 并发 `load` 去重、慢响应按请求代次丢弃；写操作（新增/编辑/删除/排序）成功后提升
  **写代次**，早于写操作的列表快照一律丢弃（不会回滚刚完成的配置），必要时最多重试一次，
  不产生请求风暴，也不引入轮询；
- 路径占用只在文件操作期间持有，按路径粒度判定，不做全局大锁，无关目录并行不受影响；
- 目标配置由 `useDropTargetsStore` 缓存，工具面板与完整面板共用，切页不重复拉取；
- 最近暂存只取 `shelf_list(limit=4)`，不加载完整历史；5s 软缓存 + 在途去重，
  子页来回切换不重复 IPC；文件子页关闭后没有订阅/定时器残留；
- 完整面板视图切换只条件渲染，不重新加载列表；目标管理期间不注册拖放消费者，
  拖入事件直接留给胶囊（一次拖入仍只有一个消费者）；
- 投递在 Rust 的 `spawn_blocking` 线程执行，UI 线程不做文件 IO；
- 进度只展示真实条数（已知批次大小），不伪造百分比；界面卸载不中断底层操作，
  结果保存在 store 里，重开面板仍可查看；
- 拖入 `over` 事件只在卡片切换时触发一次重渲染。

### 12.8 已知限制与未验证

- **UNVERIFIED（真机）**：本机未执行「从 Windows 资源管理器真实拖入」的原生验收，
  目前只有 jsdom 下的分发/命中用例 + Rust 文件操作用例；真实 OS 拖放、125%/150%/200%
  DPI 下的物理坐标换算（公式与 wry 源码一致，实际数值仍需真机取样）、多显示器跨屏拖入、
  网络盘/外部磁盘断开时序需真机复验。
- v36 的最近暂存、视图分离、空态与表单布局有前端组件/store 用例；静态走查截图只证明
  排版，不证明真实拖拽、滚动或 DPI 表现，胶囊真实高度下的信息密度仍需真机复看。
- 不支持在投递过程中取消（不做「假取消」：关闭面板不会中断已提交的批次）；
- 不做断点续传；跨卷移动大文件夹耗时随体积增长；
- 目标目录必须是已存在的目录，不能提前配置一块暂时离线的网络盘（恢复供电/重连后
  由 TTL 重探或手动刷新恢复状态）；
- 非 Windows 平台的「不覆盖提交」只能先检查再改名（`std` 无 `RENAME_NOREPLACE`），
  当前交付目标 Windows 使用系统级无覆盖语义。
