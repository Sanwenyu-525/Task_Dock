# 文件暂存架（File Shelf）

> v0.8 新增模块。用户**主动**收纳临时资料的空间：文件、图片、截图、文档、文件夹、
> 网页链接与文本片段；支持查看、整理、多选、删除、过期清理与任务关联。
> 模块代码：`src-tauri/src/shelf/`（逻辑）+ `src-tauri/src/commands/shelf.rs`（命令）
> + `src/components/shelf/`（UI）+ `src/store/useShelfStore.ts`。

## 1. 与智能剪贴板的职责边界（强制）

| | 智能剪贴板 | 文件暂存架 |
|---|---|---|
| 数据来源 | 被动记录用户复制历史 | 用户主动添加/整理/清理 |
| 生命周期 | 受采集开关、保留期、条数与容量配额约束 | 独立；只受用户操作与（可选的）过期清理约束 |
| 资产存储 | `data_dir/clipboard/{images,thumbs}` | `data_dir/shelf/{files,images,thumbs}` |
| 删除语义 | 删条目会清理其拥有的资产文件 | 引用模式绝不触碰原文件；托管模式只删 Task Dock 拥有的副本 |

**资源所有权**：暂存架**不共享** `clipboard_assets`。该表的删除按路径反查引用、
没有跨模块引用计数，直接共享必须改动剪贴板清理策略（跨模块风险不可接受）。
因此「从剪贴板添加」把字节**复制**为暂存架独立副本：

- 剪贴板历史被清空 → 暂存架中的截图仍可访问；
- 删除暂存条目 → 只删暂存架自己的副本，剪贴板条目与其资产不受影响；
- 剪贴板的清理/清空/孤儿扫描逻辑（`clipboard/store.rs`）**零改动**。

## 2. 两种存储模式

### 引用模式（reference，默认）

- 只保存规范化后的原文件路径（词法消解 `.`/`..`，拒绝穿越），不复制文件；
- 适合：本地文档、大型文件、项目目录、文件夹（文件夹**仅支持**引用模式）；
- 原文件被移动/删除后条目失效：进入页面时批量核对存在性，失效条目带
  「失效」徽标并在详情页明确提示；打开/定位前再次校验；
- 删除暂存记录不删除原文件，也不统计释放字节。

### 托管副本模式（managed）

- 流式复制到 `data_dir/shelf/{files|images}/<uuid>.<ext>`，缩略图在
  `thumbs/<uuid>.png`（PNG 源生成；非 PNG 暂不出缩略图，避免引入图像解码依赖）；
- 适合：截图、剪贴板图片、需要短期保留、用户显式勾选「保存副本」的文件；
- 复制采用 `.part` 临时文件 + 校验长度 + 原子改名：中断只留 `.part`（启动与
  清理时回收），绝不把半份文件当完整资源；并发复制上限 4（RAII 闸）；
- 配额：`shelf_max_storage_mb`（默认 2048，范围 64..102400）；复制前还要求
  磁盘剩余 ≥ 文件大小 + 128MB；单文件上限 2GB（超过请用引用模式）；
- Task Dock 拥有副本：删除条目时删除副本与缩略图（canonical 路径复核在
  shelf 根目录内），原文件永不触碰。

默认策略：拖入/文件选择器/**引用**模式（不偷偷复制占用磁盘）；UI 提供明确
的「保存副本」开关；从剪贴板添加的图片一律托管复制（必须落副本才有独立生命周期）。

## 3. 数据模型（v22 迁移）

- `shelf_groups`：分组；三个内置分组（默认暂存/工作资料/图片截图）随迁移种子化；
  删除分组时条目归位默认分组，不删条目；
- `shelf_items`：`kind(file|folder|image|link|text)`、`storage_mode(reference|
  managed|link)`、`original_path`、`managed_path`（相对 shelf 根，仅
  `files|images|thumbs` 前缀）、`content`（link=URL ≤2048；text=正文 ≤512KB）、
  `byte_size`、`file_ext`、`favorite/pinned`、`exists_state(ok|missing|unknown)`、
  `group_id`、`scene_id`（场景软关联，无外键；一个条目同一时刻归属一个场景）、`expire_at`；
- `shelf_task_links`：`(task_id, item_id)` 复合主键（天然防重复关联），双向
  `ON DELETE CASCADE` —— 删除任务只级联删关联行，暂存资源保留；解除关联随时可用；
- 备份登记：三表均在 `BACKUP_TABLES`（class=shelf，快速/完整都全量）与
  `EXTENDED_TABLES`（依赖序：groups → items → task_links）。

## 4. 过期清理

- **自动清理默认关闭**（`shelf_auto_cleanup_enabled`）；启用后每 1 小时检查一次，
  每次运行前重读设置（设置不可读则跳过本轮，fail-closed）；
- 过期判定：显式 `expire_at` 优先；未设置时按 `created_at + shelf_retention_days`
  （默认 30 天，范围 1..3650）；
- **收藏、置顶与 `scene_id` 非空的条目不会被自动或手动过期清理**，也不计入候选；
  手动清理不提供「包含受保护条目」开关；只有详情页单条删除在明确确认后可一并删除
  受保护条目（场景会失去该文件引用，用户原文件仍不受影响）；
- 清理分三类动作：删暂存记录 / 删托管副本与缩略图 / **绝不删用户原文件**（第三类
  由架构禁止）；
- 文件删除失败只计数（`failed_files`）不谎报成功；孤儿扫描（`purge_orphan_files`）要求完整读取托管路径和图片引用，任一查询失败立即终止；每个删除候选在 writer transaction 中再次核验引用及文件身份。生产清理还与文件添加共享独占维护闸，避免文件先落盘、数据库后登记期间被误判为孤儿。报告字段为 `dry_run / candidates / skipped_protected / temporary_files_skipped / freed_bytes / failed_files / orphan_files_removed`；
- 手动「立即清理过期」先自动执行 dry-run 预览，再用统一确认框展示候选数、预计释放字节与受保护跳过数；确认后才调用真实清理，取消、Escape 或预览失败都不会删除任何内容；
- 真实清理成功后复用删除/清空的权威同步路径：刷新当前筛选列表、总统计、分组与最近暂存，保留已加载范围与滚动位置；同步失败只提示重试，不重复执行清理；
- 批量执行、1 小时粒度，无高频后台扫描。

### 删除与清空的数据状态同步（2026-11-06）

- `shelf_delete` / `shelf_clear` 返回的 `ShelfDeleteReport` 是写操作结果：`deleted` 表示
  已删除的数据库记录，`skipped` 表示因收藏、置顶或场景引用保护跳过的条目（同时命中多项仍只计
  1 项），`freed_bytes` 表示已删除的托管主文件字节数，`failed_files` 表示数据库记录删除后托管
  主文件或缩略图仍未能删除的文件数；文件残留不等于数据库删除失败。
- 批量删除在单个写事务内读取保护状态并删除，ID 按 500 项分批绑定且先去重；清空在同一写事务内
  按保护条件直接删除，不先读取 ID 列表。两条路径均不删除引用模式原文件；托管路径越界或文件清理
  失败会保留磁盘对象并计入 `failed_files`。
- 前端仅在后端写入成功后刷新当前已加载范围、总统计、分组统计和最近暂存。收藏、置顶与场景引用
  条目由权威列表保留，仍存在的选择与详情继续可用；缓存代次会丢弃写入前启动的最近列表响应。
- 若写入成功但刷新失败，保留原有列表并明确提示状态可能未同步，提供重试入口；提示按报告区分已删
  记录、受保护跳过项与托管文件/缩略图残留，不把部分结果显示成全部成功。

## 5. 备份与恢复

- 三张 shelf 表中的 `shelf_items`、`shelf_groups`、`shelf_recent_dirs` 走通用扩展
  模块通道（`EXTENDED_TABLES` + `BACKUP_TABLES`）；
- **`shelf_file_ops` 不进入跨设备备份**：它只保存本机未完成文件操作的绝对路径，
  属于设备本地瞬时恢复日志。备份写入空 section（保持 schema 完整），恢复时忽略
  旧备份中的该表行并清空本机旧日志，避免恢复后凭他机路径执行移动/删除或改写引用。
- **托管副本全部打包**（快速与完整备份都含，条目元数据不截断）：避免恢复出
  「有记录无文件」的失效托管条目；占用受配额约束不会无限膨胀。缩略图是可再生
  装饰：存在才打包，缺失不阻断备份；
- bundle 内托管文件使用独立命名空间 `shelf/<files|images|thumbs>/<name>`，
  `safe_asset_rel` 同时校验剪贴板（`images|thumbs/*.png`）与 shelf 两个命名空间；
- 恢复：`build_plan` 按 `shelf/` 前缀路由到 shelf 根目录，沿用「留底 vault →
  逐文件原子提交 → 失败整体回滚」状态机；读取端校验每个 shelf 资产都被
  `shelf_items` 引用（managed_path 或确定性缩略图），大小与 `byte_size` 一致；
- 引用模式条目**不打包用户原文件**（只存路径）；恢复后原路径失效时 UI 如实
  显示 missing 状态；
- 快速备份的 partial_reasons 明确声明「暂存架条目与托管副本全量包含」。

## 6. 文件拖放：实现与限制

### 拖入（已实现，待真机验收）

- 监听 Tauri Webview 级 `onDragDropEvent`（`ShelfWorkspace.tsx`）：真实 OS 文件
  拖入，非 HTML5 dragstart 模拟；仅在暂存架页签激活时订阅，随卸载释放
  （subscription scope 引用计数）；
- enter/over 显示高亮遮罩（文案随「保存副本」开关切换）；drop 批量调用
  `shelf_add_paths`（≤500/批），逐条失败原因以 Toast 展示（中文/空格/Unicode
  路径由后端规范化处理，不经过前端拼接）；
- **验收状态**：无头会话无法产生真实 OS 拖拽 → ENVIRONMENT BLOCKED，待真机
  复验（证据见 `tmp/acceptance/file-shelf/report.md`）。

### 添加结果分级与诊断（2026-11-12）

- `ShelfAddReport.failed[]` 在 `path` / `reason` 之外新增可选 `code` / `category`
  （来自 `AppError::code()` / `category()`）；`None` 时不序列化，旧前端兼容。
- `addPaths` 不再无条件写成功：全成功 `INFO/success`；部分失败
  `SHELF_ADD_PARTIAL_FAILED`、全部失败 `SHELF_ADD_FAILED`（错误码一致时复用真实码）、
  0 添加 0 失败 `SHELF_ADD_NO_INPUT`；级别按失败分类（integrity → CRITICAL，
  validation/not_found/unsupported/conflict → WARN，其余 ERROR）。
- 收尾刷新失败只追加 `SHELF_ADD_REFRESH_FAILED`（WARN，stage=finalize），不改变
  添加结果、不 reject；诊断 metadata 只含计数/模式/来源/失败码，不含路径或文件名。
- 业务失败事件约定与筛选路径见 `docs/DIAGNOSTICS.md` §22。
- **2026-11-13 更正**：拖入路径客户端预检（空白/相对路径）从 `ShelfWorkspace` 下沉到
  `useShelfStore.addPaths` 内部，预检失败与后端失败共用同一 `operation_id` 与同一份
  `{added, failed}` 返回值（预检失败在前）；全部输入无效 →
  `SHELF_ADD_ALL_INVALID`（WARN，stage=validate，不调后端）；metadata `total` 含无效项，
  `failure_codes` 可含 `empty_path` / `relative_path`。调用方不再预过滤路径。详见
  `docs/DIAGNOSTICS.md` §22a。

### 拖出（2026-11-09 已实现，真机待验收）

- 通道：前端按住卡片超过 5px 位移后调用 `shelf_drag_out`，命令层用
  `AppHandle::run_on_main_thread` 回到 Tauri 主线程（tao 已 `OleInitialize`），
  再执行 `OleInitialize` → 自实现 `IDataObject` → `DoDragDrop` → `OleUninitialize`。
  **不能在自建后台线程上跑**：OLE 拖拽循环依赖调用线程的输入队列接管鼠标捕获，
  后台线程拿不到 `DragEnter`，表现为拖了没反应。进入拖拽前还会检查
  `GetAsyncKeyState(VK_LBUTTON)`，左键已松开就跳过，避免合成/迟到调用把主线程
  永久挂在拖拽循环里。
  `QueryContinueDrag` 同样直接读全局左键状态，而不是 OLE 传入的 `grfKeyState`。
- 数据对象由 Rust 直接构造 `DROPFILES` 全局内存；不使用 shell
  `SHCreateDataObject`（本机实测返回空格式集，无法保证目标应用拿到文件）。
- 拖拽幽灵：数据对象接受 `IDragSourceHelper` 写入的 `DragImageBits`（HGLOBAL）与
  `DragContext`（TYMED_ISTREAM），`EnumFormatEtc(DATADIR_SET)` 返回空集；
  否则 helper 会因 `SetData` 的 `E_NOTIMPL` 整条失败，资源管理器不画跟随光标的
  文件幽灵。幽灵图取第一个文件的 Shell 缩略图/图标（96px）。
- 效果：引用模式允许 `DROPEFFECT_COPY | DROPEFFECT_MOVE`，遵循 Windows 默认
  （同卷移动、跨卷复制，Ctrl 强制复制）；托管副本一律只允许复制，避免把
  内部副本移出托管目录、弄坏暂存记录。
- 拖出范围：完整暂存架卡片与工具面板「收集箱 → 文件 → 最近暂存」行；link/text
  条目没有文件语义，不参与拖出。
- move 后源路径失效：后端返回 `effect=move` 与已不存在的路径，前端刷新
  `exists_state` 并明确提示「条目保留，可重新定位或删除」，不静默改记录。
- 回退通道：**复制路径**（文本，换行分隔）、**复制文件**（CF_HDROP，
  资源管理器 Ctrl+V 即得文件本体）、**打开 / 所在文件夹**（explorer /select）。
- 前端无 HTML5 `draggable`/`dragstart` 实现；拖拽后 350ms 内的 click 会被吞掉，
  避免误开详情。
- 本轮真机拖拽因会话锁屏（前台为锁屏界面）未能执行，见
  `tmp/acceptance/shelf-ui-drag/report.md` §7；幽灵数据通路由 Rust 单测
  `drag_source_helper_attaches_drag_image` 覆盖。

## 7. 安全边界

- **路径**：托管文件名由后端生成（uuid），前端字符串不进入路径成分；
  `safe_managed_rel` 白名单校验；删除前 canonical 复核在 shelf 根内
  （防符号链接/重解析点逃逸）；引用路径词法规范化 + 穿越拒绝；
- **打开/定位**：复用 `navigation::validate_local_path` / `validate_url`（仅
  http/https、拒绝控制字符），链接 URL 取库内正文，不信任前端回传；
- **预览**：文本 ≤512KB 截断；HTML 文件经前端白名单净化只读渲染（复用
  HtmlReader，不发资源请求）；未知格式只展示元数据，不自动执行；
- **剪贴板写入**：复制路径/复制文件走 `write_payload_notifying`（自写登记，
  不回流为剪贴板记录，不与逐项粘贴互相覆盖）；
- **磁盘**：配额 + 128MB 余量预检 + 流式分块复制（不整读进内存）+ `.part`
  原子提交；设置键全部进入 `ALLOWED_KEYS` 白名单并逐键校验。

## 8. 用户操作说明

- 入口：完整模式左侧导航「暂存架」（收集箱之后、历史之前，Ctrl+6）；
- 添加：单行工具条的「添加」按钮（文件选择器，可多选）＋ ▾ 菜单 → 添加文件夹 /
  网页链接 / 文本片段 / 从剪贴板添加；菜单底部用 radio 选择「引用原文件（不复制）」
  或「保存副本到托管目录」，该模式同时作用于拖入与剪贴板添加；或直接把文件拖进窗口；
- 查看：点击卡片名进详情（图片灯箱、文本/HTML 只读预览、链接、元数据、任务
  关联、备注）；缩略图懒加载；
- 整理：搜索（名称/内容/备注）常驻；类型、分组、只看收藏收进「筛选」浮层，
  激活时工具条下方显示可移除的条件摘要；收藏 ★、置顶、多选（移动分组/收藏/
  删除/复制文件）、自定义分组（内置分组不可删）；
- 拖出：按住卡片拖到资源管理器或其他窗口（引用文件按 Windows 默认复制/移动，
  托管副本只复制）；移动后原路径可能失效，按提示重新定位或删除；
- 文件操作（v34）：卡片/详情右键「移动文件到…」「复制到…」「导出副本到…」，
  多选后可从批量栏的「文件操作」菜单批量移动/复制；文件操作面板内选最近目录、
  固定目录或浏览其他目录，并选择同名冲突策略（跳过 / 自动重命名）；
- 清理：「⋯」→ 空间与清理 → 空间占用、自动清理开关与过期天数、预览可清理、
  立即清理（立即清理会先自动预览并二次确认）；同菜单的「清空暂存架」保留
  收藏、置顶与场景引用条目；
- 失效处理：失效徽标 → 详情页提示；引用条目点「重新定位…」选择新路径即可
  更新引用（保留分组、收藏、置顶、备注与任务关联）；托管条目丢失不得指向外部
  文件，需通过备份恢复或删除记录后重新添加。

## 9. 已知限制

- 非 PNG 图片暂无缩略图（不为此引入图像解码依赖），显示类型图标，原图可灯箱打开；
- 文件夹仅引用模式（不递归复制目录内容）；
- 系统级拖出的真机验收未执行（无头环境不可模拟物理拖拽，见 §6）；托管副本
  拖出只复制；UIPI/目标应用不接受文件时仍需用复制路径/复制文件回退；
- 场景工作区通过稳定 shelf ID 选择暂存文件/文件夹；Rust `scenario_get/save/delete` 读取与更新 `scene_id`，保存、所有权校验和解绑在立即事务内完成。路径失效时仍保留 ID；复制场景不转移关联；删除场景只解除关联，不删除暂存记录或真实文件。
- 存在性探测对失效网络路径可能阻塞数秒（在异步命令线程执行，不阻塞 UI）；
- 文件移动/复制的第一版同名策略只有「跳过」与「自动重命名」，不支持覆盖；
  跨卷移动依赖复制 + 逐字节校验，超大文件夹耗时随体积增长且不可断点续传；
  跨盘、网络目录、文件占用、权限不足、磁盘写满等真实环境场景见 §11 的验收说明。

## 10. 统一入口「收集与暂存」（v0.8 后期整合）

「收集箱」与「暂存架」在侧边栏合并为单一视觉入口**收集与暂存**，页面内双子页签
**快速收集 | 文件暂存**（容器 `src/components/collection/CollectionPanel.tsx`）。

- **职责区别不变**：快速收集 = 快速捕获的落地箱（想法/文字/待办/任务/链接，处理导向）；
  文件暂存 = 用户主动收纳的临时资料（文件/图片/文件夹/链接/文本，资料管理导向）。
  两套 Store（useCaptureStore / useShelfStore）与后端存储完全独立，未合并任何表。
- **交互规则**：点击合并入口打开「上一次的子页」（`useUiStore.collectionSub`，默认

  Ctrl+6=文件暂存、旧调用方语义全部不变。同一时刻只挂载一个子页，切换即卸载，
  Store 状态保留，不重复拉取全量。
- **快捷键兼容**：TAB_ORDER 保持逻辑 Tab 序列不变（新增 Tab 由其所属模块追加），
  合并只发生在 FullView 的视觉渲染层（RAIL_ENTRIES 折叠），其余快捷键不偏移。
- **跨模块转存**：
  - 收集箱 → 暂存架：text/idea 条目 → 暂存文本，link 条目 → 暂存链接（走
    useShelfStore 既有 addText/addLink）；任务/待办保留「转为任务」，不默认入库暂存架。
    成功 Toast 附「查看」直达文件暂存子页；**原收集条目默认保留**，失败不改变状态；
    逐条 busy 在途守卫防连点重复创建。
  - 暂存架 → 收集箱：text/link 条目菜单「添加到收集箱」，复用快速捕获既有
    `quick_capture_submit`（client_id 幂等去重）。注意：列表载荷不含 content
    （大文本不进前端内存），转存前先经 `shelf_get_item` 取全量权威行。
- **原始数据保留**：转存是复制不是移动——两个方向的原始条目都保留，不删除、不改状态。
- **资源所有权不变**：不触碰剪贴板资产所有权、文件托管语义与清理策略；
  徽标口径：合并入口徽标只显示「待处理收集内容」数（收集箱），暂存条目不计入。

## 11. 文件移动、复制与失效重定位（v34）

命令：`shelf_move_items` / `shelf_copy_to` / `shelf_relocate_item` / `shelf_recent_dirs*`；
后端实现 `src-tauri/src/shelf/fsops.rs`；前端面板 `src/components/shelf/ShelfFileOpPanel.tsx`。

### 11.1 语义与模式边界

| 操作 | reference（文件/图片/文件夹） | managed（托管副本） | link / text |
|---|---|---|---|
| 移动原文件到… | 允许：移动真实文件/文件夹并更新 `original_path` | **不允许** | 不显示 |
| 导出副本到… | — | 允许：复制托管副本到用户目录，保留 `managed_path` | — |
| 复制到… | 允许：保留原文件与暂存记录 | 允许（同「导出副本」） | 不显示 |
| 重新定位… | 失效时允许 | **拒绝**：只能通过备份恢复或删除记录 | 不显示 |

- 移动/复制一律由后端按条目 ID 从数据库读取权威路径，前端传入的源路径不参与
  文件操作；link/text 没有文件语义，后端直接拒绝。
- 移动成功后只更新路径与存在状态，**条目 ID、收藏、置顶、分组、备注、任务关联
  全部保留**；不会用「删旧建新」模拟移动。
- 同一原文件被多条记录引用、或父目录/子目录条目同时引用被移动路径时，按
  大小写不敏感的路径前缀同步改写所有匹配的 `original_path`。
- 托管副本不参与移动；「导出副本到…」成功后托管副本与配额统计不变，不产生
  新的暂存记录；复制同样不会把目标文件重新加入暂存架。

### 11.2 同名冲突与文件系统安全

- 默认「跳过」：目标已存在同名项时该条目标记为 skipped，不覆盖任何文件；
  「自动重命名」生成 `名称 (1).ext`（文件夹为 `名称 (1)`），最多尝试 999 次。
- 源与目标同一目录：移动标记 skipped（不重复移动）；文件夹移入自身或子目录
  直接拒绝（canonical 路径比较，防递归）。
- **同卷移动不再使用会覆盖的 `rename`（2026-11-05）**：改为不带 REPLACE 标志的
  `MoveFileExW`（非 Windows 走存在性检查 + rename）。即使目标在检查后被并发创建，
  也返回冲突并保持源/目标原样，绝不静默覆盖。
- **移动源与暂存架根重叠时拒绝（2026-11-05）**：`src == root`、源是 root 的祖先或
  位于 root 内部都会在磁盘操作前失败，避免把 `data_dir` / 托管资产目录搬走后导致
  `managed_path` 全部失效。
- 同卷优先原子改名；跨卷降级为「流式复制到唯一临时副本
  `.原名.<uuid>.shelf-part` → 完整性校验 → 原子建立目标 → 删除源」。完整性校验
  同时覆盖目录结构（含空目录）、文件集合、文件大小和逐文件流式内容比对；复制或
  校验期间源文件集合/大小/时间戳变化即判失败，**绝不删除源文件**。
- **源清理失败绝不删除目标**：源可能已被部分删除，目标可能是唯一完整副本。此时
  保留目标、把暂存引用切到目标并返回 `partial`（附 `residual_source` 与
  `recovery` 建议），不递归清理不确定状态的残留源；不再用 `src.exists()` 推断
  源完整性。
- 复制或校验失败、日志关键阶段写失败时都不删除源；日志阶段失败会保留源与已校验
  目标（`partial`），交由启动恢复收敛。
- 复制到自身或自身子目录（canonical 祖先比较）直接拒绝；目标检查与最终建立之间
  重新确认不存在，文件优先用同目录硬链接提交，避免 `rename` 静默覆盖同名文件。
- 符号链接、联接点及其他重解析点直接拒绝（Windows 按 `FILE_ATTRIBUTE_REPARSE_POINT`
  判定，不只看 `is_symlink`）；目录递归复制有深度上限并用 canonical 已访问集合
  防循环；临时副本名含 uuid，绝不预先删除目标目录中的同名用户文件。
- 每次磁盘操作前写入 `shelf_file_ops` 日志（intent/copied/moved），磁盘移动与
  SQLite 引用更新非原子；启动时 `recover_pending_file_ops`（幂等、可重复执行）
  按「日志阶段 + 文件系统现状」收敛，而不是只凭目标存在判成功：
  - copy / 未完成的跨卷临时副本：源仍存在时只清理带本次 uuid 的 `.shelf-part`；
  - 目标存在、源不存在：补写引用后清日志；
  - 源与目标都存在：保留两者，仅把引用切到已校验目标，并记录源残留；
  - 源与目标都不存在：保留日志作为异常诊断，不判成功、不清理文件；
  - 日志条目对应记录已删除或路径已指向无关位置时直接丢弃日志，不操作文件；
  - 恢复失败只记录并按启动节奏重试，不做高频循环；清日志只在安全终态之后。

### 11.3 最近目录

- 表 `shelf_recent_dirs`（路径主键、`pinned`、`last_used_at`），最多 8 项；
  按固定优先、最近成功使用倒序排列；重复路径自动去重。
- 仅在打开文件操作面板或执行时读取并探测 `available`，**启动阶段不扫描目录**，
  不新增后台服务；不可用目录在面板中明确标注。
- 支持固定/取消固定/移除/清空；全部 8 项被固定时新增目录会提示先取消固定。
- 只有操作至少成功一条后才更新最近使用时间；失败不影响排序。

### 11.4 批量与完成后处理

- 复用现有卡片多选；批量移动/复制共用一套面板与冲突策略，结果逐条返回
  `ok/skipped/failed/partial` 及原因，失败与部分完成条目保留在暂存架。
- 批量内父目录与子项同时被选中时，按物理路径（大小写不敏感）先处理父目录，子项
  标记 skipped 并保留记录；父目录移动会同步改写子记录引用。同一物理路径对应多条
  记录时只处理第一条，其余 skipped；并发批次占用同一路径会被拒绝。
- `partial` 表示文件已完整复制并校验到目标、但源清理或暂存路径更新未完成；附
  `residual_source`（残留源路径）与 `recovery`（建议动作），不参与「从暂存架移除」。
- 完成后可选「保留在暂存架」（默认）或「从暂存架移除」；只移除完全成功的记录：
  - reference 移动：删除暂存记录不影响已移动的目标文件；
  - managed 导出：移除记录会连同托管副本删除，面板明确提示，需用户显式勾选；
  - 失败/跳过/部分完成条目永不因「移除」选项被删除。
- 批量报告区分三类结果：`failed`（文件操作失败）、`record_cleanup_failed`
  （文件成功但移除记录失败，记录保留可重试）、`remove_failed_files`（记录已移除
  但托管文件清理失败，由下次清理兜底）；记录清理失败不会把已成功的文件操作报成
  全部失败。
- 2026-11-05 起文件操作面板完整消费 `partial` / `record_cleanup_failed`：汇总显示
  部分完成数量，逐项展示残留源与恢复建议；只要存在部分完成或记录清理失败，就保持
  面板打开并给出 warning，不再把「成功 0 项」当成完全成功关闭。
- 「移动文件到…」作用于磁盘上的原文件；「移动到分组」只改暂存架分组，二者在
  菜单中分组呈现，文案与图标明确区分。

### 11.5 验收状态与已知限制

- 已用隔离目录 `tmp/` 覆盖：单文件/文件夹移动、跨卷（测试模式强制降级）内容校验
  失败、源复制期间变化、源部分删除、关键日志阶段失败、数据库更新失败、异常退出
  恢复（源+目标/仅目标/两者均无）、空目录与嵌套/Unicode 名称、批量部分失败、
  同名跳过/重命名、复制到自身与子目录、目标竞争不覆盖、父子目录同批、同路径多
  记录、托管导出、删除记录不影响外部原文件、备份与操作日志隔离、最近目录
  去重/固定/上限、失效重定位类型校验。
- **UNVERIFIED**：真实跨物理磁盘（单测用测试钩子强制跨卷分支）、网络共享目录、
  文件被其他进程占用、权限不足、磁盘写满、应用在移动/清理过程中被强杀（恢复
  用例为构造日志现场）、符号链接/联接点的真实创建（部分 Windows 环境需特权）
  等场景，需真机复验；现有单测只证明逻辑分支与临时目录行为，不代表上述环境已通过。
- 第一版不支持断点续传、覆盖同名文件、跨设备原子移动；文件夹复制会完整遍历
  目录并逐文件比对内容（有深度与循环保护，不装载全部内容进内存，但耗时随体积
  与文件数增长）。

### 11.6 结果模型契约（IPC，v34 定稿）

`shelf_move_items` / `shelf_copy_to` 返回同一个 `ShelfOpReport`。字段只增不减，
新增字段均为可选或默认值，旧前端忽略即可；命令参数与语义未变。

`ShelfOpReport`：

| 字段 | 类型 | 可选性 | 语义 |
|---|---|---|---|
| `success` | `number` | 必有 | 文件操作完全成功（`ok`）的条数 |
| `skipped` | `number` | 必有 | 主动跳过（同名冲突、源目标同目录、父目录已处理、重复物理路径）的条数 |
| `failed` | `number` | 必有 | 文件操作失败条数（未产生完整目标） |
| `partial` | `number` | 必有，默认 0 | 目标已完整校验但源清理/记录更新未完成的条数 |
| `removed` | `number` | 必有 | 按「从暂存架移除」实际移除的记录数 |
| `remove_failed_files` | `number` | 必有，默认 0 | 记录已移除但托管文件清理失败条数（下次清理兜底），仅计数、无逐项明细 |
| `record_cleanup_failed` | `number` | 必有，默认 0 | 文件操作成功但移除暂存记录失败条数（记录保留可重试） |
| `record_cleanup_error` | `string \| null` | **可选**，`undefined` 表示无清理失败 | 记录清理失败原因摘要（多条时取首条） |
| `entries` | `ShelfOpEntry[]` | 必有（保留字段名） | 逐项结果，顺序与请求 `ids` 一致；不存在的 ID 也占一项 `failed` |

`ShelfOpEntry`：

| 字段 | 类型 | 可选性 | 语义 |
|---|---|---|---|
| `id` | `string` | 必有 | 暂存条目 ID |
| `display_name` | `string` | 必有 | 展示名（可能为空字符串） |
| `source` | `string \| null` | 必有 | 实际操作的源路径；解析失败时为 `null` |
| `target` | `string \| null` | 必有 | 目标路径；未建立目标时为 `null` |
| `status` | `"ok" \| "skipped" \| "failed" \| "partial"` | 必有 | 仅这 4 个稳定取值，不新增枚举 |
| `reason` | `string \| null` | 必有 | 用户可读原因；`status != "ok"` 时保证非空且稳定；`ok` 时通常为 `null`，仅在「源清理报错但源已消失」时附说明文本 |
| `recovery` | `string` | **可选**，`undefined` | 部分完成时的建议动作 |
| `residual_source` | `string` | **可选**，`undefined` | 部分完成时仍残留的源路径 |

- `entries` 与 `remove_failed_files` 保持原名，前端改为可选读取是兼容的，但后端始终
  返回这两个字段。
- 失败分类只看 `status`：前端展示 `reason` 即可；跨条目汇总用 `failed` /
  `partial` / `record_cleanup_failed` / `remove_failed_files` 四个计数区分，不新增总体
  `overallStatus` 字段。需要「是否部分完成」时以 `partial > 0` 判断。
- `status == "partial"` 的条目目标副本一定已完整校验，且不会被「移除记录」选项删除。

## 12. 收集箱文件投递（v35，v36 整合最近暂存与视图分离）

工具面板（胶囊）的「收集箱」拆成两个子页：**快速收集 | 文件**。文件子页让用户把
资源管理器里的文件/文件夹直接拖到一张目标卡片上，**落到真实磁盘目录**；下方同时提供
最近暂存条目，不必跳完整面板就能打开/复制。它与完整面板共享同一份目标配置与暂存架数据，
不新建文件管理系统，也不因投递往暂存架写记录。

### 12.1 与相邻概念的边界（不要合并）

| | 文件投递目标 | `shelf_recent_dirs` | `shelf_groups` |
|---|---|---|---|
| 来源 | 用户显式配置 | 文件操作成功后自动记录 | 用户手动创建 |
| 主键 | `id`（uuid） | `path` | `id` |
| 别名 | 有（显示名称） | 无（显示目录名） | 有 |
| 排序 | 有（`sort_order`，上下移动） | 固定优先 + 最近使用 | 有 |
| 工具面板 | 可勾选是否显示 | 不显示 | 不显示 |
| 上限 | 24 | 8 | 无硬上限 |

三者共享同一套**路径校验**（`normalize_target_dir`：绝对路径、必须存在的目录、
不得指向暂存架内部），但存储与语义独立，互不覆盖。

### 12.2 数据模型（迁移 v35）

`db::MIGRATIONS` 追加 v35：`shelf_drop_targets`

| 列 | 说明 |
|---|---|
| `id` | uuid 主键 |
| `name` | 显示名称（≤40 字符，留空回退为目录名） |
| `path` | 真实目录，`COLLATE NOCASE` 唯一（Windows 路径大小写不敏感） |
| `sort_order` | 显示顺序，新增取 `max+1`，上下移动交换相邻两项 |
| `show_in_capsule` | 是否出现在工具面板 |
| `op_mode` | `copy`（默认）/ `move` |
| `conflict` | `rename`（默认）/ `skip` |
| `created_at` / `updated_at` | 审计时间 |

- 表在 `BACKUP_TABLES`（class=shelf，快速/完整均全量）与 `EXTENDED_TABLES` 登记；
  旧备份缺该段时按「缺表即跳过」恢复，不影响可用性，只是没有目标配置。
- 迁移只**新增空表**，不导入任何示例路径；首个目标必须由用户自己选择目录。

### 12.3 语义

- **默认复制**：保留源文件与目录结构（含空目录），成功后**不**创建暂存记录
  （避免同一份文件在暂存架里再出现一次）。需要移动必须由用户在目标上显式选择。
- **移动模式**：完全复用 `fsops` 的移动实现——同卷 `rename` 原子改名；跨卷
  「流式复制 → 逐文件内容校验 → 原子建立目标 → 删除源」；目标未完整校验前绝不删除源；
  源清理失败返回 `partial` 并保留目标（可能是唯一完整副本）。
- **同名冲突**：默认 `rename`（`名称 (1).ext`，最多 999 次），可选 `skip`；
  **不存在覆盖策略**，绝不静默覆盖用户已有文件。复制/移动的**最终提交**不依赖
  「先检查再改名」：文件优先用硬链接建立目标（已存在必然失败），硬链接不可用或目录
  走 `MoveFileExW`（不带 `REPLACE_EXISTING`）；提交阶段出现同名一律报冲突并回收临时副本。
- **并发占用（源 + 目标）**：占用同时覆盖**源路径**、**目标目录**与**最终目标路径**，
  并按读写语义分层，避免「源路径不同但目标互相踩踏」：
  - `Exclusive`：会改变该路径及其子树的操作（移动源、最终写入目标）；
  - `Shared`：只要求路径保持原位、可并行的操作（复制时读取源、向同一目录写入）。
  - 冲突规则：Exclusive×Exclusive 相等或互为祖先/后代即冲突；Exclusive 是 Shared
    的祖先或同路径即冲突（搬走父目录会毁掉正在写入的子目录）；Shared×Shared 从不冲突。
  - 效果：两个批次向同一目录复制**不同**文件可并行；同一最终目标互斥（后到者拿到可重试
    冲突）；目标目录被移动/删除期间，写入方整批拒绝；移动父目录与写入其子目录互斥。
  - 占用按规范化分量比较（大小写不敏感、解析重解析点/8.3 短名）；成功、失败、提前返回
    都由 `Drop` 释放；每次占用带 owner，释放只删自己的登记。
- **提交前再验证**：复制在最终提交前重新确认目标父目录仍是目录（外部删除/重挂载时给出
  可读原因）；移动在改名/复制前同样检查。真正的无覆盖仍由系统级原子提交保证。
- **文件夹**：保持层级、保留空目录、拒绝重解析点（符号链接/联接点）、拒绝把目录放进
  自身或子目录；单文件失败不阻断同批其他条目。
- **目标解析**：前端只提交 `target_id` 与路径列表，后端按 id 从库里取权威目录；
  目录在投递时再做一次 `is_dir` 确认，不可用直接拒绝（fail-closed），不写入任何文件。
- **批次**：单批 ≤200 项；同批次重复路径先去重；父目录与子项同时拖入时只处理父目录，
  子项标记 `skipped`。源类型在磁盘操作**之前**记录：移动后源路径已不存在也不会把子项
  误判为失败。父目录只完成一部分时，子项标记 `partial` 并附残留源与人工处理建议，
  不冒充成功、也不重复执行文件操作。
- **崩溃恢复**：磁盘操作前写 `shelf_file_ops`，`item_id` 用 `drop:<batch>` 前缀与条目
  操作区分；启动恢复对投递批次只清理**本次创建的** `.shelf-part` 临时副本，不改写任何
  引用、不删除源或用户目标文件。
- **最近目录联动**：批次至少成功一条后，目标目录也会出现在文件操作面板的「最近目录」里。

### 12.4 命令（IPC）

| 命令 | 说明 |
|---|---|
| `shelf_drag_out` | 按 id 解析已存在的物理文件/文件夹并发起 Windows OLE 拖出；返回 `effect / count / missing_ids`；link/text/missing 跳过，托管项只复制 |
| `shelf_drop_targets_list` | 列表；读取时逐个探测 `available`（`is_dir`），无后台扫描 || `shelf_drop_target_create` | 添加（名称/路径/模式/冲突策略/是否显示） |

`DropReport`：`batch_id / target_id / target_path / op / total / success / skipped /
failed / partial / entries[]`；`entries[]` 每项含 `source / display_name / target? /

`shelf_list` 新增可选 `sort` 参数（v36 第五轮）：缺省或 `default` 保持完整暂存架的
「置顶优先、创建时间倒序、id 倒序」；`recent` 改为纯 `created_at DESC, id DESC`
（**忽略 pinned**），供工具面板「最近暂存」使用。未知取值返回校验错误，不会静默改变
默认列表语义；分页、筛选与 `total` 不受影响。

### 12.5 拖放通道与所有权

`src/lib/fileDrop.ts` 是**唯一**的 `onDragDropEvent` 订阅者：

- 按需订阅：第一个消费者注册时建立，最后一个注销时立即 `unlisten`（不常驻）；
- 一次拖入在 `enter` 时只选一个消费者（自己 `claim()` 为真且优先级最高），
  会话期间不换人；`leave` / `drop` 结束会话；
- 无人认领时丢弃事件——不执行任何文件操作；命中不到卡片同样不投递（fail-closed）；
- `leave` 之后的 `drop` 不投递：松手时不再临时仲裁（「找不到会话就不猜消费者」）；
- 坐标链路（按 `Cargo.lock` 实际解析的 tauri 2.12.5 / wry 0.57.1 源码核实）：Windows OLE 传入屏幕坐标 →
  wry `ScreenToClient` → **Windows 客户端区物理像素**（相对 webview 左上角）→
  Tauri 包装为 `PhysicalPosition<f64>`。前端除以 `devicePixelRatio` 得到 CSS 像素，
  再 `document.elementFromPoint(...).closest('[data-drop-target]')` 命中卡片，
  因此 DPI 缩放与多显示器共用同一套逻辑；高亮层必须 `pointer-events: none`；
- 落点以**松手瞬间的坐标重新命中**：不复用可能过期的 `over` 高亮缓存；
  坐标缺失时传 `null`，卡片不可见/已删除/视图已切换时同样不投递（绝不回到默认目录）。
- **`enter` 也带坐标（2026-11-13）**：Windows OLE 只在**鼠标移动**时发 `DragOver`，
  wry 不节流也不补发。因此「拖进窗口后停在卡片上」不会再有第二次命中机会——消费者
  必须在 `enter` 时先按该坐标命中一次；若命中发生在目标列表就绪之前、或面板滚动
  /目标列表变化之后，还要用**最后一次已知坐标**重算（`InboxDropPane` 的 `rehit`）。
  这三条合起来才是「鼠标明明在卡片上、界面却一直提示把文件拖到卡片上」的根因层修复；
  松手仍然只用实时坐标重新命中，绝不复用 `overId`。
- **应用内拖出的限制（同轮结论）**：从最近暂存行拖出时，`DoDragDrop` 在 UI 线程运行，
  tao 会把 `enter/over/drop` 全部缓冲到拖拽结束后才派发。因此该路径**拿不到**逐卡
  实时高亮；`useShelfDragOut` 增加 `onDragStart` 前置信号，让面板在拖拽一开始就显示
  「可投递」形态（落点仍以松手坐标判定，不受这个信号影响）。

消费者优先级：胶囊投递卡片 `20` > 暂存架 `10`。暂存架在胶囊停靠期主动退出
（`dock-app` 处于 inert，不能抢拖入事件），避免文件被悄悄塞进暂存架。

**拖出通道（2026-11-09）**：

- 前端 `src/hooks/useShelfDragOut.ts`：左键按下后位移超过 5px 才调用后端；忽略
  `[data-no-drag]`（勾选/更多菜单）；不使用 HTML5 dragstart、不 `setPointerCapture`；
  拖拽后 350ms 内吞掉一次 click，pointercancel/blur/卸载/30s 看门狗回收监听与在途闸。
- 后端 `src-tauri/src/shelf/drag_out.rs`：命令层用 `AppHandle::run_on_main_thread`
  回到 Tauri 主线程（tao 已 `OleInitialize`）执行 `OleInitialize` → 自实现
  `IDataObject`（暴露 `CF_HDROP`，并接受 helper 的 `DragImageBits` /
  `DragContext`）→ `DoDragDrop` → `OleUninitialize`；进程级
  `AtomicBool` 单飞，防止并发 `DRAGDROP_E_CONCURRENT_DRAG_ATTEMPTED`。
  进入前检查全局左键状态，已松开则直接返回 `effect=none`，避免主线程被
  无输入事件的拖拽循环挂死。
- 拖拽幽灵：`IDragSourceHelper::InitializeFromBitmap` 取第一个文件的 Shell
  缩略图/图标（96px）写入数据对象；`SetData` 同时接受 HGLOBAL 与 IStream，
  `EnumFormatEtc(DATADIR_SET)` 返回空集（返回 `E_NOTIMPL` 会让 helper 整体失败）。
- 允许效果：全部为引用模式时 `DROPEFFECT_COPY | DROPEFFECT_MOVE`；包含托管副本时
  只允许 `DROPEFFECT_COPY`。`effect=move` 后按返回的 `missing_ids` 刷新存在性并提示。
- 限制：DoDragDrop 必须在左键仍按下时进入；WebView2 指针捕获冲突、UIPI 跨完整性
  级别拖放、目标应用不接受文件等仍需真机验证；真机未执行前不得宣称拖出已验收。
  2026-11-09 会话锁屏导致原生鼠标拖拽未执行，幽灵数据通路由 Rust 单测
  `drag_source_helper_attaches_drag_image` 覆盖。

**应用内投递（2026-11-10）**：最近暂存行拖到目标卡片时仍走同一条原生拖出通道；
松手后 wry 的 drop 目标把真实路径交回前端，`InboxDropPane` 按**松手坐标**命中卡片并
调用 `shelf_drop_to_directory`，目标 `op_mode` 决定复制/移动。两个必须保持的不变量：

- **拖入提示条渲染在目标网格之后**。从暂存架拖出的 `DoDragDrop` 运行在主线程，
  enter/over/drop 事件要等拖拽结束才被处理；提示条若插在网格上方，enter 触发的那次
  渲染会先把卡片下移，随后 drop 按真实松手坐标重新命中时就落到提示条/空白处，表现为
  「拖到卡片上没反应」。2026-11-10 隔离真机对照：提示条隐藏时同一坐标命中卡片并成功
  复制；恢复提示条后卡片下移 32.7px，drop 命中容器（`cap-drop`）而非卡片。
- **托管副本只允许复制**。源路径位于暂存架 root 内时，移动模式目标明确拒绝
  （`failed` + 可读原因，源文件保留）；复制模式按只读导出处理，不修改暂存记录。
  这与拖出通道「托管项只复制」的约束一致，避免把内部副本搬出托管目录。

  管理操作。添加表单在列表上方展开，编辑表单**就地替换该行**，只提交名称/目录/模式/策略，
  id、排序与可见性保持原值；有未保存表单时返回暂存架先弹确认，不静默丢弃输入。
  完整面板与工具面板共用同一份表单组件（`components/shelf/DropTargetForm.tsx`），
  胶囊表单控件统一为 30px 高（`--input-height-sm`），同名策略折叠在「高级选项」里
  但摘要常显；胶囊底栏按状态切换：列表态「添加目标/管理」，表单态只有「保存/取消」，
  不再出现表单内与底栏两套主操作。胶囊里的「管理」会切到该视图。
- **暂存架空状态**：区分「暂存架真空」（显示添加文件/文件夹与拖入提示，筛选浮层仍可用
  但没有对象）、「当前筛选无结果」（保留筛选，提示没有匹配并给「清除筛选」）、
  「首次/刷新加载中」与「读取失败」（错误空态 + 重试），不把加载或失败画成空暂存架。
- 定位：拖入与操作中都不自动收起——展开态胶囊本来就是「用户主动关闭」，
  不因短暂失去 hover 收起，也不为此修改全局收起策略。

### 12.7 性能与资源

- 目录可用性只在打开面板/强制刷新时探测，不轮询、不在启动阶段扫描；结果缓存
  `AVAILABILITY_TTL_MS = 30s`，过期后由面板打开时后台重探一次（不阻塞首屏）；
- 「看起来不可用」时投递前强制重探一次（外接盘重连后无需重启应用）；手动刷新无视 TTL；
- 并发 `load` 去重、慢响应按请求代次丢弃；写操作（新增/编辑/删除/排序）成功后提升
  **写代次**，早于写操作的列表快照一律丢弃（不会回滚刚完成的配置），必要时最多重试一次，
  不产生请求风暴，也不引入轮询；
- 路径占用只在文件操作期间持有，按路径粒度判定，不做全局大锁，无关目录并行不受影响；
- 目标配置由 `useDropTargetsStore` 缓存，工具面板与完整面板共用，切页不重复拉取；
- 最近暂存只取 `shelf_list(sort=recent, limit=4)`，不加载完整历史；5s 软缓存 +
  在途去重，子页来回切换不重复 IPC；新增/删除/改名/移动/清理后递增数据代次并清掉
  TTL，早于变更的慢响应一律丢弃，不会覆盖更新后的切片；文件子页关闭后没有订阅/定时器残留；
- 完整面板视图切换只条件渲染，不重新加载列表；目标管理期间不注册拖放消费者，
  拖入事件直接留给胶囊（一次拖入仍只有一个消费者）；
- 投递在 Rust 的 `spawn_blocking` 线程执行，UI 线程不做文件 IO；
- 进度只展示真实条数（已知批次大小），不伪造百分比；界面卸载不中断底层操作，
  结果保存在 store 里，重开面板仍可查看；
- 拖入 `over` 事件只在卡片切换时触发一次重渲染。

### 12.9 失败分类、诊断联动与旧库兼容（2026-11-12）

- **结构化失败分类**：`DropEntry` 在既有 `reason/recovery/residual_source` 之外新增可选
  `code`（稳定错误码）与 `stage`（prepare / resolve / journal / commit / copy / cleanup /
  rewrite）。`reason` 仍是用户可读文案；诊断聚合只依赖 `code/stage`，不解析文案。正常跳过
  不带 code。稳定码表见 [docs/DIAGNOSTICS.md §21](../DIAGNOSTICS.md#21-文件投递业务失败记录与旧库兼容2026-11-12)。
- **数据库日志失败不再误报为文件问题**：`journal_insert` / `journal_set_target` /
  `journal_mark_copied` 失败统一归入 `SHELF_DROP_DB` / `SHELF_DROP_DB_SCHEMA_INCOMPATIBLE`，
  `stage = journal`；复制/移动在日志写入失败后不会继续任何磁盘操作，源文件保持原位。
- **诊断归属**：命令层在 `drop_paths` 返回后按批次写入汇总（`drop_completed` /
  `drop_partial` / `drop_failed`）与最多 4 条按错误码聚合的明细
  （`drop_item_failed`），`operation_id = batch_id`。收集箱结果条在
  `failed > 0 || partial > 0` 时显示「查看诊断」，进入完整模式诊断中心并按
  `operation_id` 打开操作链；入口只在导航成功后下发一次性意图，被草稿拦截/保存中拒绝时
  不残留、不误报「已打开」。
- **旧库兼容（迁移 v47）**：早期构建把 v34 的 `shelf_file_ops.op` 约束写成单值
  `CHECK (op IN ('move'))`，且 `user_version` 已推进到 46，原地修改 v34 不会重放。
  v47 在单事务内重建表为 `('move','copy')`，逐列复制全部未完成日志、恢复
  `idx_shelf_file_ops_created`；任何异常行（外部改库）会让整条迁移回滚，`user_version`
  保持 46，不静默丢行。新库同样执行一次重建，结果等价。
- **验证**：`db::tests::v47_*`（旧约束修复、保行、回滚）与
  `shelf::tests::drop_copy_png_on_legacy_schema_database_is_repaired_by_v47`
  （真实文件库从 v46+旧约束升级后复制 PNG）覆盖；诊断侧由
  `diagnostics::tests::shelf_drop_business_failure_reaches_anomaly_list_and_operation_chain`
  验证默认异常列表、操作链、错误码筛选与隐私边界。真机 WebView2 跳转未验证。

### 12.10 拖放接收修复与统一仲裁（2026-11-12）

- **完整暂存架**（`ShelfWorkspace`）：拖入消费者只在「页面真实可见」时注册——
  `active && useFullViewVisible() && !capsuleMode && !targetsOpen`。此前只看逻辑 Tab，
  而完整面板在极简/紧凑模式下由 `DeferredView` 保活、仅 CSS 隐藏，隐藏的暂存架会继续
  以 `claim: () => true` 抢走可见界面上的拖入，文件被悄悄加进看不见的暂存架。
- **拖拽会话稳定**：`copyOnAdd` 改为 ref 读取，切换引用/托管不再重注册消费者
  （重注册会清空 `owner`，正在进行的拖入会在松手时被 fail-closed 丢弃）。
- **路径预检**：空白/相对路径不进入后端；全部无效时明确失败提示，混合批次只提交有效
  路径并把无效项并入失败汇总。`added=0 && failed=0` 不再静默当作成功；失败提示合并为
  一条（成功数 + 失败数 + 首条原因），不按条目刷 N 个 toast、不把完整路径写进提示。
- **胶囊统一仲裁**：仍是 `InboxDropPane` 一个消费者（priority 20）接管整个拖拽会话，
  `onOver`/`onDrop` 用**当前/松手瞬间坐标**路由：可见目录卡片 → 目录投递；最近暂存
  `data-drop-zone="shelf-recent"` → `addPaths(..., "reference", "drag")`；空白/缺坐标/
  空 paths → 不执行。一次会话只执行一次；`leave` 后迟到的 drop 不生效；卡片与接收区
  高亮互斥，`onDrop` 不复用 over 缓存。
- **最近暂存接收区**：有条目/空列表都可接收；拖拽期间显示轻提示与内描边高亮，绝对定位、
  `pointer-events: none`，不挤占列表、不挡命中；既有「+」添加、列表、删除、OLE 拖出不变。
- **监听可观测**：`lib/fileDrop` 的订阅/退订失败写一条 5s 去重的 WARN
  （`module=file`、`action=file_drop_listener`、`stage=subscribe|unlisten`、不含路径/
  原始 message），恢复后补一条 `recovered`；正常 enter/over/drop 不写持久化日志，
  失败后下次注册仍会重试。
- **验证边界**：jsdom 端到端覆盖 enter→over→drop→`shelf_add_paths`/`shelfDropToDirectory`、
  落点切换、重复 drop、缺坐标、DPI 1.25/2、页面卸载/切视图与监听失败恢复；真实 Windows
  资源管理器 OLE 拖入、真实 DPI/多显示器与窄窗视觉仍需真机验收（本轮未执行）。

### 12.7 拖入视觉状态、命中修复与几何不变量（2026-11-13）

目标：拖入时让用户不思考就能判断「哪里能放 / 现在指向哪 / 松手会发生什么」，
同时**不改动任何已验证的坐标与投递语义**。

**状态模型**（`InboxDropPane` 的 `data-drop-state`，一处判定，避免自相矛盾）：

| 状态 | 何时 | 卡片表现 |
|---|---|---|
| `idle` | 无拖拽 | 普通玻璃卡，无任何拖入提示 |
| `ready` | 拖拽中、光标不在其上 | 1px 强调内描边 + 图标换成「文件夹 + 向内箭头」+ 图标底色微调；opacity 0.86；**保留完整模式文案（含「删除源文件」警告）** |
| `over` | 光标位于该卡 | 强调底色 + 1.5px 强调内描边；`meta` 行改为「松手即复制 / 松手即移动」（单行同字号，字号 9.5px，实测不换行不省略） |
| `blocked` | 目标不可用或正在投递 | 不可用：保留红字「目录不可用」徽标与普通图标，不加可投递描边；光标停在其上时改用警示色描边（明确「放不进去」）。正在投递：显示「正在复制/移动 N 项」进度，同样不加可投递/落点描边 |

**最近暂存接收区**：拖拽期间整区 1px 强调内描边 + 极淡底色；光标落到其上时
1.5px 内描边 + 强调底色，并把标题行里的状态标签从「可暂存」换成「松开即加入」。
标签放在**标题行内**（与 22px 按钮同高、`pointer-events: none`）——不新增段落高度，
也不再用盖住最后一行的底部浮层。`pointer-events`/`overflow`/`-webkit-line-clamp`
等装饰一律不作用于卡片本体与按钮。

**信息层级**：顶部 `PanelHead` 只说明「拖文件到卡片即可投递 · N 个目标」；
卡片/接收区各自表达能否接收与松手动作；**删除了面板级「把文件拖到目标卡片上」提示**
（既与顶部重复，又曾作为普通流元素改变几何）。不悬停任何目标时不出现任何与顶部重复的文案。

**几何不变量**（本轮起为硬约束）：拖拽状态只允许改变类名、文本与图标，
不得插入普通文档流节点、不得改变卡片/接收区的实际矩形与命中区域：

- 卡片描边用 `inset box-shadow`（不参与布局），不新增边框/padding/缩放；
- 接收区状态标签在固定高度（22px）的标题行内，标题与计数 `white-space: nowrap`、
  `flex: 0 0 auto`（否则会被挤成两行——实测过一次 +8.44px 的高度跳变）；
- 单元测试断言 `.cap-drop` 的子节点**节点同一性/顺序**在拖拽前后不变、
  卡片子节点数与（SVG 之外的）标签序列不变；
- 浏览器 harness（真实布局引擎）在 280/320/340/400px 宽度（浅色/暗色、中文/英文）
  实测卡片/接收区/标题行/列表的 `x/y/w/h` 位移全部为 0（容差 1px）；
  **DPI 分片（100/125/150/200%）只验证命中映射**：物理坐标 `= CSS × DPR` 命中同一张卡，
  而把 CSS 坐标当物理坐标传入会命中失败——矩形几何在同一 DPR=1 的 harness 里测量。
  开发期还实测到两处高度跳变并被这两条约束挡住：状态标签加入标题行后标题被挤成两行
  （标题行 22px → 30.4px），以及英文模式文案折行导致悬停切换文案时卡片变矮
  （接收区位移 13.53px）。现在标题/计数 `white-space: nowrap`、meta 行统一单行省略，
  两处均为 0。

**命中修复（根因层）**：见 §12.5 的 `enter` 坐标与 `rehit`。
`fileDrop.toCssPoint`/`dropTargetAt` 的物理像素→CSS 像素换算**未改动**。

**验证与未验证**：见 `tmp/acceptance/file-drop-ux/report.md`。
浏览器 harness 只代表浏览器渲染；Windows 原生窗口下的真实 OLE 拖入、真实 DPI、
多显示器、跨窗口拖出仍未真机验收（会话锁屏 `ENVIRONMENT BLOCKED`）。

### 12.11 跨应用拖入：非路径内容接入暂存架（2026-11-13）

原有实现只接收**真实本地路径**（`CF_HDROP`），网页图片、链接、选中文本、HTML、Outlook
附件（虚拟文件）、截图位图在原生事件层就被 wry 的处理器丢弃。本轮把 Windows OLE 接收
整体接管（`src-tauri/src/dragdrop/`），并让暂存架按**真实类型**落库。完整架构见
[../DRAG_INPUT.md](../DRAG_INPUT.md)。

暂存架侧的变化（**不新增第二套存储、不改仲裁**）：

- **入口**：`useShelfStore.commitDragPayload(operationId, mode, groupId)`。前端只传
  `operationId`；文本/HTML 正文、图片字节、虚拟文件内容全部留在后端暂存区，
  由 `drag_payload_commit_shelf` 读取并入库。
- **入库方式**：本地路径仍是「引用 / 托管」二选一；虚拟文件与图片字节一律走
  `shelf::add_managed_from`（`original_path = None`，绝不把暂存临时路径伪装成原始路径）；
  链接走 `add_link`、文本走 `add_text`（`from_html` 时来源记为 `drag-html`）。
- **失败口径**：与 `addPaths` 相同——`added=0 && failed=0` 不假装成功；
  失败清单 = 提交阶段逐条失败 + 拖入阶段失败（带 `DRAG_*` 错误码）。
- **目录卡片**：链接/文本/HTML **拒绝**进入目录（不做隐式 `URL.txt`）。
  `useDropTargetsStore.commit(targetId, operationId, count)` 复用同一套在途单飞、
  700ms 去重、结果条与 `reportNames` 状态；内容由后端 `fsops::drop_paths` 落到真实目录。
  「移动并删除源文件」只对真实本地路径生效，暂存副本没有源可删。
- **交互**：探测只影响提示（「松开即可暂存图片 / 保存链接 / 暂存文本 / 添加文件」），
  **不改变命中**；不可投递时卡片 meta 行显示「此内容不能直接投递到文件夹」，
  行高与卡片矩形不变。
- **验证边界**：Rust 侧暂存/分类/清洗/上限与前端分发有单测；真实 Windows 上的
  Chrome/ChatGPT 拖入、Outlook 附件、截图工具拖出仍需真机验收，结论以
  `tmp/acceptance/universal-drag/report.md` 为准。


### 12.12 统一内容收集：当前剪贴板、项目关联、OCR 与重复提示（2026-11-14）

本轮在既有暂存架上增量接入，不新建第二套项目/任务/存储体系：

- **当前剪贴板粘贴**：`shelf_paste_current` 读取实时系统剪贴板并复用
  `add_reference/add_managed/add_managed_png/add_link/add_text`。完整协议、格式优先级、
  虚拟文件限制与 Ctrl+V 焦点规则见 [../DRAG_INPUT.md](../DRAG_INPUT.md) §13。
- **项目关联（v51）**：新表 `shelf_project_links(project_id, item_id, created_at)`，
  外键分别指向既有 `workspace_projects` 与 `shelf_items`，删除任一侧级联清理关系，
  **不复制项目/条目内容**。命令：`shelf_project_links` / `shelf_link_project` /
  `shelf_unlink_project`；详情页「关联项目」与任务关联并列。
- **最近投递**：`shelf_drop_targets.last_used_at` 在成功投递后更新（失败不影响结果），
  完整面板目标卡片显示「最近投递：YYYY-MM-DD」；手动排序 `sort_order` 不变，
  胶囊展示顺序仍由用户控制。
- **图片 OCR**：`shelf_ocr_item(id, request_id)` 复用 `clipboard::ocr::OcrService` 的
  本地 Windows OCR（新增 `recognize_png` 入口），只读取暂存图片字节，不改原图、
  不上传。结果可复制或「保存为文本条目」；保存时自动复制原图的项目/任务关联，
  并在新条目备注写 `OCR 自：<原图名>`。识别失败/超时/无语言包不改动原图。
- **重复提示**：同路径（`original_path COLLATE NOCASE`）或同正文（文本/链接）只计入
