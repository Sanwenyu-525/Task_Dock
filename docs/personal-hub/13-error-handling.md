# Personal Hub · 错误处理与恢复机制

- 日期：2026-11-19
- 阶段：P0 设计，**已按架构基线对齐**（**未实现**）
- 唯一架构事实源：[ARCHITECTURE_BASELINE_v1.0.md](ARCHITECTURE_BASELINE_v1.0.md)
- 前置：[08-permission-and-session.md](08-permission-and-session.md)、[10-api-and-protocol.md](10-api-and-protocol.md)、[06-threat-model.md](06-threat-model.md)

---

## 1. 核心原则

1. **安全失败关闭**：任何认证失败/权限不足/超时/身份不匹配 → 安全失败态，**不通过异常处理跳过认证**（规格 §2.3）。
2. **可取消 / 有超时 / 有上限 / 可回收**：后台任务、轮询、订阅、定时器遵循 `AGENTS.md` §4.8。
3. **不伪造 / 不吞异常**：错误如实上报；不把「没跑通」当成功；不靠重试掩盖根因。
4. **日志脱敏**：只记安全事件与必要元数据，禁记密码/私钥/完整令牌/生物特征（规格 §6）。

---

## 2. 错误分类与处理

| 类别 | 例子 | 处理 | 是否自动重试 |
|---|---|---|---|
| 认证失败 | 指纹错/ PIN 错/取消/超时 | → `SESSION_FAILED`，拒绝远控 | 否（用户重新发起） |
| 身份/签名 | 指纹不符/签名错/设备撤销 | → `SESSION_FAILED` + 审计告警 | 否 |
| 权限不足 | 请求未授权能力 | 拒绝该项操作 + 审计 | 否 |
| 邀请错误 | 过期/重复/签名错 | 邀请失效 + 审计 | 否 |
| 会话错误 | nonce/序号/过期/状态不符 | → `SESSION_FAILED` / 终止 | 否（重放即告警） |
| 网络错误 | 不可达/超时/断连 | 路径回退 + 有界重连 | 是（退避，有上限） |
| 服务错误 | PersonalHubService 崩溃 | HealthMonitor 异常恢复 + 重启 | 受控重启 |
| 存储错误 | DB/Keystore 失败 | fail-closed，拒绝相关操作 | 否 |

## 3. 断线恢复（规格 §5、§4.3）

- 连接中断 → 立即关闭控制通道 + 撤销会话授权（→ `SESSION_REVOKED`）。
- 重连 → 按连接策略尝试下一条路径；重建会话需**重新认证**（不复用旧授权）。
- 网络切换（Wi-Fi↔5G）→ 更新 peer endpoint + 隧道重连（[04](04-network-topology.md) §5 矩阵待真机测）。
- 电脑重启/休眠/服务异常退出 → HealthMonitor 恢复 + 用户重新认证。

---

## 4. 服务健康与异常恢复

- HealthMonitor：健康检查 + 配置持久化 + 异常恢复 + 服务停止保护（规格 §4.1）。
- 服务形态已由基线 D2 锁定：独立普通用户进程 + 登录自启 + 进程内 HealthMonitor 恢复；无 SYSTEM 提权面（ADR-0005）。
- 服务不可用 → UI 明示「Personal Hub 不可用」，不伪装成功，不影响 TaskDock 其他功能。

---

## 5. 审计与告警

- 每次配对/认证/授权/会话/安全失败均写审计（[09](09-data-model.md) §5）。
- 异常模式（多次认证失败、重放、撤销设备连接尝试）触发告警并记审计。
- 审计只含脱敏元数据，遵循 `AGENTS.md` §7 与 [06](06-threat-model.md) §2。

---

## 6. 用户可见反馈

- 远控开始提示 + 持续状态提示 + 停止按钮 + 一键撤销所有授权（规格 §5）。
- 失败时给出明确原因（认证失败/被撤销/网络不可达/服务不可用），不显示技术内部信息。
- 被控端始终拥有最高优先级停止权；异常断开自动关闭控制通道。
