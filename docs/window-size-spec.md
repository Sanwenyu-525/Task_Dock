# 窗口尺寸与窗口级布局规范（桌面端）

> 状态：**生效**（2026-11-16）
> 适用范围：Tauri 桌面端全部窗口（`main` / `workspace` / `widget-*` / 辅助窗口）。
> 相关：内容响应式见 [ui-responsive-layout.md](ui-responsive-layout.md)；窗口职责与顶栏结构见
> [ARCHITECTURE.md](ARCHITECTURE.md) 第 14 章「唯一大型宿主」。

本文回答两个问题：**窗口能有多大/多小**（原生层，本文 §2–§4），以及
**窗口 chrome 怎么在有限宽度里分配空间**（前端层，本文 §5）。页面内容怎么重排不在这里，
统一按容器宽度响应（§6）。

---

## 1. 审查结论：问题分层

2026-11-16 全量审查（Rust 窗口层 / 全局样式层 / 业务页面层）后，把当时暴露的问题归到三层：

| 层 | 事实（修改前） | 后果 | 归属 |
|---|---|---|---|
| 原生窗口层 | `workspace` 最小尺寸写死 `880×600` DIP，但恢复几何时把 DIP 最小值直接和**物理像素**矩形比较（`clamp_into_area`） | 125% 缩放下实际最小只剩 704×480 DIP；150% 只剩 587×400 DIP | 窗口管理层 |
| 原生窗口层 | 首次打开用 `PhysicalSize(1180,760)` 设置默认尺寸 | 125% 下首次打开只有 944×608 CSS px，低于顶栏所需宽度；中心点也偏离 | 窗口管理层 |
| 原生窗口层 | 只在小屏「打开时」算一次尺寸，没有跨显示器/改缩放后的重算 | 窗口拖到低分辨率屏后仍按原屏最小尺寸约束，内容被压缩 | 窗口管理层 |
| 前端布局层 | 顶栏是单行 flex，项目选择器 `flex: 0 0 210px`、品牌与 6 个固定宽控件都不收缩，搜索最小 150px | 窄窗时固定控件不足 → 溢出被 `.wb-root{overflow:hidden}` 裁切，表现为「图标挤在一起/文字消失」 | 全局布局层 |
| 前端布局层 | 外壳紧凑档位写死 `window.innerWidth < 1100`，页面里另有 1080 / 1180 / 1500 等窗口断点 | 同一窗口宽度下不同页面行为不一致；有些页面按窗口宽度而非内容宽度切列 | 全局布局层 |
| 前端布局层 | 页面根元素普遍没有 `min-width: 0`；卡片网格固定 3/4 列 | 窄内容区网格被内容撑破，或卡片被压成一条 | 业务页面层 |
| 业务页面层 | 少数页面在窄窗下仍然用固定两栏（列表 + 详情），或表格列宽写死 | 内容被裁切、无意义横向滚动 | 业务页面层 |

> 结论：**只加 `min-width` 不能解决**。顶栏溢出是空间分配问题，卡片挤压是内容容器与列数问题，
> 窗口被无限缩小是原生层问题。三层必须分别修，且共用同一组数字。

## 2. 窗口家族与尺寸规范

所有数字单位是 **DIP**（device independent pixel，= Tauri `LogicalSize` = CSS px）。
**禁止**把 DIP 常量与 `PhysicalSize` 直接比较（历史缺陷根因）。物理换算只在两处：
保存几何恢复、显示器工作区读取。

| 窗口 | 形态 | 默认尺寸 | 最小尺寸 | 可缩放/最大化 | 说明 |
|---|---|---|---|---|---|
| `workspace` | 大型完整工作台 | **1200×760** | **960×600**（可用区不足时降级，见 §3） | 是 / 是 | 唯一大型宿主；顶栏 + 导航 + 内容三区 |
| `main` | 完整面板（full） | 400×560 | 340×340 | 是 / 否 | 快速任务/捕获/剪贴板等短流程 |
| `main` | 紧凑面板（compact） | 400×380 | 340×280 | 是 / 否 | 同上，折叠次要区块 |
| `main` | 极简（minimal） | 280×140 | **264×112**（实测下限，见 §2.1） | 是 / 否 | 标题栏 5 个控件 + 一行核心状态 |
| `main` | 胶囊（capsule） | 由吸附引擎按轨道方向给出 | 同左 | 否 | 尺寸由 `dock_geometry` 决定，不参与本规范 |
| `widget-*` | 桌面微件 | 220–560 × 120–640 | 220×120 | 是 / 否 | 内容自适应，已独立 |
| `capture` / `notification` / `context-menu` / `tab-hint` | 辅助 | 固定 | 固定 | 否 | 不适用本规范 |

### 2.1 为什么极简下限是 264×112（而不是原 240×96）

极简窗口的高度/宽度由 `mode_min_size()` 决定，而模式切换时窗口尺寸会先落到最小值再设目标值。

2026-11-16 在真实渲染里逐档压缩取证（`tmp/layout-spec/shots/main-*.png`）：

| 尺寸 | 结果 |
|---|---|
| 240×96 | **破损**：「待办」被挤成竖排两行、计数与任务数裁切、标题栏 caret 与窗口按钮拥挤、右侧工作台按钮被切 |
| 260×120 | 通过（贴合下限，无余量） |
| **264×112** | **通过**（当前下限：宽度留 4 DIP 余量给不同字体度量，高度按标题栏 41 + 内容行 71 收口） |
| 272×128 / 280×140 | 通过 |

因此把 `main` 的极简最小尺寸从 240×96 上调为 **264×112**，常量集中在
`window_layout::MAIN_MINIMAL_MIN_WIDTH/HEIGHT`，`mode_min_size()` 与 `tauri.conf.json`
（`minWidth/minHeight`，覆盖窗口创建到首次模式命令之间的空窗期）共用同一份口径。

> 极简形态只承担「一眼看清 + 一键进入」，不因缩小而追加控件；空间不足时按 §5.3 隐藏低优先项，
> 不压缩命中区。

## 3. 动态适配：可用区、DPI、多显示器

### 3.1 判据是「工作区」而不是「分辨率」

```text
工作区 = Monitor::work_area()（已扣除任务栏/停靠栏）→ 换算成 DIP
可用宽 = 工作区宽 - 2 × 12 DIP（安全边，避免贴边/圆角裁切）
可用高 = 工作区高 - 2 × 12 DIP
```

### 3.2 三级收敛公式

```text
最小宽 = 960     若 可用宽 ≥ 960
       = 可用宽   若 720 ≤ 可用宽 < 960
       = 可用宽   若 可用宽 < 720（低于布局下限，仍以可用区为准，保证窗口开得出来）
默认宽 = clamp(1200, 最小宽, 可用宽)
```

高度同理：`600 / 480`。关键性质：

1. **正常屏幕恒为 960×600**：1080p/1440p/4K 在 100%–200% 缩放下工作区 DIP 都 ≥ 960×600
   （125% 的 1920×1080 = 1536×864 DIP；150% = 1280×720；200% = 960×540 → 高度降级为 516，
   宽度仍 960）。
2. **小屏自动降级**：1366×768@125% = 1093×614 → 可用区 1069×590，高度降到 590，窗口仍完整。
3. **绝不超过可用区**：`默认尺寸 ≤ 可用区`、`最小尺寸 ≤ 可用区`，因此不会出现「最小尺寸
   大于屏幕、窗口开不出来」。这种情况下由内容响应式（§6）接管，而不是继续压缩控件。

### 3.3 跨屏与缩放变化

- 窗口创建时按**主显示器**工作区算一次（`plan_for_monitor`）；
- 恢复保存几何后，按**窗口当前所在显示器**再算一次并收敛（`apply_window_metrics`）；
- 拖动跨屏 / 系统改缩放时，监听 `Moved` 与 `ScaleFactorChanged`，以
  「工作区矩形 + 缩放比」为签名判断是否真的换了显示器；同一屏内移动**不重算**（150ms 节流），
  避免拖动过程中反复改窗口约束；
- 最大化/最小化期间不改约束（此时矩形由系统决定）。

代码入口：`src-tauri/src/window_layout.rs`（唯一事实源）、`project_workspace_window.rs`
（创建 / 恢复 / 监听）。

### 3.4 模式切换

- `main` 的形态切换走 `mode_min_size(mode)`：**先设最小尺寸，再设目标尺寸**，避免中间态被旧最小值
  卡住（从完整面板切极简时窗口能真的变小，反之不会先被极简最小值钳制）。
- `workspace` 与 `main` 的最小尺寸互不影响：`main` 的尺寸策略只由 `commands::system` 决定，
  不读取工作台常量；工作台也不会因为主窗进入极简而改自己的约束。

## 4. 原生最小尺寸的落点（不可只靠 CSS）

- Tauri 创建窗口时用 `.min_inner_size(plan.min.width, plan.min.height)`（逻辑尺寸）；
- 运行时调整用 `win.set_min_size(Some(LogicalSize))`；
- CSS 的 `min-width` 只约束**内容**，无法阻止用户把窗口拖到更小，也不能阻止系统缩放，
  因此不允许用它替代原生约束；
- 工作台 `decorations(false)` + `transparent(true)`：最小尺寸按**客户区**（inner size）计算，
  与无边框窗口的可视区域一致；`window_shape` 的区域裁剪不会改变客户区尺寸。

## 5. 顶栏空间分配（窗口 chrome）

顶栏横跨整个窗口，因此按**窗口宽度档位**（不是内容容器宽度）分配。
档位定义在 `src/lib/layoutMetrics.ts`，CSS 在 `workbench.css` 末尾「窗口档位与顶栏空间分配」。

| 档位 | 窗口宽（DIP） | 行为 |
|---|---|---|
| `full` | ≥ 1100 | 全部控件内联：品牌名 + 项目选择器 180 + 搜索（含快捷键提示）+ 创建（带文案）+ 右栏开关 + 外观工具组 + 窗口按钮 |
| `compact` | 900–1099 | 收起右栏；隐藏快捷键提示/品牌名/创建文案；项目选择器 170；搜索可缩到 132 |
| `narrow` | 780–899 | 外观工具组（明暗/视觉主题/置顶）收进「更多」菜单；项目选择器 150；搜索 200 起缩 |
| `cramped` | < 780 | 顶栏换行，项目选择器独占第二行（仅小屏降级窗口出现） |

不变量：

1. **图标按钮与窗口控制永不被压缩**：`flex: 0 0 auto` + 固定命中区 28–30px；
2. **项目选择器有最小宽度**（132px，cramped 档为第二行全宽），不截断成几条线；
3. **退出顺序**：品牌名 → 快捷键提示 → 创建文案 → 外观工具组 → 换行；
4. **任何退出都保持可点**：外观工具组进「更多」菜单，菜单项与内联按钮共用同一份逻辑
   （`workbenchTitlebarItems.tsx` / `useWorkbenchPin.ts`），不存在第二个设置写入管道；
5. 窗口变宽后按同一顺序**自动恢复**，不做记忆/手动展开；
6. 顶栏 `data-tauri-drag-region="deep"` 的拖动语义、快捷键与事件不变。

> 2026-11-20：按顶栏走查收紧项目选择器：210→180（compact 190→170、narrow 170→150），
> 最小宽度 150→132；弹层与触发器等宽，不再声明 `menuMinWidth=240`。

### 5.1 左侧导航

- 导航宽由用户设置（72–320，`WORKBENCH_NAV_WIDTH_MIN/MAX`），窗口变窄时**只压缩内容区**，
  不回写用户宽度；72px 即图标轨（2026-11-20 从 96 收紧，96 仍是合法宽态）；
- 图标固定 18×18（容器 20），`flex: none`，任何宽度下都不缩放、不消失；
- 宽度只有两个稳态：图标轨（72）或**≥ 名称完整显示所需宽度**（实测，见 `WorkbenchShell` 的
  `measureWorkbenchNavLabelFit`）；拖拽松手/键盘调整后低于名称所需宽度一律吸附到 72，
  不留被省略号遮住的半截名称；量不到时回退 180px 兜底阈值；
- 图标轨保留 tooltip 与 aria-label（徽标计数并入名称 tooltip），手柄与 × 悬停/聚焦才显现；
  两者改为行内浮层（18/20px），命中区外扩，不占固定轨道，图标始终水平垂直居中；
- 图标 + 文字档文字单行省略；纯图标档（< 名称所需宽度）整列收窄为图标轨；
- 行高 40px，行整行可点（命中区覆盖图标与文字），拖拽排序/隐藏/恢复的命中区不变；
- 导航列宽变化通过 `grid-template-columns: var(--wb-nav-width) 0px minmax(0,1fr)` 自然带动内容区
  （拖拽条以负边距叠在边界上，不占独立列），不做 JS 重排。

### 5.2 主内容区

- `.wb-workarea / .wb-content / .wb-route / .wb-route > *` 全部 `min-width: 0`；
- 内容区唯一的滚动责任方是页面自己的滚动容器（`.wb-content` 或页内 `page-scroll`），
  外壳不出现横向滚动条；
- 表格横向溢出时在表格容器内部滚动（`overflow-x: auto` + `min-width: 0`），不撑破页面；
- 媒体（图片/视频/画布）在页面内 `max-width: 100%`，高度语义不变。

### 5.3 卡片与信息展示

沿用 [ui-responsive-layout.md](ui-responsive-layout.md) 的 `--layout-*` Token 与
`.ui-adaptive-grid`：按**内容容器**宽度给列数（1 / 2 / 3 / 4），宽屏有 `--layout-card-max`
上限，避免单卡无限拉伸；窄内容区优先减少列数、保持图标/标题/状态/操作可读，不整体缩放。

## 6. 与内容响应式的边界

| 场景 | 用哪个宽度 | 原因 |
|---|---|---|
| 顶栏工具收纳、右栏显隐、窗口 chrome | **窗口宽度**（`WINDOW_TIERS` / 媒体查询） | 顶栏与右栏相对窗口定位，与内容容器无关 |
| 页面卡片列数、页内分栏、表格列宽 | **内容容器宽度**（`@container`） | 导航宽度/右栏开合会改变内容宽度，窗口宽度不等价 |
| 组件内部（按钮组、行内标签） | 组件自身宽度 | 与两层都无关 |

禁止：用 `@media` 改页面列数（导航展开后同一窗口宽度会有两种内容宽度）；
用容器查询改窗口 chrome（顶栏不受内容容器影响）。

## 7. 验收口径

窗口尺寸必须**真机**测试（jsdom/单测不能替代）：尺寸 500×900 / 800×600 / 960×600 / 1200×760 /
1440×900 / 1920×1080，DPI 100/125/150/200%，最大化/还原、跨屏移动、模式切换、重启恢复、
可用区不足降级。判定标准见本次任务验收报告（`tmp/acceptance/window-layout-spec-20261116/`）。

### 7.0 窗口生命周期契约（2026-11-22，ADR-0009）

- **托盘唤回不是新的几何来源**：托盘左键/右键「打开完整工作台」、第二实例、启动路径
  共用 `open_or_focus_workbench` 统一创建入口；重建窗口的尺寸/位置/最大化一律由
  `restore_geometry`（`workspace_window_rect` + 内存快照）恢复，显示器变化由
  `window_layout` 收敛。**禁止**为修复唤回问题修改工作台默认尺寸（默认 1200×760 /
  最小 960×600 只随本规范的显示器适配条款变化）。
- **关闭策略不改变几何持久化**：`window_close_behavior = close_window` 走 CloseRequested
  的快照/落库链路；`quit_app` 由 `request_exit` 开头的 `persist_geometry_on_exit` 兜底。
  两条路径共享同一几何存储，不新增第二套。
- 关闭场景的真机判定标准见 [WORKSPACE_CLOSE_ACCEPTANCE.md](WORKSPACE_CLOSE_ACCEPTANCE.md) §4。

已知无法在本机完成的项（单显示器、系统缩放固定 125%）必须写 `ENVIRONMENT BLOCKED`，
不得用「应该/理论上」代替证据。
