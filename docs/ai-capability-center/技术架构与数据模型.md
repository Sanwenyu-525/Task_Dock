# 知识与 AI 能力中心：技术架构与数据模型

> 实施基线：2026-11-18。数据库迁移 v72（能力中心表）+ v73（MCP 能力白名单扩展 `knowledge.read`）+ v74（知识库/Skill 真实绑定、MCP 未知工具确认）+ v75（MCP 能力白名单扩展 `skills.read`）。
> 代码位置：`src-tauri/src/capability/`、`src/components/capability/`、`src/store/useCapabilityStore.ts`。

## 1. 分层与依赖

```
React 组件（src/components/capability/*）
  └─ src/lib/bridge.ts（camelCase IPC 类型与 invoke 封装）
       └─ src-tauri/src/capability/commands.rs（Tauri 命令，参数归一）
            ├─ knowledge.rs   知识库/文档/分块/检索/关联
            ├─ skills.rs      Skill 扫描/解析/导入/风险
            ├─ external_mcp.rs 外部 MCP Server CRUD + stdio 客户端
            ├─ context.rs     上下文配置与装配
            └─ recipes.rs     配方定义与执行
                 └─ Db（唯一写连接 + 只读连接池）/ 文件系统 / 子进程
```

约束：

- UI 不直接访问数据库与文件系统；所有读写经 `bridge.ts`。
- 不新增 npm / cargo 依赖；复用 `rusqlite`、`serde_json`、`regex`、`sha2`、`uuid`、`chrono`。
- 业务校验在 `*_impl` 函数内完成；命令层只做 `State` 注入与默认值。
- 写操作使用 `db.with_conn` 事务；读使用 `db.with_read`。
- 长任务（文件夹导入、重建索引、MCP 连接/调用）使用 `tauri::async_runtime::spawn_blocking`，不阻塞主线程。

## 2. 数据模型（迁移 v72）

DDL 常量：`src-tauri/src/capability/schema.rs::MIGRATION_72`，在 `db::MIGRATIONS` 末尾登记。

### 2.1 知识库

```sql
CREATE TABLE knowledge_bases (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  kind TEXT NOT NULL DEFAULT 'personal'
    CHECK (kind IN ('personal','project','workspace')),
  project_id TEXT REFERENCES workspace_projects(id) ON DELETE SET NULL,
  favorite INTEGER NOT NULL DEFAULT 0 CHECK (favorite IN (0,1)),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_kb_kind ON knowledge_bases(kind, updated_at DESC);
CREATE INDEX idx_kb_project ON knowledge_bases(project_id) WHERE project_id IS NOT NULL;

CREATE TABLE knowledge_documents (
  id TEXT PRIMARY KEY NOT NULL,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  source_kind TEXT NOT NULL
    CHECK (source_kind IN ('file','folder','note','capture','text')),
  source_mode TEXT NOT NULL CHECK (source_mode IN ('reference','imported')),
  source_path TEXT,
  managed_rel_path TEXT,
  mime TEXT NOT NULL DEFAULT '',
  size_bytes INTEGER NOT NULL DEFAULT 0,
  content TEXT NOT NULL DEFAULT '',
  content_hash TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending','indexed','failed')),
  error TEXT NOT NULL DEFAULT '',
  chunk_count INTEGER NOT NULL DEFAULT 0,
  indexed_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_kd_kb ON knowledge_documents(kb_id, updated_at DESC);
CREATE INDEX idx_kd_status ON knowledge_documents(kb_id, status);
CREATE UNIQUE INDEX idx_kd_kb_source ON knowledge_documents(kb_id, source_path)
  WHERE source_path IS NOT NULL AND source_path <> '';

CREATE TABLE knowledge_chunks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  doc_id TEXT NOT NULL REFERENCES knowledge_documents(id) ON DELETE CASCADE,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  ordinal INTEGER NOT NULL,
  start_offset INTEGER NOT NULL,
  content TEXT NOT NULL,
  UNIQUE (doc_id, ordinal)
);
CREATE INDEX idx_kc_doc ON knowledge_chunks(doc_id, ordinal);
CREATE INDEX idx_kc_kb ON knowledge_chunks(kb_id);

CREATE TABLE knowledge_links (
  id TEXT PRIMARY KEY NOT NULL,
  doc_id TEXT NOT NULL REFERENCES knowledge_documents(id) ON DELETE CASCADE,
  target_kind TEXT NOT NULL
    CHECK (target_kind IN ('task','project','note','agent_session','workflow','file')),
  target_id TEXT NOT NULL,
  label TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL,
  UNIQUE (doc_id, target_kind, target_id)
);
CREATE INDEX idx_kl_target ON knowledge_links(target_kind, target_id);
```

设计要点：

- `source_path` 为引用模式绝对路径；导入模式记录来源路径（可空）+ `managed_rel_path`（相对 `<data>/knowledge`）。
- `content` 保存可检索正文（≤2 MiB）；原文件仍是唯一原文。
- `content_hash` 为 SHA-256，用于增量判断与重复检测。
- 文档分块 1200 字符、重叠 200 字符，`start_offset` 用于原文定位。
- 检索 v1 使用分块 LIKE（与全局搜索一致，兼容中文），不引入 FTS5 依赖假设；FTS/Embedding 在 P2 评估。

### 2.2 Skill

```sql
CREATE TABLE capability_skills (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  source_kind TEXT NOT NULL CHECK (source_kind IN ('discovered','imported')),
  source_path TEXT NOT NULL,
  scope TEXT NOT NULL DEFAULT 'global'
    CHECK (scope IN ('global','project','workspace','agent')),
  project_id TEXT REFERENCES workspace_projects(id) ON DELETE SET NULL,
  enabled INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
  risk_level TEXT NOT NULL DEFAULT 'low' CHECK (risk_level IN ('low','medium','high')),
  risk_notes TEXT NOT NULL DEFAULT '[]',
  version TEXT NOT NULL DEFAULT '',
  content TEXT NOT NULL DEFAULT '',
  content_hash TEXT NOT NULL DEFAULT '',
  missing INTEGER NOT NULL DEFAULT 0 CHECK (missing IN (0,1)),
  last_seen_at TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_skill_path ON capability_skills(source_path);
CREATE INDEX idx_skill_scope ON capability_skills(scope, project_id, enabled);
```

- `source_path` 为 Skill 目录绝对路径（不是 SKILL.md 的路径），唯一。
- 发现时 upsert；目录不存在时 `missing=1`，不删除记录（保留用户启停选择）。
- `risk_notes` 为 JSON 数组 `[{kind, detail, file}]`，不含文件正文。

### 2.3 外部 MCP Server

```sql
CREATE TABLE external_mcp_servers (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  transport TEXT NOT NULL DEFAULT 'stdio' CHECK (transport IN ('stdio')),
  command TEXT NOT NULL,
  args_json TEXT NOT NULL DEFAULT '[]',
  env_json TEXT NOT NULL DEFAULT '[]',
  enabled INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
  allow_high_risk INTEGER NOT NULL DEFAULT 0 CHECK (allow_high_risk IN (0,1)),
  status TEXT NOT NULL DEFAULT 'unknown'
    CHECK (status IN ('unknown','ok','failed','disabled')),
  last_error TEXT NOT NULL DEFAULT '',
  server_info_json TEXT NOT NULL DEFAULT '{}',
  tools_json TEXT NOT NULL DEFAULT '[]',
  resources_json TEXT NOT NULL DEFAULT '[]',
  prompts_json TEXT NOT NULL DEFAULT '[]',
  last_connected_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE external_mcp_calls (
  id TEXT PRIMARY KEY NOT NULL,
  server_id TEXT NOT NULL REFERENCES external_mcp_servers(id) ON DELETE CASCADE,
  tool_name TEXT NOT NULL,
  success INTEGER NOT NULL,
  duration_ms INTEGER NOT NULL,
  error TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL
);
CREATE INDEX idx_emc_server ON external_mcp_calls(server_id, created_at DESC);
```

安全约定：

- `env_json` 仅在保存与本地连接时使用；列表接口只返回键名与 `hasValue`，不返回值。
- 调用记录只存工具名、成功、耗时、错误摘要；不存参数、返回正文、环境变量。
- v1 仅支持 stdio；Streamable HTTP 在 P2 评估（需要 TLS 客户端与代理策略）。
- 子进程强制 `CREATE_NO_WINDOW`（`winproc::hidden`），连接 15s、调用 60s 超时，超时强杀并 `wait` 回收。


`config_json`：

```json
{
  "kbIds": ["..."],
  "skillIds": ["..."],
  "mcpTools": [{ "serverId": "...", "toolName": "..." }],
  "taskIds": ["..."],
  "rules": "项目约束/角色说明（纯文本）"
}
```

`steps_json`（配方步骤白名单）：

```json
[
  { "type": "knowledge_search", "kbIds": ["..."], "query": "人物设定", "limit": 5 },
  { "type": "mcp_tool", "serverId": "...", "toolName": "..." , "args": {}, "highRisk": true },
  { "type": "save_note", "title": "配方结果：..." }

```

校验：类型白名单、数组上限 20、字段长度上限、`save_note` 只接受标题；`mcp_tool` 的 `highRisk` 由后端按工具名/描述重新判定，不信任前端。

## 4. Agent 接入（P1）

新增 MCP 资源能力 `knowledge.read`（`mcp/permissions.rs`）：

- 全局授权：可搜索全部知识库、列出知识库。
- 知识库级授权：`resource_id = knowledge_bases.id`，只能检索该库。
- 新工具（`mcp/knowledge_tools.rs`，注册进 `tool_defs`）：
  - `taskdock_list_knowledge_bases`
  - `taskdock_search_knowledge`（query, kb_ids?, limit）
  - `taskdock_get_knowledge_document`（document_id, offset?, max_chars?）
- 返回内容带 `source`（文档标题、路径或笔记 id）与字符偏移；工具返回视为数据，不含可执行指令。
- 未授权返回 `-32002` 语义（`ToolError::Authz`），与既有资源工具一致。

## 5. 错误与失败分类

| 场景 | 错误类型 | 用户可见 |
|---|---|---|
| 参数非法/超限 | `AppError::Validation` | 具体字段与范围 |
| 目标不存在 | `AppError::NotFound` | 对象类型 + id |
| 不支持的格式 | `AppError::Validation` | 「PDF/DOCX 暂不支持，请转为文本」 |
| MCP 启动/连接失败 | 报告 `error` | 原始错误摘要（截断，无密钥） |
| MCP 调用超时 | 报告 `error=timeout` | 超时秒数 |
| 高风险未确认 | `AppError::Validation` | 「该工具可能修改数据，需确认后执行」 |
| 索引失败 | 文档 `status=failed` + `error` | 文档行内提示与重试按钮 |

不吞异常、不把失败包装成空列表；前端统一用 `localizedErrorMessage`/`errorMessage`。

## 6. 性能与资源

- 文件导入：单文件 2 MiB、文件夹 2000 文件/深度 8/总量 32 MiB；逐文件事务，失败单项记录。
- 检索：`LIMIT ≤ 100`，按匹配等级排序，摘要 ≤ 240 字符；不返回全文。
- 上下文装配：总字符上限默认 12000，超出截断并标记 `truncated`。
- 配方：最多 20 步；每步输出记录 ≤ 8 KB；知识检索 ≤ 20 条。
- MCP：单次连接/调用一个子进程；超时强杀；不做常驻与自动重连（P2）。
- 页面：无轮询；切换页签复用已加载数据，显式刷新。

## 7. 安全边界

- 路径：`file_workspace::validate_abs_path` + 禁止控制字符；文件夹扫描跳过符号链接（`file_type().is_symlink()`）。
- 受管副本：文件名由 UUID 生成，目录固定 `<data>/knowledge/<kb_id>`，不接受前端路径成分。
- 删除：引用模式只删记录；导入模式删记录 + 副本；任何路径都不删原文件。
- Skill：只读扫描与正则风险标记；永不执行 Skill 内脚本；导入只复制目录。
- 外部 MCP：返回内容一律作为不可信数据显示；不解析为指令；不自动把输出写入知识库或任务。
- 日志：不记录 token、env 值、调用参数正文、知识正文、完整个人路径（仅记录类型/计数/耗时/错误摘要）。
- 权限：Agent 读取知识必须 `knowledge.read`；外部 MCP 工具不暴露给 Agent（P2 评估）。

## 8. 迁移、备份与兼容

- v72 只新增表与索引，不改既有表；旧库升级通过 `PRAGMA user_version` 追加执行。
- 备份：新表登记进 `BACKUP_TABLES`（如备份模块按清单导出），不改变既有 manifest 版本。
- 删除知识库级联文档/分块/关联；删除项目时 `project_id` 置空（知识库保留，避免误删资料）。
- Skill 记录不随项目删除而删除；`project_id` 置空并保留作用域历史。
- 外部 MCP 记录独立于项目；删除 Server 级联调用记录。

## 10. 第二轮整改（2026-11-18）

本节记录对第一轮验收问题的架构纠偏；历史章节保留，冲突处以本节为准。

### 10.1 知识库来源刷新（P0）

- `reindex_document_impl(db, data_dir, id)` 与 `rebuild_kb_impl(db, data_dir, kb_id)` 不再只读数据库快照。
- `reference` 重新读取 `source_path`；`imported` 重新读取受管副本 `managed_rel_path`；
  `note` / `capture` / `text` 没有外部文件来源，继续使用数据库正文。
- 读取成功：重新解析 → 计算 SHA-256 → 更新 `content/mime/size_bytes/content_hash` →
  删除旧分块 → 重建 → `indexed`。
- 读取失败：删除旧分块、`status=failed`、`chunk_count=0`、`error` 写入
  `[source_missing]` / `[source_unreadable]` / `[source_unsupported]` / `[source_too_large]`
  前缀；不新增状态枚举，兼容既有 `pending|indexed|failed`。
- 测试：`reference_reindex_reads_latest_source`、`rebuild_kb_reads_reference_sources`、
  `reference_reindex_marks_missing_source_as_failed`、`imported_reindex_reads_managed_copy_not_original`。

### 10.2 真实绑定（P0）

- `knowledge_bases.workspace_id`（v74）与 `project_id` 都是真实外键，指向
  `workspace_projects.id`。当前系统唯一的稳定 Workspace 身份就是项目工作空间
  （`workspace_projects`），本轮复用，不新建重复 Workspace 表。
- `personal` 清除全部绑定；`project` 必须有 `project_id`；`workspace` 必须有 `workspace_id`；
  后端 `normalize_kb_binding` 再次校验，不依赖 UI。
- 编辑允许修改类型并重新绑定；UI 在创建/编辑对话框都展示类型与绑定选择器。
- 检索的项目过滤同时匹配 `kb.project_id`、`kb.workspace_id` 与文档的项目关联。

### 10.3 Skill → Agent（P1）

- `capability_skills.workspace_id / agent_id`（v74）为 workspace / agent 作用域提供真实对象；
  `agent_id` 复用 `mcp_agents.id`，不引入第二套 Agent 身份。
- 统一过滤口径 `capability::skills::{SkillAccessContext, is_applicable, list_applicable_conn}`：
  `enabled=1`、`missing=0`，global 全可见，project/workspace/agent 精确匹配；未知 scope fail-closed。
- MCP 工具（`mcp/capability_tools.rs`，需 `skills.read` 全局授权）：
  - `taskdock_list_skills(project_id?, workspace_id?)`
  - `taskdock_get_skill(skill_id, project_id?, workspace_id?)`
  - 不存在与无权限统一返回「Skill 不存在或不可访问」。
- 上下文装配使用同一过滤函数：项目上下文预览不包含 agent 级 Skill；Agent 调用时按真实 Agent 身份匹配。

### 10.4 Context → Agent（P1）

- 新增 `taskdock_get_task_context(task_id, project_id?, query?, max_chars?)`（需 `knowledge.read` 全局授权）：
  1. 读取任务与 `workspace_task_links` 的项目绑定；
  2. 优先使用该项目最新 `capability_contexts`；
  3. 没有配置时使用安全默认：仅项目/工作区绑定知识库 + 当前任务 + 适用 Skill，
     不自动读取全部知识库，不自动绑定 MCP 工具；
  4. 调用 `context::assemble_impl`（保留 query、maxChars、截断、来源清单）；
  5. 返回 `bundle + skills + policy + projectId/contextProfileId`。
- 任务不存在、任务不属于请求项目统一返回「任务不存在或不可访问」，避免存在性 oracle。

### 10.5 Recipe 与 Workflow（P1）

### 10.6 外部 MCP 协议（P0/P1）

## 11. 知识库全局/项目作用域（2026-11-23，Phase 3）

### 11.1 归属分类

- `KnowledgeBase.ownership` 是**派生字段**（不落库），在 `row_to_base` 按 `kind` + 绑定推导：
  - `personal`（无绑定）→ `global`；
  - `project` + `project_id` → `project`；
  - `workspace` + `workspace_id` → `workspaceLegacy`（旧类型兼容展示，不新增迁移）；
  - 其余（项目删除后绑定被 `ON DELETE SET NULL` 置空）→ `unowned`。
- 关键约束：**未归属库绝不能被当成全局库**。全局视图只查 `kind='personal'`，
  `unowned` 单独可查，列表与详情都要显式提示归属丢失，并提供「转为全局 / 归入当前项目」恢复入口
  （走既有 `capability_kb_update`，不自动迁移）。

### 11.2 列表作用域

- IPC `capability_kb_list(query?, kind?, scope?, projectId?)`：
  - `scope` 缺省 = `all`，保持管理界面旧行为；非法值返回 Validation。
  - `global` → `kind='personal'`；`unowned` → `kind IN ('project','workspace') AND project_id IS NULL AND workspace_id IS NULL`；
  - `project` → `project_id=? OR workspace_id=? OR EXISTS(知识文档通过 knowledge_links 明确关联到该项目)`；
    缺 `projectId` 直接 Validation，不做「默认当前项目」猜测。
- 项目视图包含两类来源：该项目拥有的库（含旧 workspace 绑定）与**有文档明确关联到该项目**的全局库；
  其他项目的私有库不会出现（不依赖前端过滤）。
- `list_bases_impl(db, query, kind)` 保留为 `all` 语义，供 `agent_access` 投影等旧调用方使用；
  Agent 入口的收紧属 Phase 4。

### 11.3 项目删除清理

- `knowledge_links.target_id` 无外键，项目删除必须在 `delete_project_tx` 里显式
  `DELETE FROM knowledge_links WHERE target_kind='project' AND target_id=?`，否则残留幽灵引用会被项目视图误判。
- 知识库本身由 `project_id/workspace_id` 的 `ON DELETE SET NULL` 保留（正文、索引、文档数与内容 hash 不变），
  列表转为 `unowned` 等待用户显式恢复。

### 11.4 验证与边界

- SQL 语义用 `tmp/acceptance/global-project-data-scope-phase3/verify_kb_scope.py` 从 `capability/schema.rs`
  原样抽取 DDL 建库验证：A 看不到 B、关联到 A 的全局库可见、pC 删除后残留库只落 `unowned`、
  项目删除清掉链接且重复清理幂等。
- 前端 `KnowledgeSection` 增加作用域切片（全部/全局/未归属/当前项目，无项目上下文则隐藏项目片），
  列表元信息改为归属文案；项目上下文存在时**默认进入项目作用域**（用户显式切换后尊重其选择），
  避免在 A 项目里先看到 B 的私有库；`KnowledgeSection.test.tsx` 覆盖参数下推与未归属恢复。
- 未覆盖：`search_impl` / `assemble_impl` 的项目收紧、Skill 作用域与 Agent 全入口授权仍是 Phase 4 范围。
