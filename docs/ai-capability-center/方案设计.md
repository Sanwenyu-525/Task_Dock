# 知识与 AI 能力中心：方案设计

> 状态：2026-11-18 实施版（与代码同源，实现偏差以代码与验收报告为准）
> 范围：知识库、Skill 管理、MCP 管理、项目上下文、能力配方，以及它们与 Agent / 工作台 / 搜索 / 笔记的整合。
> 非目标：不新建第二套笔记系统、不新建第二套搜索系统、不推翻既有 TaskDock MCP Server、不在本阶段引入外部 Embedding 服务。

## 1. 背景与目标

TaskDock 已有任务、项目、Agent 监控、工作流、笔记、全局搜索、文件工作区、采集箱、MCP Server 等资产，但知识与 AI 能力分散在设置页、文件系统和各 Agent 配置中，无法回答三个问题：

1. 完成任务需要哪些资料，资料在哪里、是否已索引、是否仍然有效？
2. 有哪些可复用的 Skill，适用哪个项目/工作区，是否包含高风险脚本？
3. 外部 MCP Server 能提供什么工具，当前是否可用，调用是否被授权与留痕？

本方案在统一工作台内建设「知识与 AI 能力中心」，形成闭环：

```
资料采集 → 知识沉淀 → Skill 选择 → MCP 工具调用 → Agent 执行
        → 结果沉淀 → 更新项目上下文 → 持续推进任务
```

设计原则：

- **复用优先**：笔记正文、文件读取、路径校验、项目/任务模型、工作流引擎、MCP Server 认证审计均复用既有实现，不复制。
- **单一事实源**：知识与能力元数据只落 SQLite；正文在引用模式下仍归原文件所有。
- **默认最小权限**：Agent 默认看不到任何知识库；外部 MCP 工具默认不执行高风险操作。
- **真实链路**：UI → `src/lib/bridge.ts` → Rust 命令 → SQLite/子进程；无模拟数据、无空壳接口。

## 2. 现状调研（真实代码证据）

### 2.1 Term: MCP Server（TaskDock 作为服务端）

| 能力 | 位置 | 结论 |
|---|---|---|
| stdio 子命令 / loopback bridge | `src-tauri/src/mcp/protocol.rs`、`mcp/bridge.rs` | 已实现；`--mcp-server` 逐行 JSON-RPC，HTTP loopback + Bearer 常量时间比较 |
| 协议子集 | `mcp/protocol.rs` | `initialize` / `ping` / `tools/list` / `tools/call`；未知方法 `-32601` |
| Agent 身份与 token | `mcp/auth.rs`、迁移 v37 的 `mcp_agents` | token 明文只返回一次，库内 SHA-256 |
| 资源能力授权 | `mcp/permissions.rs`、迁移 v64/v73/v75 | `tasks.read/write`、`notes.read/write`、`workflows.read`、`workspace.read`、`knowledge.read`、`skills.read` |
| 工作区根目录 | `mcp/permissions.rs`、`mcp_workspace_roots` | 绝对路径 + canonicalize，拒绝 UNC |
| 审计 | `mcp/audit.rs`、`mcp_audit_log` | 每次调用留痕，写工具有 `request_id` 幂等重放 |
| 诊断 | `mcp/diagnostics.rs` | 真实探测 bridge/传输文件/工具注册表/数据库/身份 |
| 设置页 UI | `src/components/settings/McpAccessSection.tsx` | Agent、token、scope、项目授权、能力、根目录、审计、诊断均已可视化 |

**结论**：TaskDock 作为 MCP Server 的能力完整，本方案只做「统一入口整合」和「知识能力挂载」，不重写认证、授权、审计。

### 2.2 笔记、搜索与文件

| 能力 | 位置 | 复用方式 |
|---|---|---|
| 笔记 CRUD / 置顶收藏 / 任务关联 | `src-tauri/src/notes/store.rs`、`commands/notes.rs` | 知识库「从笔记导入」直接读 `notes` 表，不复制笔记系统 |
| 全文搜索 | `src-tauri/src/global_search/mod.rs`（LIKE + 匹配等级） | 新增 `knowledge` 分类复用同一命令与排序口径 |
| 文件读取与路径校验 | `file_workspace::validate_abs_path`、`read_text_preview` | 知识文档导入复用绝对路径校验与字节上限 |
| 采集箱 | `quick_capture_items`（`quick_capture/store.rs`） | 「从收集箱导入」按 id 读取正文 |
| 文件工作区 | `src-tauri/src/file_workspace/` | 只引用路径，不复制文件树 |

### 2.3 Agent、工作流与工作台

| 能力 | 位置 | 结论 |
|---|---|---|
| Agent 会话/事件/统计 | `src-tauri/src/agents/`、`src/components/agents/` | 上下文结果可关联会话 id，不复制会话数据 |
| 工作流引擎 | `src-tauri/src/workflows/engine.rs` | 步骤白名单为导航/建任务/场景/恢复现场；**不直接承载配方步骤**。第二轮起知识/MCP/笔记步骤统一走 `capability/steps.rs` 公共执行器，Workflow 如需同类步骤应调用同一执行器 |
| 统一工作台 | `src/workbench/WorkbenchShell.tsx`、`navigationRegistry.ts` | 新页面只注册一个左侧入口，不新增一级导航群 |
| 设置页 | `src/components/settings/SettingsPanel.tsx` | MCP Server 管理保留原位，能力中心提供统一视图与外部 Server 管理 |

### 2.4 缺失能力

1. 知识库数据模型、索引、检索、知识关联（无）。
2. Skill 发现/解析/作用域/风险检查（无；仓库只有用户级 `.agents/skills` 目录约定）。
3. 外部 MCP Client、工具/资源/Prompt 发现、可视化调用（无；现有仅有 Server 方向）。
4. 项目上下文配置与交付（无）。
5. 能力配方（无；工作流步骤白名单不含知识/MCP）。
6. 知识分类的全局搜索（无）。

### 2.5 架构与安全限制

- `db::MIGRATIONS` 只能追加；本方案追加 v72，DDL 放在 `capability/schema.rs`，避免继续膨胀 `db/mod.rs`。
- 现有依赖不含 PDF/DOCX 解析器；**不新增依赖**，PDF/DOCX 明确返回「不支持」而不是假装成功。
- 外部 MCP Server 的 stdio 子进程属于高风险管理面：必须有超时、强杀、并发上限、日志脱敏。
- 没有操作系统凭据库封装；v1 不存储任何第三方密钥/令牌，stdin/env 中的敏感值仅保存在本机 SQLite，并在 UI 明示风险。

## 3. 产品架构

### 3.1 模块职责与数据归属

| 模块 | 职责 | 数据归属 |
|---|---|---|
| Knowledge Base | 知识库、文档、分块、索引状态、关联 | `knowledge_*` 表；引用模式正文仍在原文件 |
| Skill Manager | 发现、解析、导入、启用、作用域、风险 | `capability_skills` 表 + 受管目录 `<data>/skills` |
| MCP Manager | Server 端统一视图 + 外部 Server 生命周期/能力快照 | 既有 `mcp_*` 表 + `external_mcp_*` 表 |
| Context Manager | 项目上下文配置与装配 | `capability_contexts`；装配结果不落库 |
| Capability Recipes | 配方定义与运行记录 | `capability_recipes` / `capability_recipe_runs` |
| Agent Integration | 通过 MCP 工具暴露知识检索（授权后） | 复用 `mcp_agent_capabilities`，新增 `knowledge.read` |
| Permission & Audit | 统一授权、调用留痕 | 复用 `mcp_*`；外部调用写 `external_mcp_calls` |
| Diagnostics | 索引失败、连接失败、配方失败可定位 | 复用诊断中心入口 + 各模块状态字段 |

### 3.2 模块调用关系

```
CapabilityCenterPanel（工作台页面）
  ├─ KnowledgeSection ──> capability_knowledge_* 命令 ──> knowledge::* ──> SQLite
  ├─ SkillsSection ─────> capability_skill_* 命令 ─────> skills::* ─────> 文件系统 + SQLite
  ├─ McpSection ────────> mcp_* 既有命令 + capability_mcp_*（外部）──> external_mcp::*（stdio 子进程）
  ├─ ContextSection ────> capability_context_* ──> context::*（调用 knowledge 检索 + skills 列表）
  └─ RecipesSection ────> capability_recipe_* ──> recipes::*（knowledge 检索 / MCP 调用 / 笔记落盘）
```

共享：

- 知识检索函数 `knowledge::search_impl` 同时服务 UI、上下文装配、配方步骤、MCP 知识工具。
- MCP 调用函数 `external_mcp::call_tool_impl` 同时服务 UI 测试面板与配方步骤。
- 所有写操作经过同一 `Db` 写连接与事务；不引入第二套数据库。

### 3.3 权限与确认

| 场景 | 规则 |
|---|---|
| Agent 读知识 | 需要 `knowledge.read` 全局或知识库级授权；无授权返回明确拒绝 |
| Agent 写知识 | 本阶段不开放写工具；Agent 结果由用户确认后导入 |
| 外部 MCP 工具执行 | 仅 `enabled` 的 Server；高风险工具（名称/描述含 write/delete/exec 等）需 `confirmed=true` 或 Server 显式允许 |
| 配方执行 | 含高风险 MCP 步骤时整次执行必须 `confirmed=true` |
| 删除知识库/文档 | 只删索引与受管副本；引用模式原文件永不删除 |
| Skill 脚本 | 只扫描与标记，不执行任何 Skill 脚本 |

### 3.4 避免重复

- 知识库不提供富文本编辑器：查看原文 + 外部打开；需要编辑时跳转笔记或原文件。
- 搜索不新建搜索命令：全局搜索新增 `knowledge` 分类，能力中心内提供知识库内检索。
- 配方不新建第二套执行引擎：知识检索 / MCP 调用 / 保存笔记统一由 `capability/steps.rs` 执行；配方只保存模板、参数、整次确认与运行记录。既有工作流（导航/建任务/场景）职责不变，后续如需把能力步骤暴露为工作流步骤，应复用同一执行器，不复制逻辑。
- MCP 不新建服务端：Server 侧状态、Agent、token、审计、诊断均读取既有表与命令。

## 4. 关键流程

### 4.1 资料采集 → 知识沉淀

1. 用户选择知识库 → 导入文件/文件夹/笔记/收集箱/文本。
2. 后端校验路径（绝对路径、控制字符、大小上限），按扩展名白名单解析文本。
3. 引用模式只记录路径；导入模式复制到 `<data>/knowledge/<kb_id>/<uuid>.<ext>`。
4. 写入 `knowledge_documents`（pending）→ 分块写入 `knowledge_chunks` → 状态 `indexed`；失败写 `failed` + 原因。
5. 文件夹导入按「文件数/深度/单文件大小」上限执行，返回 skipped 明细；不阻塞 Tauri 主线程（命令 `async + spawn_blocking`）。

### 4.2 检索 → 上下文 → Agent

1. 用户在上下文配置中绑定知识库、Skill、MCP 工具、任务。
2. 「预览装配」按查询检索知识（标题+分块），列出启用 Skill 与允许工具，给出字符估算与来源。
3. 未来 Agent 启动任务时通过 MCP 工具 `taskdock_search_knowledge` / `taskdock_get_knowledge_document` 获取授权内容与来源。
4. 执行结果由用户确认后再导入知识库（本阶段不自动写入）。

### 4.3 外部 MCP Server 生命周期

```
新增 Server → 保存配置（不连接）→ 测试连接
  → spawn 子进程（stdio）→ initialize → tools/list / resources/list / prompts/list
  → 快照落库 → 关闭子进程
调用工具 → 新建短连接 → initialize → tools/call（超时/取消）→ 关闭 → 写调用记录
```

失败分类：启动失败 / 初始化失败 / 协议错误 / 超时 / 工具错误；原样返回可读原因，不伪造成功。

## 5. UI / 交互

- 入口：统一工作台左侧导航新增「能力中心」（`capability`），归入「规划」分组，不新增一级导航群、不占 Ctrl+数字。
- 页面结构：`WorkbenchPageHeader` + 五个分段页签（知识库 / Skill / MCP / 上下文 / 配方）。
- 三栏密度：左列表（可筛选）—中详情/操作—右状态/来源；窄内容区按容器查询降级为单栏。
- 统一组件：`Select`、`SearchField`、`Dialog`、`ConfirmDialog`、`Switch`、`StatusBadge`、`EmptyState`、`DropdownMenu`。
- 状态：加载、空、失败、部分成功（导入 skipped）均有明确文案；不以颜色作为唯一状态表达。
- MCP 工具返回视为不可信文本：只展示、复制，不自动执行其中内容。
- 移动端：本阶段只提供知识检索/查看与 MCP 状态查看的接口基础；不移植 Skill 编辑器与 JSON 调试器。

## 6. 性能与可靠性

- 文件夹导入上限：2000 个文件、深度 8、单文件 2 MiB 文本、总量 32 MiB；超限逐项 skipped。
- 检索：按知识库/来源/项目过滤 + `LIMIT`；摘要按字符边界截断；不在 UI 线程做文件 IO。
- 索引：按内容哈希判断增量；手动「重建索引」；失败可重试。
- MCP：连接/调用均有超时（连接 15s、调用 60s）、进程强杀、单次调用不并发；不保留常驻子进程（v1 权衡，避免孤儿进程）。
- 无轮询：页面挂载读取一次 + 用户操作后刷新；MCP 状态不做定时探测。

## 7. 分期与遗留

- P0：知识库 CRUD/导入/索引/检索/关联/删除语义；Skill 发现/详情/启停/导入/风险；外部 MCP stdio 连接与工具调用；上下文配置与装配；配方定义与执行；工作台 UI。
- P1：全局搜索知识分类、MCP 知识工具（Agent 授权读取）、Skill 作用域与项目绑定、配方导入导出。
- P2：Streamable HTTP、资源/Prompt 实际读取、PDF/DOCX 解析、Embedding/向量检索、移动端采集与审批、OS 凭据库。

遗留项必须在验收报告中列出，不得标记为已完成。
