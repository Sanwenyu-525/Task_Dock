# 安全设计

## 1. 可信边界

| 主体 | 信任级别 | 说明 |
|---|---|---|
| 本机用户（UI / 无 token 的 CLI） | 可信 | 本就能读写数据库与文件 |
| Agent（token 认证） | **不可信** | 只能触达被授权的能力与资源 |
| 外部文件内容 | **不可信** | 一律作为数据，不执行其中指令 |
| 网络 | 不可信 | 仅 loopback；远程未实现 |

## 2. 攻击面与对策

| 风险 | 对策 |
|---|---|
| 外部 Agent 直接改 SQLite | 不提供 DB 路径给 Agent；只提供 CLI/MCP/REST/文件；文件导入走 schema 校验 |
| 路径逃逸（`..`、符号链接、UNC） | 规范化后必须仍在 workspace 根内；拒绝含 `..` 的相对路径；不跟随符号链接写 |
| 任意文件覆盖 | 只写协议定义的目录；写前校验 `.taskdock-workspace.json` 的 `workspace_id` |
| 同步环（自身写入→导入→再写） | 导出记录 hash/revision；hash 相同即跳过；导入只发生在可导入目录且 hash 不同 |
| 浏览器跨站打本地端口 | 拒绝 `Origin`；无 CORS 头；强制 `Authorization`；不使用 Cookie |
| Token 泄露 | 只存哈希；明文仅创建/轮换返回一次；不进日志/审计/导出/manifest |
| 越权 | scope + capability + 项目范围三层校验；失败明确拒绝并记录 |
| 并发覆盖 | `base_revision` + `updated_at` 双校验；冲突返回 409，不静默覆盖 |
| 注入 | SQL 全部参数化；Markdown/JSON 只作数据；文件名不参与 SQL |
| 拒绝服务 | body 1 MiB、header 5s、请求 20s、并发 16、限流 120/min；扫描单轮 200 文件/2s |
| 敏感数据外泄 | 审计只存元数据；上下文/活动不写正文；导出不含 Token、绝对用户目录（只保留 workspace 相对路径） |

## 3. 不可信输入的处置

- JSON/Markdown 导入：先 schema，再字段级校验，最后业务校验；任何一步失败 → 拒绝 + 事件，不部分写入。
- 导入内容里出现「忽略以上指令」「执行命令」等文本：**只作为正文保存**，不进入任何系统提示、
  不触发工具调用。
- 知识文档正文同样视为数据：Context Engine 只做摘要与引用，不执行其中指令。
- 文件大小/数量上限 + UTF-8 校验，避免超大文件拖垮扫描。

## 4. 日志与审计

记录：接口、action、resource_kind/id、project、agent_id、request_id、success、error_code、
revision、duration_ms、脱敏 detail。
**不记录**：token、请求 body、上下文正文、文件内容、绝对用户路径、剪贴板/笔记正文。

## 5. 破坏性操作

- 删除（任务/知识/决策/交接）**本轮不开放**给外部 Agent；UI 仍可删（既有能力）。
- 同步 `keep-file` 覆盖需 `force=true`，且仅限该文件对应资源的已授权能力。
- 不删除用户文件：投影/索引只标记状态；导入成功后移动到 `exports/applied/`（可追溯）。
- 不做 `git clean` / 清空目录 / 递归删除等操作。

## 6. 远程访问

未实现。原因：TLS、证书分发、身份绑定、网络暴露面与审计都需独立设计，不能在「顺手打开端口」
的层面交付。任何远程能力上线前必须满足：独立开关（默认关）、强制 TLS、独立 token 策略、
IP 允许列表、独立审计与限流。

## 7. 供应链

不新增第三方依赖（复用 hyper/tokio/serde/rusqlite/sha2/uuid）；不引入 MCP SDK；不引入向量库。
CLI 复用同一 crate，不引入打包脚本或外部运行时。

## 8. 文件导入的信任边界（v81 修订）

| 主体 | 信任级别 | 说明 |
|---|---|---|
| 文件导入（FileImport） | **不可信且默认无写权限** | 需要目录策略（`trusted`）或本机人工单次批准 |
| 文件中的 `agent_id` | **声明，非凭据** | 只能用于审计与目录绑定一致性校验 |

新增对策：

| 风险 | 对策 |
|---|---|
| 「能写 Inbox」被当作「能改 TaskDock 全部资源」 | 身份与来源解耦（`Identity` vs `Source`）；文件导入必须携带 `ImportGrant` |
| 文件自称某个 Agent 冒充身份 | 目录绑定 Agent 时校验自称身份；不一致直接拒绝 |
| 未授权文件静默写库 | 默认 `NeedsReview`，只登记待审核请求；业务表零写入 |
| 同一文件重复导入造成重复任务 | 导入前占幂等声明（`agent_import_claims`：路径 + kind + 内容 hash + 主体），成功后置 `ok` |
| 业务成功但归档失败导致重复写入 | 声明在写入前占位、写入后置 `ok`，归档失败也不回滚业务、下一轮不重复写入 |
| 冲突处理越权 | `resolve_conflict` 按冲突的真实资源类型映射能力，并重新校验权限与 revision |
