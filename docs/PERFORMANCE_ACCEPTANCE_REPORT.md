## 2. 改动前问题与逐文件改动（v0.4 → v0.5）

### 2.1 改动前（commit e31cc91）的真实问题

| 位置 | 改动前行为 | 后果 |
|---|---|---|
| `src-tauri/src/agents/http_ingest.rs` | `tiny_http` 阻塞式服务器，逐请求串行处理；无请求体上限、无请求超时、无并发上限 | 一个慢客户端可占住接收线程；大批量上报没有背压语义 |
| `src-tauri/src/agents/mod.rs` | `ingest_batch` 在**每个事件**上调用 `after_ingest`；后者发一次 `agent-changed`、刷新一次托盘、逐条发系统通知 | 100 条事件 = 100 次前端快照请求 + 100 次托盘刷新；高频事件下 UI 与托盘被打爆 |
| `src-tauri/src/agents/mod.rs` | 每个事件一个 SQLite 事务（`ingest_core` 逐条提交） | 批量写入被放大为 N 次 fsync；5,000 条需 21.6 秒（见 §4.6） |
| `src/App.tsx` + `src/store/useAgentsStore.ts` | `onAgentChanged(() => loadAgents())`：每个事件直接 `agentSnapshot()` 全量拉取，无节流、无单飞、无脏标记 | 事件风暴下前端请求数线性放大，与后端写入互相拖慢 |
| `src-tauri/src/agents/file_drop.rs` | 轮询目录，读所有文件；无单文件大小、单轮文件数、单文件事件数上限；失败文件无隔离 | 一个超大/半写文件可造成长时间阻塞或内存峰值 |
| `src-tauri/src/agents/hooks_install.rs` | 为每个 Hook 生成 PowerShell `.ps1` 并以 `powershell -File` 启动 | 每个事件启动一次 PowerShell，进程开销远大于事件本身；Agent 侧易感知卡顿 |
| `src-tauri/src/db/mod.rs` | 单一 `Mutex<Connection>`，读写共用 | 历史/快照查询与写入互相排队；长查询会阻塞接入 |
| `src-tauri/src/agents/` | 无事件保留/归档、无性能诊断、无 keyset 分页 | 事件表无限增长；历史面板只能截断最近 N 条 |

### 2.2 改动后

- 所有接入通道统一进入 `agents/pipeline.rs` 的**有界队列**（默认 1024）→ 250ms 合并窗口
  → 单事务批处理（默认 ≤100 条）；关键状态永不合并，队列满时返回可重试错误；
  非关键 `running` 在同一 `source + instance + session + run + transport` 内合并/计数采样。
- HTTP 改为 hyper 异步：并发/在途上限、5s 头/体超时、20s 总超时、64KiB 体上限、
  429/503 + `Retry-After`、批量全成功/全失败；鉴权与 `dedupe_key` 幂等语义不变。
- 文件投递增加稳定文件判定（mtime > 300ms、排除 `.tmp/.partial`）、单文件 4MiB、
  单轮 200 文件/16MiB、失败目录 + 指数退避 + 手动重试。
- Hook 改为原生 CLI（stdin ≤1MiB，连接 700ms / 读写 1200ms），HTTP 失败原子回退文件；
  DSH/OpenCode 插件模板改为有界队列 200、单并发、2.5s AbortController、指数退避、`unref()`。
- 前端改为**事件驱动调度器**：critical 100ms / normal 400ms 节流 + 单飞 + 脏标记追赶 +
  隐藏窗口不刷新 + 失败退避；历史面板 keyset 分页（100 条/页），刷新增量合并。
- SQLite：WAL + 1 写连接 + 3 只读连接（`query_only=ON`）；补充事件/通知/轮次/会话索引；
  保留策略只清理可重建的过程事件（受保护状态永不自动删除），删除前先写 JSONL 归档
  （临时文件 + fsync + 原子 rename），归档失败则本轮不删除。
- 托盘与通知按批聚合：每批一次广播、一次托盘刷新、最多 3 条系统弹窗 + 摘要；
  进度类 `running` 不触发系统弹窗。
- 新增 `performance_diagnostics`（受设置项控制）与前端 `getAgentRefreshMetrics()`，
  队列深度、合并/采样/拒绝、接入/写库分位、SQLite 读延迟、读池规模均可观测。

### 2.3 架构对比

```
v0.4：HTTP(阻塞串行) / 文件 / Hook(每事件 PowerShell) ──► 逐事件 ingest_core 事务
                                                        └─► 每事件广播 + 托盘 + 通知
     前端：每个 agent-changed → 全量快照

v0.5：所有通道 ──► 有界队列(1024) ──► 合并窗口(250ms) ──► 单事务批处理(≤100)
                                                        └─► 每批一次：广播 + 托盘 + ≤3 通知
     前端：事件 → 调度器(节流/单飞/脏标记/隐藏跳过) → 至多 1 在途 + 1 追赶快照
     读路径：3 个只读连接；写路径：单写连接 + WAL
```

## 4. 后端管线（A–E + 基线）

测试入口：`src-tauri/tests/ingest_perf.rs`（ignored，手动运行）。
全部使用真实 `IngestPipeline`、真实 `ingest_core` 事务与真实 SQLite；
**不含 WebView2/Tauri 窗口与托盘 UI**（`backend_only = true`）。

驱动节拍按 Agent 独立计时。v0.5 发现并修复了一个**测量缺陷**：Windows 定时器粒度约 15.6ms，
