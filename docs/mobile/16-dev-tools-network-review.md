# 16 · 开发者工具网络边界与 API 调试安全评审

> 2026-11-16 第十一轮。本文是「API 调试」真实发送能力的**独立网络安全设计评审**记录。
> **结论：未批准**。在评审通过并落地通用 HTTPS 客户端之前，移动端不提供真实发送，
> UI 明确禁用并说明阻塞原因；只交付离线请求编辑、校验、cURL 导入导出、历史与手动响应查看。
> 本文不是「已通过」的安全证明，也不把离线能力包装成联网能力。

## 1. 范围与非目标

范围（若未来批准）：

- 用户在手机上主动发起的一次性 HTTPS 请求（GET/POST/PUT/PATCH/DELETE）；
- 请求由用户逐次确认，不进入后台队列、不参与设备同步；
- 响应只用于当前页面查看，默认不持久化正文。

非目标（明确不做）：

- Postman Collection / 环境变量 / 测试脚本 / 压测 / WebSocket / GraphQL IDE / OAuth 全流程；
- 用 API 调试通道代替 TaskDock 配对、同步、文件互传；
- 把任意第三方证书信任根写进现有 `modules/secure-http`。

## 2. 现有传输体系与为什么不能复用

| 模块 | 用途 | 信任模型 |
|---|---|---|
| `modules/secure-http` | 桌面端配对、同步、文件互传 | TLS-only；自定义 `X-TaskDock-SPKI` 校验；首次配对由二维码/深链预置指纹；缺指纹 fail-closed |
| 未来通用 HTTPS 客户端 | 第三方 API 调试 | 标准系统 CA 证书链 + 主机名校验；不得信任用户提供的任意证书 |

`secure-http` 是**面向单一已知桌面服务**的通道：

- 它的价值在 SPKI 固定与 fail-closed，而不是通用互联网请求；
- 它的信任锚来自配对载荷，不是系统 CA；
- 它没有为「用户输入任意域名」设计证书错误 UI、重定向策略、响应体上限或跨域凭据隔离；
- 为了 API 调试而放宽它的校验（例如首次信任 / 忽略证书错误），会直接削弱配对与同步的安全边界。

因此：**不得修改 `secure-http` 的信任逻辑来迁就 API 调试，也不得把它的实例暴露给工具页。**

## 3. 威胁模型（草案）

| 威胁 | 后果 | 必须的约束 |
|---|---|---|
| 用户被诱导请求明文 HTTP | Token/Cookie 明文上网 | 默认拒绝 `http://`；不提供「仍然发送」开关 |
| 中间人替换证书 | 凭据与响应被窃取/篡改 | 标准证书链 + 主机名校验；证书错误硬失败 |
| 开放重定向到恶意域 | 凭据被带到第三方 | 默认不自动跟随；跨域重定向须用户确认，且剥离 Authorization/Cookie |
| 恶意大响应 | 内存爆掉 / UI 卡死 | 响应体硬上限、流式读取、超限中止 |
| 诊断日志泄漏 | Token 进入日志/崩溃报告 | Header/Query/Body 脱敏；日志只记方法、域名、状态码、耗时 |
| 请求历史泄漏 | 密钥长期留在本机 | 只保存用户显式收藏的请求；保存前脱敏；不存响应正文 |
| 无限重试/自动请求 | 流量与费用失控、被封禁 | 每次发送显式触发；失败不自动重试；无后台队列 |
| 请求混入同步 outbox | 设备同步被污染 | API 请求永不进入 outbox / 同步客户端 |
| 超大请求/无限等待 | 卡死 | URL/Body 输入上限、连接/读取超时、可取消 |

## 4. 若批准：实现基线（待评审，不是现状）

1. **传输库**：优先评估 Android 原生 `OkHttp`（Expo config plugin 或本地 module）而非新增
   通用 JS HTTP 封装；必须使用系统默认 `TrustManager` + `HostnameVerifier`，不得
   `trustAllCerts`、不得覆盖主机名校验。
2. **独立模块**：新建 `modules/api-client`（Name `TaskDockApiClient`），与 `secure-http` 零共享
   TLS 配置；模块只接受 `https://`，`http://` 在 JS 与原生双层拒绝。
3. **请求执行**：用户点击「发送」→ 模块执行一次 → 返回状态码、耗时、响应头、响应体（受上限）。
   `cancel()` 必须真正断开连接；页面卸载/退后台触发取消。
4. **超时**：连接/读取默认 15s / 30s，UI 可调；超时给出分类错误，不自动重试。
5. **重定向**：禁用自动跟随；如未来开放，3xx 只展示 Location，跨域时要求用户确认并剥离凭据。
6. **响应体上限**：建议 2 MB；超出时截断并明确标记，不把截断内容当完整响应。
7. **凭据存储**：不把 Header/Token/Cookie 写进 `tool_requests` 明文。收藏请求保存前脱敏；
   如需保存密钥，走 SecureStore + 用户显式「保存密钥」开关，并且不与请求历史混合。
8. **日志**：`isSensitiveHeader` / query 敏感键 / JSON 密钥字段复用 `apiRequest.ts` 的脱敏规则；
   崩溃与诊断日志不得出现请求/响应正文。
9. **网络策略**：不使用明文 `usesCleartextTraffic=true` 全局放开；如确需局域网 HTTP，
   另立评审与白名单，不复用本模块。
10. **测试**：本地 mock server 覆盖 2xx/4xx/5xx、超时、取消、证书错误、重定向、超大响应、
    敏感头脱敏；真机使用公共 HTTPS 与自签证书反例各一组；不得用「能发出去」替代安全用例。

## 5. 当前交付（已实现，离线）

| 能力 | 状态 | 说明 |
|---|---|---|
| 方法 / URL / Query / Header / Body 编辑 | 已实现 | 纯本地状态；关闭页面不保留未收藏草稿 |
| URL 校验与明文 HTTP 拒绝 | 已实现 | `validateDraft` 返回 `secure=false`，UI 提示且发送不可用 |
| cURL 导入 / 导出 | 已实现 | 支持常见参数，拒绝 `-F`/`-T`/代理/证书文件；只做文本解析 |
| 收藏 / 历史 | 已实现 | SQLite `tool_requests`；敏感 Header 与 JSON 密钥字段保存前脱敏 |
| 手动响应查看 | 已实现 | 用户粘贴文本，JSON 格式化/原始切换；标注「不是本应用发出的响应」 |
| 真实发送 / 取消 / 状态码 / 响应头 | **阻塞** | 未接入任何网络客户端；发送按钮 disabled |
| 超时 / TLS 错误处理 | **阻塞** | 依赖真实客户端，未实现 |
| 请求参与同步 / outbox | 明确禁止 | 不写 outbox，不与配对通道共享 |

## 6. 评审准入清单（全部满足才可解禁）

- [ ] 架构负责人书面批准通用 HTTPS 客户端方案与信任边界；
- [ ] 新增模块不修改 `secure-http` 的 TLS/SPKI/令牌逻辑；
- [ ] 证书链、主机名、明文拒绝、重定向、超时、响应上限、取消均有代码与测试；
- [ ] 敏感信息脱敏测试通过，日志/崩溃报告抽查无明文；
- [ ] 真机反例（自签证书、错误域名、明文 HTTP）均硬失败；
- [ ] 配对/同步/文件互传回归通过；
- [ ] 依赖与 APK 体积影响评估完成并获准。

在以上全部打勾前，`ApiScreen` 保持「离线请求工作台」定位，不显示任何真实响应或成功状态。
