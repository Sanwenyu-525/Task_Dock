## 10. 风险

1. **文件竞争**：并行任务在同一批枢纽文件写入，追加行可能被覆盖。缓解：小步 Edit + diff 复核 +
   最终验收报告列出精确改动；被覆盖时停止并上报。
2. **迁移顺序**：v77 先于 project-hub 的 v78 落地；若他人抢先使用 v77，需重新编号（迁移号是
   `PRAGMA user_version` 单调序列，不能重复）。
3. **AI 能力空窗**：无模型配置时只能本地结构化生成，用户可能误以为「AI 已接入」。缓解：UI
   明确显示 provider 名称与「本地规则生成」标识；外部 provider 未配置返回可读错误。
4. **原型安全**：任何「渲染 Agent 提供的 HTML」都会突破主应用边界。缓解：只接受白名单组件 DSL，
   服务端校验，前端不 eval、不 innerHTML、不加载外部 URL。
5. **审批越权**：Agent 通过 MCP 提交方案后尝试自批。缓解：审批命令只接受 UI Actor；
   `plans.review` 不由 Agent capability 映射。
6. **重复建设**：agent_access/project-hub 未来可能覆盖部分能力。缓解：本文档明确职责边界，
   集成时以「一个能力只保留一个实现」为准，本模块可退化为数据适配层。

## 11. 调研结论

- 本模块**应以「新增业务域 + 复用容器」的方式落地**，而不是改造规划中心或复制 Agent 接入层。
