# 协作与可视化规划中心（Collab Center）

> 模块代号：`collab` · 导航归属：规划中心（`roadmap`）下的「协作」数据源
> 文档基线：2026-11-18 · 状态口径见下表，**未实现的功能不得标记为完成**

## 1. 一句话

把「外部 Agent 提交需求/Bug → AI 生成方案与可视化 → 人工审批 → 拆解开发任务 → 上传证据 → 验收」
固化为 TaskDock 内一条**可追溯、可版本化、可审计**的长期业务链路，而不是一次性画图工具。

## 2. 与既有模块的分工（禁止重复建设）

| 既有模块 / 并行任务 | 职责 | 本模块如何复用 |
|---|---|---|
| 规划中心 `planning_*`（已提交） | 项目/功能/步骤/里程碑/进度历史 | 作为项目容器与任务拆解落点；**不重建项目/功能表** |
| 任务中心 `tasks`（已提交） | 待办、提醒、完成状态 | 方案拆解的任务写入同一 `tasks` 表 |
| Agent 共享工作空间 `agent_access`（**未跟踪，他人任务在途**） | CLI/MCP/REST/文件四入口、身份、授权、审计、版本、交接 | 本模块**只读参考**，不修改其文件；接入层复用其权限与审计语义 |
| AI 能力中心 `capability`（v72/v74） | 知识库、Skill、外部 MCP、上下文、配方 | 项目上下文的知识检索走既有能力；不新建知识库 |
| 项目中枢 `project-hub`（文档 + 领域逻辑，未落库） | 目标驱动的项目执行体系 | 本模块的 `project_id` 当前绑定 `planning_projects`；项目中枢落库后按 `workspace_project_id` 映射迁移 |
| 统一可视化引擎（**本模块新增**） | 图/原型/标注/版本/差异/导出 | 规划中心、能力中心、工作空间共用同一套 Renderer 与文档格式 |

## 5. 不可违反的边界（摘要）

1. 外部 Agent 不能直接把方案标记为「已批准」；审批必须由具备 `plans.review` 的本机用户完成。
2. AI 生成内容一律先校验 Schema 再落库；失败必须记录失败原因，**不得显示成功**。
3. 原型/图表内容是不可信数据，只按白名单组件渲染，**不执行任何模型或 Agent 提供的 JS/HTML**。
4. 版本只增不减；恢复历史版本会生成一个新版本，不删除中间版本。
5. 删除默认改为归档；跨模块共享资源只解绑，不级联删除。
