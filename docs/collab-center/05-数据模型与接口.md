`authoring_mode` 枚举（服务端校验）：`manual | ai_generated | ai_assisted | agent_authored | imported`。

- 文档创建：UI 默认 `manual`；AI 生成 `ai_generated`；MCP Agent `agent_authored`；文件导入 `imported`。
- 文档更新：AI 应用后升级为 `ai_assisted`（若原为 `manual`/`ai_generated`）；版本记录本次实际来源。
- AI 修改被确认应用时，`VisualPatch.aiJobId` 写入版本快照的 `aiJobId`，可从版本追溯到具体 AI Job。
- 图片编辑器支持 40–200% 缩放；裁剪与拖拽/粘贴导入未实现（P1 遗留，已在验收报告登记）。
- `collab_visual_assets` 登记 `BACKUP_TABLES` / `EXTENDED_TABLES`，恢复顺序晚于 `collab_visual_docs`。

## 2. 实体关系

```
planning_projects (既有)
 ├── collab_issues (kind=feature/bug/...)
 │    ├── collab_issue_links (issue↔issue / issue↔plan)
 │    └── collab_evidence (subject=issue/bug/task/plan/visual)
 ├── collab_plans
 │    ├── collab_plan_links (plan↔issue / visual / task / feature)
 │    ├── collab_visual_docs
 │    │    └── collab_visual_versions
 │    └── collab_ai_jobs
 └── collab_audit（按 project 维度）
tasks (既有)
 └── collab_plan_links(kind=task)   ← 只记录方案→任务，不复制任务字段
```

不建立跨表外键到 `tasks`（既有表无稳定级联语义），用 `collab_plan_links` 弱关联 + 事务保证；
读取时若任务已删除，进度计数跳过并标注 `orphan`。

## 4. 关键约束与语义

1. `collab_issues.dedupe_key` 只用于**提示**，不建唯一索引；重复允许存在（人工决定合并）。
2. `collab_evidence` 唯一键防止同证据重复入库；不同 subject 引用同一文件时按 subject 各存一行（路径可同）。
3. `collab_plans.status` 只由服务层状态机修改；`approved` 必须有 `approved_by/approved_at`。
4. `collab_visual_docs.version` 从 1 开始，每次内容写入 +1；`revision` 为乐观锁。
5. `collab_audit` 不接受 Agent 写/删；只在服务层事务内插入。
6. 所有时间 `RFC3339` 本地带偏移字符串（与既有 `now_iso()` 语义一致）。
7. 项目删除（`planning_projects` DELETE）级联删除本模块表；归档不删除。

## 5. IPC 命令（`src-tauri/src/collab/commands.rs`）

实际注册 **52** 个，全部为 `collab_*`，由 `src-tauri/src/lib.rs` 的 `invoke_handler` 注册；返回统一

| 方案 / 审批 / 任务 | `collab_plan_create_from_issue`、`collab_plan_update`、`collab_plan_get`、`collab_plan_list`、`collab_plan_submit`、`collab_plan_review`、`collab_plan_link_visual`、`collab_plan_create_tasks`、`collab_plan_tasks`、`collab_plan_progress` |
| 可视化文档 | `collab_visual_create`、`collab_visual_update`、`collab_visual_get`、`collab_visual_list`、`collab_visual_delete`、`collab_visual_versions`、`collab_visual_version`、`collab_visual_restore`、`collab_visual_compare`、`collab_visual_export`、`collab_renderers` |
| 原型 | `collab_prototype_state`、`collab_prototype_dispatch`、`collab_prototype_patch`、`collab_prototype_validate` |
| 资产（v85） | `collab_visual_asset_import`、`collab_visual_asset_list`、`collab_visual_asset_archive`、`collab_asset_read` |
| AI | `collab_ai_generate`、`collab_ai_modify`（修改提案，不落库）、`collab_ai_image`、`collab_ai_jobs`、`collab_ai_cancel`、`collab_ai_notice` |
| 审计 | `collab_audit_list` |

`collab_ai_modify` 返回 `{ job, baseRevision, kind, proposedContent, summary }`；**不写文档**。
前端展示差异后，用户确认时再调用 `collab_visual_update`（带 `expectedRevision`）落库。

> `collab_plan_create_from_issue` 从 Issue 创建方案时，按规则写入 2 条默认任务草案
> （`实现：<标题>`、`验证：<标题>`，第一条继承 Issue 优先级），保证方案批准后可直接拆解；
> 草案可被 `collab_plan_update` 覆盖，不是 AI 生成内容。

关键参数约定：
- 所有写命令要求 `expectedRevision`（创建除外）；不一致返回 `CONFLICT`。
- `collab_plan_review` 的 `decision` 只接受 `approve` / `reject`，且 `Actor` 必须为 UI；Agent 调用返回 `PERMISSION_DENIED`。
- `collab_evidence_attach` 的 `path` 必须是应用数据目录内文件；`collab_evidence_attach_text` 用于日志/文本证据。
- 分页统一 `page` / `pageSize`，服务端把 `pageSize` 限制在 1..=50。

## 9. 错误码

| code | category | 触发 |
|---|---|---|
| `VALIDATION` | validation | 字段长度/枚举/JSON/坐标/上限 |
| `NOT_FOUND` | not_found | 项目/实体/版本/任务不存在 |
| `PERMISSION_DENIED` | permission | 能力不足、跨项目、Agent 审批 |
| `CONFLICT` | conflict | revision 不匹配、非法状态转换 |
| `DUPLICATE_PLAN` | conflict | 同一 Issue 重复创建方案 |
| `PROVIDER_UNAVAILABLE` | unsupported | 未配置模型/图像 provider |
| `UNSUPPORTED` | unsupported | 不支持的 renderer/导出格式 |
| `DATABASE_ERROR` | database | SQLite 失败（detail 只含错误码） |
| `OVERLOADED` | service | 队列/并发上限（后续） |
