# 句式命令不接入模型

Task Dock 需要「自然语言管理」入口。决定不引入任何模型（不内置、不代下载、不接本地运行时、不接云端 API），改为在全局搜索中提供一套封闭帧表的确定性句式命令：任务域只读查询与单步修改，两段式确认，识别失败零损失回退为普通搜索。

原因：常驻低占用定位与「数据默认不出本机」承诺分别排除了内置模型和云端服务；在这套受限范围里，模型实际只承担「把一句话翻译成参数」，而时间解析已有确定性实现（`src-tauri/src/nlp.rs`），任务候选匹配必须查询本地数据库，模型换来的措辞覆盖不足以抵消运行时依赖、推理期资源峰值与提示词外泄面。确定性实现可完整单测、不会编造数字，与既有「不伪造分母」纪律及剪贴板标题的确定性规则一致。

## Considered Options

- **内置或可选下载本地模型**：数 GB 下载加推理期 CPU/内存峰值，与胶囊常驻的低占用定位冲突。
- **用户自备本地运行时（Ollama / LM Studio）**：仍是本地模型依赖，只是把下载成本转嫁给用户。
- **云端 API**：能力最好，但任务与 Agent 元数据会离开本机，破坏本地优先承诺，需要单独的豁免决策；本需求不值得。
- **自由语序 + 规则**：没有模型兜底时规则维护没有上限，故收敛为封闭帧表。

## Consequences

- 帧表外的说法（如「把交周报的优先级调高」「取消完成 X」）回退为普通搜索而不报错；帮助页必须维护帧表。
- 整句精确命中任务标题时同样回退搜索：搜索无损、命令有副作用，冲突时选择无损路径。
- **独立于命令面板的第二通道**：`commandRegistry.ts` 的契约禁止数据写入命令（`EXECUTABLE_ACTION_KINDS` 白名单 + 契约测试）；句式写意图不登记为 `CommandDef`，由后端解析、前端二次确认后调用既有任务命令。`commandRegistry` 的红线保持不变。
- 写意图只给候选（排除已完成任务，最多 5 条）；第一次 Enter 展示差异预览，第二次才落库。执行前复核状态：完成前若任务已被其他窗口完成则不再翻转；改期/优先级先读全量任务再只写目标字段，避免清空描述、提醒与重复规则。
- v1 明确不做：多步链式、批量、删除、暂存架、剪贴板、撤销。改期/优先级可再发一条命令改回。
- 可发现性靠空输入的模板示例、帧表近似命中时的提示与帮助文档。
- 若未来改主意接入模型，帧表仍可作为模型输出的校验层，不会作废。
