# ADR-0005 架构守卫三阶段渐进启用，禁大量忽略规则

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-19 |

## 1. 背景
Phase 2 需建立自动化架构检查，但历史代码已有 V1–V7 违规（见 MODULE_DEPENDENCIES.md）。

## 2. 当前问题
若一次性全局强制，会因历史违规阻断所有构建；若大量添加忽略规则，守卫形同虚设。

## 3. 决策
三阶段：① 报告模式建基线不阻断；② 新代码禁增违规 + 已治理模块强制；③ 逐模块清理后全局强制。每个例外必须有理由 + 退出条件，记入 `architecture-rules.json`。

## 4. 备选方案
A. 一次性全局强制；B. 不检查；C. 三阶段（选中）。

## 5. 选择原因
C 兼顾"立即有量具"与"不被历史债淹没"，且防止忽略规则泛滥。

## 6. 优点
可落地；可见进步；例外可控。

## 7. 缺点
需要维护阶段状态与例外台账。

## 8. 影响模块
`scripts/architecture/`、所有被检查模块。

## 9. 迁移计划
Phase 2 建报告脚本与基线；Phase 3+ 逐模块升级强制。

## 10. 测试要求
守卫脚本自身单测；基线 JSON 可复现；违规计数不增长（阶段二起）。

## 11. 回滚条件
守卫误报影响正常开发时，调整规则路径范围而非全局关闭。
