# ADR-0007：删除构建调度器

## 状态

Accepted

## 日期

2026-11-19

## 背景

用户明确要求删除构建调度器。此前桌面、移动端、集成验证和性能门禁通过统一队列执行，
维护全局并发、分类槽位、优先级、心跳与调度日志。

## 候选方案与最终决策

选择删除调度器实现和专属测试，所有命令直接执行；不采用保留空壳直通调度器的方案，避免继续维护无用入口。
保留磁盘守卫、Dev 实例复用、集成快照及其独立工作区、构建锁、构建日志和产物校验。
集成所用原子 JSON 读写从调度器迁至 `scripts/integration-state.mjs`，保持既有行为。

## 原因与代价

执行用户指定的基础设施简化；不再提供自动排队、全局并发限制或调度 provenance。
并行任务需自行协调资源、端口与构建输出目录。历史状态和证据不自动清理，运行中的他人进程不终止。

## 影响与兼容性

- 根目录及移动端 npm 命令保留原名称，直接执行工具；`:raw` 别名继续可用。
- 删除 `sched*` npm 命令及 `scripts/build-sched*.mjs`、`scripts/sched/`。
- 集成构建与检查仍记录日志、退出码和提交；兼容字段 `schedulerTaskId` 保留，新记录为 null。
- `--priority`、`--class` 不再具有调度含义；集成命令帮助中移除这些选项。
- 产品功能、IPC、数据库与备份格式无变化。

## 后续

如需恢复自动调度，应重新评估实际并发需求并新增替代 ADR；不恢复旧操作规则作为默认要求。
