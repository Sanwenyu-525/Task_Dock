# ADR-0004 数据库迁移红线：版本/顺序/表结构不变，仅文件化 SQL

| 项目 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-19 |

## 1. 背景
`db/mod.rs` 7010 行，`MIGRATIONS` 混合内联 SQL 与外部常量，版本 v78（README 误写 v33）。审计提出文件化迁移以降维护成本。

## 2. 当前问题
单文件过大；SQL 来源分散；维护与回滚风险。

## 3. 决策
迁移文件化（每版本一个 .sql，`include_str!` 引用），但**红线**：版本号 1→78、顺序、`user_version` 语义、表结构完全不变；SQL 文本逐字节等价。备份表清单（143 张）可数据化但不删表。

## 4. 备选方案
A. 保持内联（现状）；B. 文件化且改结构；C. 文件化仅改来源（选中）。

## 5. 选择原因
C 降低维护成本同时消除用户库升级失败/数据丢失风险。

## 6. 优点
可维护；可审计；数据零风险。

## 7. 缺点
需谨慎保证逐字节等价；迁移回放测试成本高。

## 8. 影响模块
`db/mod.rs`、各模块 `MIGRATION_N` 常量、备份。

## 9. 迁移计划
Phase 3 基础设施批次；隔离测试库全版本回放验证。

## 10. 测试要求
v1→v78 迁移回放；`user_version` 断言；备份/恢复一致性；不碰生产库。

## 11. 回滚条件
任何 schema 或 user_version 偏差立即停止；保留原 MIGRATIONS 定义可回退。
