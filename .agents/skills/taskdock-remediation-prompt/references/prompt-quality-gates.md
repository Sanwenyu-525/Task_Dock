# 修复提示词质量闸门

完成前确认：
1. 可以用自然语言重现用户问题；期望行为可测试，不是“优化一下”。
2. 事实与猜测分离；文件路径只在确认存在或明确让 Agent 自行搜索时使用；历史只用当前可访问内容，不虚构。
3. 仅要求最小范围根因修复；不要预先强制改某个推测函数；任务类型准确（缺陷/新功能/性能/遗留），新功能不虚构缺陷。
4. 关键兼容性按需涉及 SQLite/备份、Tauri IPC、Window/DPI、剪贴板隐私、Agent 关键事件与有界队列、导航隐藏与共享服务。
5. 明确所有已有其他 Agent 修改默认为他人工作，禁止 `git reset --hard`、`git clean`、覆盖未知文件或强制清理共享构建目录（包括杀未知进程、删共享缓存）。
6. 测试预算与风险匹配；纯 UI 不做无关全量压测，原生窗口不以 mock 代验；高成本压测写清必要性、隔离条件与授权。
7. 证据要明确执行层 A–F，特别区分 B/C/E/F；抢鼠标/前台需要授权；失败判据与反例明确。
8. 交付时包括修改文件、具体测试命令/退出码、没跑的测试、遗留风险、证据实际路径。
9. 非长期信息只保存在 `tmp/acceptance/<task-name>/`；架构变化只维护既有正式文档，不泛滥新报告。
10. 并行开发期间不掩盖本轮改动触发的失败，不将其他会话失败当本轮修复目标。
11. 若用多 Agent（最多三）并行：提示词写清每方文件范围、共享文件合并责任、禁区与主 Agent 最终验证；耦合高不硬拆。
12. UI/UX、数据安全、性能/资源释放、文档同步按本次风险填写；简单任务可缩短，但不遗漏相关风险项。
