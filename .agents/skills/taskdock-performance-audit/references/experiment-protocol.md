# 性能实验协议

## 安全前置
- 不杀其他会话进程，不在生产数据目录写测试数据；使用任务专属 `TASK_DOCK_DATA_DIR`。
- 检查构建空间与 `scripts/build-guard.mjs` 操作约束；只有用户授权才运行破坏性或高压力步骤。
- 先读现有 `scripts/perf/` 脚本的帮助、参数和副作用；不臆造 CLI flags。

## 分阶段
1. **基线**：记录 git SHA/dirty、二进制 sha256（若可取得）、Windows/构建模式、数据量与采样条件。
2. **空闲**：先获取稳定空闲样本，记录 CPU、Working Set/RSS、Private Bytes、句柄数、线程数。
3. **受控负载**：固定消息速率/输入数量/操作次数，避免机器与其他会话竞争；记录队列深度/背压/丢弃计数。
4. **恢复阶段**：停止负载，观察是否下降并进入平台期；区分缓存保留与持续增长。
5. **退出阶段**：确认被本任务启动的子进程/线程、端口、锁及临时资源释放。
6. **比较**：相同负载、时长、构建和数据条件下才计算差异；输出样本数、p50/p95、最大值、趋势和测量局限。

## 解释
- 首末差值是观察，不是泄漏率；p95 在样本少时仅供参考。
- 没有对照数据不能声称提高百分比；没有长跑不能宣称长时稳定。
- 共享构建、前台锁拒绝、磁盘不足等单列 `ENVIRONMENT BLOCKED`，不要改动范围外模块去换取一个绿灯。
